# 第一部分：你为什么需要转型

## 1.1 MCU开发的"天花板"

作为MCU工程师，你可能已经掌握了:

- GPIO、I2C、SPI、UART外设驱动
- 寄存器级编程
- 中断服务函数
- RTOS任务调度
- 简单的状态机设计

但MCU开发有几个自然的"天花板":

| MCU 局限 | Linux BSP 对应能力 |
|---------|-------------------|
| 64KB-1MB RAM | 4GB+ 虚拟内存, MMU保护 |
| 单文件数百行代码 | 多文件模块化, 驱动框架复用 |
| 简单RTOS | 完整进程调度、内存管理、网络栈 |
| 手动烧录 | OTA远程升级、包管理 |
| 无安全模型 | 用户态/内核态隔离、SELinux |
| 有限的外设支持 | 数十万行的成熟驱动生态 |

# 第二部分：思维转型 — 从"面向寄存器"到"面向框架"

## 2.1 核心思维差异

### MCU思维模式

```c
// MCU: 我知道每个寄存器的地址和位定义
// 我控制一切, 从时钟树到引脚状态
#define GPIOA_BASE    0x50000000
#define GPIOA_ODR     (*(volatile uint32_t *)(GPIOA_BASE + 0x14))

void main() {
    // 1. 使能GPIOA时钟
    RCC->AHBENR |= RCC_AHBENR_GPIOAEN;
    // 2. 配置GPIOA_PIN5为推挽输出
    GPIOA->MODER = (GPIOA->MODER & ~(3 << 10)) | (1 << 10);
    // 3. 输出高电平
    GPIOA->ODR |= (1 << 5);
    while(1) { ... }
}
```

### Linux BSP思维模式

```c
// Linux: 我使用内核框架, 框架处理底层细节
// 我描述硬件连接 (设备树), 实现驱动逻辑

// ===== 设备树 (硬件描述) =====
// leds {
//     compatible = "gpio-leds";
//     my_led: led-0 {
//         gpios = <&gpioa 5 GPIO_ACTIVE_HIGH>;
//         default-state = "on";
//     };
// };

// ===== 驱动代码 =====
#include <linux/module.h>
#include <linux/platform_device.h>
#include <linux/leds.h>

static int my_driver_probe(struct platform_device *pdev)
{
    struct led_classdev *led;
    // 框架自动解析GPIO, 我不需要知道基地址!
    led = devm_led_classdev_register(&pdev->dev, &my_led_data);
    return 0;
}

// 我不需要:
// 1. 手动使能时钟 (框架处理)
// 2. 知道寄存器地址 (框架处理)
// 3. 配置引脚复用 (pinctrl子系统处理)
```

### 关键转型

| 概念 | MCU | Linux BSP |
|------|-----|-----------|
| 硬件描述 | 代码中硬编码 | 设备树 (.dts) 描述 |
| 外设访问 | 寄存器直接读写 | regmap / GPIO子系统 / IIO / ... |
| 引脚配置 | 手动写MUX寄存器 | pinctrl子系统, DTS描述 |
| 时钟管理 | 手动写时钟寄存器 | CCF (Common Clock Framework) |
| 中断处理 | ISR直接操作硬件 | threaded_irq: top-half / bottom-half |
| 代码复用 | 复制粘贴 | 驱动框架, 只需实现差异化逻辑 |
| 设备匹配 | 硬编码地址 | compatible 字符串匹配 |

## 2.2 最重要的5个思维转变

### 转变1: 从"写死"到"描述"

```
MCU:     "GPIOB PIN3 连接LED, 我在代码中写: GPIOB->ODR |= BIT(3)"
Linux:   "设备树描述: led { gpios = <&gpiob 3>; }, 代码使用LED子系统"
```

### 转变2: 从"修改寄存器"到"调用API"

```
MCU:     "I2C发送: 写TXDR寄存器, 等待TXE标志..."
Linux:   "i2c_transfer(client->adapter, &msg, 1); — 框架处理所有时序"
```

### 转变3: 从"轮询/阻塞"到"异步/事件驱动"

```
MCU:     "while(!(SPI->SR & SPI_SR_RXNE));  // 死等!"
Linux:   "interrupt驱动 + completion/wait_queue — 不阻塞CPU"
```

### 转变4: 从"全局变量"到"驱动私有数据"

```
MCU:     "int g_sensor_value; // 到处可用, 谁都可能改"
Linux:   "struct my_drv *drv_data = dev_get_drvdata(dev); // 封装在驱动内部"
```

### 转变5: 从"我知道了硬件"到"我只是设备树+驱动"

```
MCU:     "我写了整个系统的所有代码"
Linux:   "我只需写: 设备树节点 + 驱动probe() + 功能回调"
```

# 第三部分：学习路径 — 从MCU到BSP的阶梯

## 3.1 每周学习计划 (12周)

### 第1周: Linux基础命令行 + Git

```bash

# Day 4: Shell脚本入门
变量、条件判断、循环、函数、参数传递

# Day 5-6: Git基础
git clone, git add, git commit, git log, git diff
git branch, git checkout, git merge, git rebase

# Day 7: Git高级
git format-patch, git am, git cherry-pick, git stash
# (这是BSP开发最常用的patch工作流!)
```

### 第2周: C语言回顾 + 内核编程基础

```c
// 需要复习的C语言重点:
1. 指针和指针运算 (函数指针尤其重要!)
2. 结构体和联合体
3. 位操作和位域
4. 内存对齐 (__attribute__((aligned)))
5. 链表操作 (list_head, 双向循环链表)
6. container_of 宏 — 内核中无处不在!

// 内核编程新概念:
- 没有libc (不能用printf, 用printk)
- 没有浮点运算 (内核态禁用FPU)
- 栈空间很小 (通常8KB, 不能用大数组)
- 并发无处不在 (中断 + 多核 + 抢占)
```

### 第3-4周: 设备树 (DTS) — BSP工程师的"语言"

```dts
// 理解设备树的核心概念:
// 1. 节点层次
// 2. compatible 字符串
// 3. reg 属性
// 4. GPIO / interrupt / clock 引用
// 5. pinctrl

// 实战练习:
```

### 第5-6周: 第一个内核模块 — "Hello World"

```c
// my_first_module.c
#include <linux/module.h>
#include <linux/kernel.h>

static int __init my_init(void) {
    printk(KERN_INFO "Hello from BSP world!\n");
    return 0;
}

static void __exit my_exit(void) {
    printk(KERN_INFO "Goodbye!\n");
}

module_init(my_init);
module_exit(my_exit);
MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
```

```makefile
# Makefile
obj-m += my_first_module.o
KDIR := /path/to/kernel/source
all:
    make -C $(KDIR) M=$(PWD) modules
clean:
    make -C $(KDIR) M=$(PWD) clean
```

```bash
# 编译 + 测试
make

insmod /tmp/my_first_module.ko
dmesg | tail   # 应该看到 "Hello from BSP world!"
rmmod my_first_module
```

### 第11周: 平台设备驱动 + 设备树

```c
// 理解 platform_driver + of_match_table 匹配机制
// 这是BSP工程师最核心的技能

static const struct of_device_id my_of_match[] = {
    { .compatible = "mycompany,my-device" },
    { /* sentinel */ }
};
MODULE_DEVICE_TABLE(of, my_of_match);

static struct platform_driver my_driver = {
    .driver = {
        .name = "my_device",
        .of_match_table = my_of_match,
    },
    .probe = my_probe,
    .remove = my_remove,
};
module_platform_driver(my_driver);
```

```bash
# 手动内核构建

make menuconfig                       # 修改配置
make -j$(nproc) Image modules dtbs    # 编译
```

## 4.2 调试三板斧

```bash
# 1. printk / dev_dbg — 最基础也最常用的调试手段
# 驱动中:
dev_info(&client->dev, "sensor chip_id=0x%02x\n", val);
# 查看:
dmesg -wH | grep sensor

# 2. debugfs — 运行时查看/修改驱动状态
# 创建debugfs节点:
debugfs_create_file("status", 0444, parent, drv_data, &status_fops);
# 查看:
cat /sys/kernel/debug/my_driver/status

# 3. devmem — 直接读写寄存器 (仅调试用!)
# 读取:  devmem 0xFD580000 32
# 写入:  devmem 0xFD580000 32 0x12345678
```

## 4.3 DTS调试

```bash
# 查看运行时设备树
dtc -I fs -O dts /proc/device-tree | less

# 查看某个具体节点
ls /proc/device-tree/i2c@fea90000/

# 查看内核加载的DTB信息
cat /sys/firmware/fdt

# 查看设备模型
ls /sys/devices/platform/
ls /sys/bus/i2c/devices/
```

# 第六部分：常见问题与解决方案

## Q1: 我之前在MCU上用Keil/IAR, 现在用什么IDE?

```
推荐: VS Code + 以下插件:
  - C/C++ (Microsoft)
  - Cortex-Debug (JTAG调试)
  - Remote-SSH (远程开发)
  - DeviceTree (设备树语法高亮)
  - ShellCheck (Shell脚本检查)

不推荐: 重量级IDE (Eclipse, CLion)
因为: BSP开发中大量工作是Shell脚本 + 命令行 + Git
轻量级编辑器 + 命令行效率最高
```

## Q2: 没有硬件怎么学习?

```
使用QEMU模拟ARM64:
  qemu-system-aarch64 -M virt -cpu cortex-a57 \
    -kernel Image -append "console=ttyAMA0" -nographic

或购买便宜的开发板:
  树莓派4B (~400元) — 社区最活跃, 文档最多
  ROCK-5C (~700元) — 你手头就有, 性能更强
  香橙派Zero3 (~100元) — 最便宜的全志H618方案
```

## Q3: 内核panic了怎么办?

```bash
# 1. 拍照/记录panic信息
# 2. 重点分析:
#    - PC (Program Counter): 崩溃位置
#    - LR (Link Register): 调用者
#    - Call trace: 函数调用栈
# 3. 使用 aarch64-linux-gnu-addr2line 定位代码行:
aarch64-linux-gnu-addr2line -e vmlinux -f -C <PC值>
```
