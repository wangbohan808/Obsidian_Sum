# 第 2 套方案：STM32F407 主控 + ESP32 WiFi 从机 — FreeRTOS 双系统方案 v1

> 本方案与"ESP32-S3 单芯片方案"**并存姊妹版**，互不覆盖。两套共享同一套外壳、亚克力、20×20 主矩阵 + 12 侧发光轮廓光的结构件与 UI 资源。
> 核心差异：**显示与主逻辑全部跑在正统 ARM Cortex-M4F（STM32F407）上**，ESP32 退居"智能 WiFi 网桥"从机。双 MCU + 双 RTOS + 自定义主从通信协议，是比单芯片更"正统"、更有进阶深度的 FreeRTOS 学习载体。
> 语言：中文（全部交付物用中文，代码注释除外）。

---

## 一、为什么选这套（定位）

| 目标 | 如何满足 |
|------|----------|
| 更"正统"的 FreeRTOS 学习 | STM32F407 是近乎所有嵌入式课程/考研/招聘面试默认的经典平台，HAL + 独立 FreeRTOS 源码移植，学习点standard且生态海量 |
| 主从通信是亮点 | 双 MCU 用 USART + 自定义二进制/JSON 协议交互，涵盖帧同步/校验/分块大文件/双系统状态同步，是单芯片体会不到的进阶内容 |
| 保留联网与网页配置 | ESP32 从机跑 esp_http_server，续接原方案的网页/配网/NTP 全部能力 |
| 降低成本 | STM32F407 核心板 + ESP32 模组模块化，无需画复杂的双片 PCB，可先用两块现成开发板连起来跑通再打板 |

## 二、系统架构（主从双核）

```text
┌───────────── STM32F407（主控/大脑）────────────┐      ┌──────── ESP32（从机/网桥）────────┐
│ Cortex-M4F @168MHz，FreeRTOS(HAL)              │      │ Xtensa 240MHz，FreeRTOS(ESP-IDF) │
│  ┌────────┐ ┌────────┐ ┌────────────┐         │      │                                  │
│  │输入任务│ │传感任务│ │显示任务     │         │      │ WiFi(STA/SoftAP)  网页配置        │
│  │ 按键   │ │ SHT40 │ │ 主矩阵+轮廓 │◄───────┼──────┼──UART2×27──► 协议握手            │
│  └────────┘ └────────┘ └────────────┘         │      │  NTP校时   RTC伺服            │
│  ┌────────┐ ┌────────┐                        │      │  图案下载(网页→透传)           │
│  │灯效任务│ │倒计时楼 │                        │      │                                  │
│  │ 动画   │ │ RTC    │◄───────── time/日期 ───┼──────┼──透传/GPSR ──► NTP            │
│  └────────┘ └────────┘                        │      │                                  │
└──────────────┬────────────────────────────────┘      └────────────────────────────────┘
               │ 5V/3.3V 共用，共地
               ▼
   ┌────────────────────────────────────────────┐
   │ 20×20 主矩阵 + 12 侧发光轮廓光（与 A 版共用）│
   └────────────────────────────────────────────┘
```

**分工原则（单职责，降低耦合）**：
- **STM32F407 负责**：一切实时与本地逻辑——WS2812 矩阵/轮廓光驱动（DMA/SPI 或定时器）、SHT40、按键、桌宠/灯效渲染、倒计时计算、本地 RTC、本地 RTOS 调度。
- **ESP32 只负责**：网络连接与"翻译官"——接入 WiFi、跑 HTTP 网页、配网/NTP、把用户通过网页下的配置（目标日期、图案原始数据、灯效参数、WiFi 凭据）编码成协议帧经 UART 推给 STM32；把 STM32 上报的状态（温湿度、倒计时、剩余天数）转发给网页。
- 二者之间**有且只有一条 UART 高速链路**，协议明确，状态机通信，便于调试也便于后续换平台。

## 三、主从通信协议（项目最大亮点）

### 3.1 链路层
- **物理**：STM32F407 `USART2`（PA2/PA3）↔ ESP32 `UART0`（或 UART2），115200 bps（图案大文件时可协商提至 921600）。
- 两者共地，闲置脚可不接。

### 3.2 帧格式（自定义，二进制 + CRC）
```text
| 帧头 0xAA 0x55 | 长度(2B LE) | 命令(1B) | 序列号(1B) | 负载(Payload) | CRC16(2B) | 帧尾 0x0D 0x0A |
```
- 命令表（节选）：
  - `0x01 HELLO/握手`、`0x02 请求状态`、`0x03 上报状态(温湿度/倒计时)`、
  - `0x10 下发完整图案(20×20+轮廓)`、`0x11 下发桌宠动画帧组`、`0x12 下发灯效参数`、
  - `0x20 下发系统时间/目标日期`、`0x21 下发激励语`、
  - `0x30 WiFi状态通知`、`0x31 配网结果通知`、`0x40 心跳(每秒)`、`0xFF 错误`。
- 大图案分块：20×20×3=1200B 超过一帧上限，按 `0x11` 分片携带 `首片/续片/末片` 标志与片序号，接收端组包校验。

### 3.3 通信状态机（教学重点）
```text
IDLE → HELLO(握手) → AUTH_READY → SYNC(时间校准) → DATA_EXCHANGE → 心跳维持
                         └────────── 异常→重同步/重试
```
- 演示 **UART 中断 + FreeRTOS 队列** 接收、**状态机**解析、**超时重传**、**CRC 校验失败丢弃**、**背压**（对端忙时流控）。
- 双端各自打印极易用逻辑分析仪定位。

## 四、FreeRTOS 学习点（比单芯片更丰富）

除继承 A 版全部概念外，本套新增/强化：

| 新增学习点 | 落地 |
|-----------|------|
| **双系统时间同步** | ESP32 从 NTP 取 UTC 经协议推给 STM32，STM32 写本地 RTC（DS3231），离线降级 |
| **Vt — 帧分块传输与重组** | 大图案切片 → 协议组包 → 校验 → 完整 framebuffer 落地 |
| **队列生产者/消费者多对一** | 多个源（HTTP/按键/传感）→ 同一队列 → 显示任务消费 |
| **互斥与优先级继承** | STM32 侧保护 framebuffer 与协议共享缓冲，演示 mutex 优先级继承避免反转 |
| **事件组联合触发** | 通信握手成功 + 传感到位 + 动画就绪 → 才切综合页 |
| **看门狗/栈监控** | 双端各自 Task Watchdog，协议卡死不牵连主系统 |
| **低功耗/唤醒（进阶）** | 夜间降频 + 按键外部中断唤醒，ESP32 负责网络待机 |

> 教学模式建议：先在**纯 STM32 板**用 `rtos_demo/` 跑通每个概念，再把通信接上做综合。

## 五、硬件方案

### 5.1 器件选型（BOM）

| 功能 | 器件 | 说明 |
|------|------|------|
| 主控 | **STM32F407VET6** 或 **F407ZGT6** 核心板（"黑丸/正点原子/野火"） | Velocity; 64/128KB RAM; 168MHz; 3 路 USART/5 路; 足够放 FB+动画 |
| 芯片级（自绘PCB） | STM32F407VGT6 TQFP100 + 25MHz 晶振 + 3.3V LDO | 出货稳定、兼容库海量 |
| WiFi 从机 | **ESP32（标准版）模块/模组（WROOM-32）** 刷自写固件 | 跑 esp_http_server 网桥，学习价值高 |
| WiFi 备选 | ESP8266 + AT 固件 | 最省成本，但只能收发文本，控制粗粒度，不推荐教学 |
| 显示 | WS2812B 20×20 主矩阵 + 12 颗侧发光轮廓光（与 A 版共用） | 同结构件 |
| 温湿度 | SHT40 (I2C) | |
| RTC | DS3231 (I2C) + CR1220 | 掉电时间不丢 |
| 按键 | 轻触 ×2 + 硅胶帽 | 顶置 |
| USB-C | 5V 供电（STM32 侧 LDO→3.3V） | |
| 电平 | 3.3V/I 足够；WS2812 走 5V 面（与 A 版相同的电平处理） | |

> 采购建议：**两块现成核心板先用杜邦线/面包板联调**（STM32F407 核心板 ~20-50 元 + ESP32 最小板 ~15-30 元），软件全部跑通后再自己画含双芯片的 PCB。

### 5.2 引脚分配（STM32F407 侧）

| 功能 | 引脚 | 说明 |
|------|------|------|
| 主矩阵 WS2812 | PA10 (SPI1_SCK) 或 TIM/DMA | DMA+SPI 或定时器+PWM 驱动，见驱动方案 |
| 轮廓光 | PA11 或 PA5 | 独立 DMA 通道 |
| UART 去 ESP32 | USART2: PA2(TX)/PA3(RX) | 高速协议链路 |
| I2C1 | PB6(SCL)/PB7(SDA) | SHT40 + DS3231 = 7-bit 0x44,0x68 |
| KEY1/KEY2 | PA0/PE0 | EXTI 外部中断 |
| 光敏(可选) | PA1 (ADC1) | |
| 蜂鸣器(可选) | PD12 (TIM4) | |

### 5.3 WS2812 驱动（F407 特色）
- **RMT 于 F407 没有**，但可用：**DMA + SPI（8bit 拆 3bit 再 GPA 扩）+ 定时器 PWM**。
- 推荐入门：**定时器 + DMA 输出 800kHz**（如参考 Tim_PWM 波形）或用 **MSB-First SPI 转移**；动画仅需每帧重写，60fps 预算内轻松。
- framebuffer 20×20×3 = 1200B，双缓冲 swap 防撕裂。

### 5.4 资源估算：F407 跑 FreeRTOS 完全够用（逐项量化）

> 结论先说：STM32F407 是 FreeRTOS 最经典的移植平台之一，本项目的 CPU/RAM/Flash 三项需求远低于其供量，**不存在资源瓶颈**。下表据此做实打实的估算，供选型心里有底。

**5.4.1 总览（供给 vs 需求）**

| 资源 | F407 供给（VGT6 / VET6） | 本项目需求 | 占用比 | 余量 |
|------|--------------------------|-----------|--------|------|
| CPU | Cortex-M4F 168MHz（带 FPU） | 峰值负载在 WS2812 刷新 + 动画渲染 | 低（大部分时间任务阻塞） | 极充裕 |
| RAM | 128KB / 64KB | 见 5.4.2，典型 < 20KB | ≈ 可选 6%~15% | 充裕 |
| Flash | 1MB / 512KB | 内核 + 固件 + 常驻小字库，约 200~400KB | 默认 VGT6 用 < 40% | 极宽裕 |

**5.4.2 FreeRTOS 内核 + 本项目 RAM 占用明细（估算，以 VGT6 128KB 为基准）**

| 消耗项 | 估算 | 说明 |
|--------|------|------|
| FreeRTOS 内核数据（TCB/队列/信号量/堆内存池） | ≈ 5~8KB | 内核极小，堆内存在 `FreeRTOSConfig.h` 配 heap 大小 |
| 10 个任务栈（平均 0.75KB，大任务 2KB） | ≈ 8~12KB | 各任务细化见下 |
| framebuffer 双缓冲 20×20×3 | ≈ 2.4KB | 主矩阵仅 1.2KB ×2 防撕裂 |
| 轮廓光缓冲 12×3 | ≈ 36B | 可忽略 |
| 协议接收/发送缓冲（分片组包窗口） | ≈ 2~4KB | 双缓冲 + CRC |
| 全局状态/配置副本/NVS 镜像 | ≈ 1KB | |
| **合计占用** | **≈ 18~27KB** | 128KB 下占用 ≤ 21%，64KB 下 ≤ 42%，均达标 |

**5.4.3 各任务栈分配建议（可在调试页 `vTaskList` 复核余量）**

| 任务 | 建议栈 | 说明 |
|------|--------|------|
| `display_task`（WS2812 刷新 + 队列处理） | 0.5KB | 栈较浅，重活交给 DMA，不占 CPU 栈 |
| `pet_task` / `effects_task`（动画/灯效计算） | 1~2KB | 涉及较多局部数组，给足余量 |
| `comm_task`（协议解析/组包 + CRC + 分片重组） | 2KB | 协议处理是本项目较复杂的任务，栈放充裕 |
| `sensor_task` / `input_task` / `clock_task` | 0.5~1KB | I2C/中断为主，阻塞多 |
| `server_state_task`（定时组状态上报） | 0.5KB | 轻量 |

> 经验值：所有任务栈在运行时按 `uxTaskGetStackHighWaterMark()` 留 ≥30% 余量，`rtos_demo/` 里有配套示例。

**5.4.4 真正吃性能的是 WS2812 驱动（与 FreeRTOS 无关），对策**

| 驱动方式 | CPU 占用 | 说明 |
|----------|----------|------|
| 定时器 + DMA（推荐入门） | 极低（DMA 搬运，刷新时 CPU 基本空闲） | 用定时器出 800kHz 时序，DMA 把色彩缓冲搬运到 GPIO，刷新 60fps 轻松 |
| SPI（MSB-first，8bit 拆 3bit） | 低 | 更快，但需更多 GPIO/外设，代码稍复杂 |
| 纯 GPIO 翻转（不推荐） | 高，且占用高优先级中断 | 400 灯不可取，仅用于 1~2 颗测试 |

结论：**168MHz + DMA 驱动下，刷新 400 灯矩阵对 CPU 是几乎零负担**，主 CPU 时间主要花在动画算法上，仍远有余量。

## 六、固件工程骨架（双工程）

```text
master_fw/                      # STM32F407 主控工程 (STM32CubeIDE 或 PlatformIO + HAL)
├── Core/ (启动/时钟)
├── Middlewares/FreeRTOS/       # 独立移植的 FreeRTOS 源码
├── App/
│   ├── tasks.c                 # 任务创建矩阵
│   ├── events.c                # 事件组/队列定义
│   ├── ui/framebuffer.c
│   ├── ui/font5x7.c, font_cn.c, text_render.c
│   ├── ui/pet_animations.c, effects.c
│   ├── drivers/ws2812_dma.c, sht40.c, ds3231.c, key_exti.c
│   ├── comm/protocol.c         # <== 主从协议核心（帧解析/组帧/CRC/分片）
│   └── comm/link_uart2.c       # USART2 中断+队列
└── interrupt_handlers.c

slave_fw/                       # ESP32 从机网桥工程 (PlatformIO/ESP-IDF)
└── main/
    ├── wifi_manager.c          # STA/SoftAP
    ├── http_server.c           # 网页配置 REST
    ├── ntp_client.c
    ├── webassets/ (index.html/app.js/style.css)
    ├── comm/protocol.c         # <== 与 master_fw 一模一样的协议模块
    └── comm/link_uart.c

shared/                         # 两端共用的头文件（协议/配置字）
├── proto.h                     # 命令/帧格式/分片标志
└── defs.h                      # 显示参数/灯效枚举（两端 include 相同头，保证内存布局一致）
```

> **关键实践**：`shared/proto.h` 由两工程 `#include` 同一份，双端帧结构/枚举永远一致，从源头避免字段错位。

## 七、网页配置端（从机 ESP32 提供，能力继承 A 版）

- ESP32 跑 `esp_http_server` + LittleFS，访问 `http://pixelpet.local`。
- 配置流：**网页表单 → ESP32 解析 → 编码协议帧 → UART → STM32 执行/存储**。
- 能力：配网向导、温湿度仪表、高考倒计时目标设置、桌宠角色/自定义图案上传（ESP32 降采样到 20×20 或 12×16 后分片下发）、灯效/轮廓光/亮度调参、倒计时激励语编辑。
- STM32 定时向网页上报状态（`0x03` 帧），网页实时刷新三秒一次。

## 十一、关键决策与待确认

**已确定**：
- 主控 STM32F407VET6(ZGT6) Cortex-M4F，从机 ESP32(WROOM)，双 FreeRTOS；
- 主从 UART 自定义二进制协议（帧头+长度+命令+负载+CRC16），`shared/proto.h` 两端同源；
- 学习导向：先纯 STM32 跑通 `rtos_demo/`，再接通信；
- 结构/UI/网页能力与 A 版共用，仅驱动端与联网归属不同。

**待你拍板（不影响写文档）**：
- 自绘 PCB vs 先用核心板联调（默认：先核心板跑通全部软件，满意后再决定是否画含双芯片的板）；
- WS2812 驱动偏好：定时器+DMA（推荐入门）还是 SPI（更快）；
- ESP32 从机固件：自写网桥（推荐）还是先上 AT 固件快速联调（更省但少学点）。

2. `master_fw/` STM32F407 主控工程骨架（HAL + 独立 FreeRTOS + 全部任务/驱动/UI/协议）。
3. `slave_fw/` ESP32 从机网桥工程骨架（WiFi/HTTP/NTP/协议）。
4. `shared/proto.h` 双端共享协议头。
5. `docs/schematic_stm32.md` + `docs/BOM_stm32_bridge.md`：双芯片连接清单与 BOM。
6. 网页配置端源码（与 A 版复用，但 API 走从机透传）。
7. `rtos_demo/` 回归 STM32 平台的最小示例（含双系统联调示例）。
8. 提供**主从协议调试工具**（PC 端脚本/上位机说明），便于无硬件时先验证协议。

> 说明：A 版（ESP32-S3 单芯片）规划文档不受影响，继续保留。两套结构件/亚克力/UI 资源共享。
