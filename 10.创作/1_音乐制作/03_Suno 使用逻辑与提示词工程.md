# Suno 使用逻辑 · 采样模型与提示词工程

> **一句话核心：Suno 不是在"编曲"，是在"采样"——你用文字描述一片声音的概率分布，它每次从里面抽一个样本。所以全部用法归结成一句：把"抽到的"和"想要的"之间的差，翻译回更窄、更少的文字。**

> **定位**：工具层·操作手册。与 [[01_Logic Pro 本质模型与功能全图]] 对称——那篇管"抽到之后怎么拆装"，本篇管"怎么让它抽出接近的东西"。
> **来源**：2026-11-16，按 [[06_剪映精通教程-底层逻辑与操作细节]] 的讲解结构（模型 → 反直觉处 → 管线 → 参数层 → 手册 → 练法）重排，结合 v6 官方页面与 2026-10/11 的公开评测。
> **读法**：§一～§三是**模型**（为什么这样）；§四～§六是**操作**（怎么下手）；§七～§九是**选择**（买什么、什么时候离开浏览器）；§十～§十二是手册与练法。

## 一、底层模型：一次生成 = 一次采样

```
文本层（你 100% 控制）
  Style 框 · Lyrics 框 · 旋钮 · 参考
        │  一次生成
        ▼
采样层（你能引导，不能指定）
  按分布的这一次抽样：旋律走向、音色细节、演唱处理
        │
        ▼
音频层（你拿到的）
  一条混好的立体声波形 —— 不可分解、不可编辑、只可整条替换
```

**关键：Suno 里没有"工程文件"这种东西。** 你保存下来的是"提示词 + 一棵版本树"，音频是这棵树的叶子。这与剪映"引用 + 参数"是同一件事的两面：**剪映存参数不存像素，Suno 存提示不存音符。**

三条推论，直接决定用法：

| # | 推论 | 后果 |
|---|---|---|
| 1 | 一版成本几乎为零 | "批量出候选"在经济学上是对的——所以发现环路成立 |
| 2 | 同一提示词复现不了 | 不是 bug，是采样。别指望"昨天那版再来一次" |
| 3 | **你手里"很好但差一点"的那一版是资产** | 全局重生成会把"意外的对"一起丢掉 |

第三条是从"玩具"到"工具"的分界线。**新手把每次生成当独立抽奖，老手把每次生成当"在同一棵树上修枝"。**

## 二、唯一真正反直觉的地方：「改」和「重来」是两种不同操作

- **新手**：不满意 → 点 Generate → 得到 3 个与上次无关的新版本 → 再不满意 → 反复 20 次，越抽越远。
- **老手**：定位"哪一段不对" → 只重采样那一段 → 其余全部锁定。

| 你的不满 | 该用的工具 | 它动的是 |
|---|---|---|
| 一句歌词不好 | 文本编辑改单句 | 只有那句的发音 |
| 某段的情绪 / 编制不对 | Replace Section | 只重采样那一段 |
| 副歌要更炸 | Replace / Add Section + 圆括号注释 | 那一段的密度 |
| 太短 | Extend | 从某时间点往后接 |
| 风格不对但旋律好 | Cover | 保留旋律，重采样音色与编曲 |
| 整体糊、像老录音 | Remaster | 只重做混音层 |
| 想拆开自己改 | Extract Stems | 输出分轨 |

**判断口诀：先问"变的是哪一层"——文本层还是采样层；再问"范围是整首还是一段"。两个问题定完，工具就唯一了。**

> 这是剪映"两套时间坐标"的等价物：**同一首歌，你永远在两个尺度上工作——整首（macro）和一段（micro）。分不清就会用错力。** 而 Suno 的"段"比剪映的"片段"更模糊：你只能靠方括号标签去**声明**边界，不能拖一条线去**画**边界。

## 三、生成四阶段：每一段塌掉，听感完全不同

```
① 解析：把你的文字变成一组要求
② 结构规划：分几段、每段多长、副歌什么时候进
③ 演奏与演唱生成：音色、和声、演奏细节
④ 混音与压缩：多条音源压成一条立体声
```

| 现象 | 塌在哪一段 | 怎么救（只能在文字层做） |
|---|---|---|
| 完全不像那个流派 | ① 解析 | 换子流派词；删掉互相矛盾的描述 |
| 没有副歌 / 突然结束 / 段落长短失控 | ② 结构 | 加方括号标签；用歌词行数控制每段长度 |
| 糊、闷、人声被埋 | ③④ | **减描述条数**；降 Weirdness；点名"dry / close-miked / minimal reverb" |
| 动态全平、从头到尾都在响 | ④ 混音 | 在段落后加圆括号要求"这段只留钢琴和人声" |
| 换一首还是同一个毛病 | 不是采样问题 | 你的提示词里有一条系统性错误 |

**最值钱的推论：v6 的默认混音偏平、人声偏后，是公开的普遍抱怨（MusicRadar、Reddit 上"muffled / generic"的评价很集中）。所以"听起来不够贵"大概率不是你提示词写错了，是模型默认值的问题。** 你只有两条路：在文字里要"稀疏、贴脸、干声"，或者拿走 stems 进 DAW 自己做。

> **反直觉的一条：描述越多 ≠ 越精确。** 超过 5–8 个概念，模型开始"平均化"，结果是"什么都有点、什么都不突出"。**砍词往往比加词有效。**

## 四、四层输入：任何想法先问它属于哪一层

| 层 | 入口 | 管什么 | 典型错误 |
|---|---|---|---|
| **声音层** | Style 框 | 流派、BPM、编制、人声、制作质感 | 写成一段散文；堆二十个形容词 |
| **结构层** | Lyrics 框里的 `[方括号]` | 段落顺序、每段密度、什么时候进 | 只放歌词不放标签 → 得到标准三分钟模板 |
| **随机层** | Weirdness / Style Influence | 分布的宽窄 | 以为在调"好坏" |
| **参考层** | Inspire / 上传音频 / 上传 MIDI / Voices | 用已有素材当锚 | 以为 MIDI 能决定音色 |

### 4.1 Style 框：五个必填槽 + 一条纪律

按顺序写，一到两句就够：

```
[子流派], [BPM], [人声：谁 + 怎么唱], [3 个定义性乐器], [制作质感/空间]
```

实例（对应 [[方向词库]] 第一行）：
`华语流行摇滚, 76 BPM, 男声主歌气声偏多、副歌加三度和声, 钢琴 + 弦乐 + 实鼓, 副歌才进失真吉他, 大空间但人声贴脸, 无电子鼓`

| 纪律 | 原因 |
|---|---|
| **给子流派，不给大类** | "流行"等于没写；"华语流行摇滚"才有方向 |
| **点名缺什么**（`no guitar` / 无电子鼓） | 不写，它就会加 |
| **描述特征，不点艺术家名** | 多数名字被屏蔽，勉强识别也会被平均化 |
| **一次只改一条** | 同时改三个词，出问题你不知道是谁的锅 |

### 4.2 Lyrics 框：方括号是要求，圆括号是语气

| 写法 | 含义 |
|---|---|
| `[Chorus]` | 这里是一段副歌 |
| `[Chorus] (全编制，加合唱层，宽立体声)` | 这一段怎么做 |
| 纯歌词，无标签 | 把结构交给模型猜 → 通常给你标准模板 |

标签对照（v6 认的）：

| 标签 | 作用 |
|---|---|
| `[Intro]` / `[Outro]` | 器乐或氛围开场 / 收尾，可要求 `fade` 或 `full stop` |
| `[Verse]` | 叙事段，能量低 |
| `[Pre-Chorus]` | 过渡，把能量推上去 |
| `[Chorus]` / `[Hook]` | 峰值段，重复的钩子 |
| `[Bridge]` | 对比段，常降编制或转调 |
| `[Instrumental Break]` | 明确的无演唱段（独奏）；非电子语境比 `[Drop]` 稳 |
| `[Build]` / `[Drop]` | 电子与电影语境；用错流派会让模型困惑 |

三条纪律：

1. **每段单独一行，标签在段首。**
2. **副歌歌词逐字重复**（每次一字不改）——模型才会把它当钩子。
3. **合规率不是 100%。** 被忽略时，在标签后补一个圆括号注释再跑，比整首重来便宜得多。

### 4.3 两个旋钮：它调的是"宽度"，不是"好坏"

| 旋钮 | 真实含义 | 怎么调 |
|---|---|---|
| **Weirdness（怪异度）** | 允许偏离常规的程度 | 常规赛道调到 30–50；想找"意外的对"往 70 试。默认 50 = "正常" |
| **Style Influence（风格影响度）** | 文字对结果的约束强度 | 词写得准 → 调高；词是随手写的 → **别调高**，只会放大错误 |

**调到 100 不会"更好听"，只会"更极端"。** 与剪映里"强度滑杆其实是线性混合推子"同一性质——**它是数学量，不是审美量。**

### 4.4 参考层：四种锚，各锚住不同的东西

| 锚 | 锚住什么 | 锚不住什么 |
|---|---|---|
| **Inspire**（选一个歌单） | 大方向氛围 | 任何具体细节 |
| **上传音频** | 音色 / 律动 / 片段（免费 8 min，付费 30 min） | 结构，它会自己重排 |
| **上传 MIDI** | **音符骨架**：音高与时值 | 音色——MIDI 里没有声音 |
| **Voices / Persona** | 同一把嗓子 | 唱法与情绪 |

> **最容易误解的一句：MIDI 决定骨架，提示词决定肉体，两者缺一不可。** 详见 [[AI辅助写歌工作流]] §一。

## 五、六个改造工具：边界与代价

| 工具 | 做什么 | 保住什么 | 代价 |
|---|---|---|---|
| **Extend** | 从某时间点往后接 | 前面全部 | 接缝处常需交叉淡化；分次接完要 `Get Whole Song` |
| **Cover** | 换风格 / 换声音重唱 | **旋律与结构** | 编曲细节全换 |
| **Remaster** | 只重做混音层 | 演奏与演唱 | 救不回"塌了的结构" |
| **Mashup** | 多首元素混搭 | 基本不保 | 纯探索工具 |
| **Replace Section / Add Section** | 只重采样一段 | 其余全部 | **Premier 才有** |
| **Add Vocals / Add Instrumental** | 给已有素材加一条 | 原有素材 | **Premier 才有** |

**判断链：「想留住的东西」在旋律层 → Cover；在编曲层 → Replace；在混音层 → Remaster。**

## 六、三档模型：可控性 vs 意外性

| 模型 | 档位 | 性格 | 什么时候用 |
|---|---|---|---|
| **v6** | Pro / Premier | 最可预测，提示词回报最高 | **默认用这个**。定稿、要交付的东西 |
| **v6-wild** | Pro / Premier | 故意不可预测 | 冷门流派、实验、找"意外的对"。**少写细节，多跑几版** |
| **v6-mini** | 免费 | 快、轻 | 只试方向。只有"流派 / 主奏乐器 / 人声"三项可信 |

**v5 与 v5.5 已于 2026-09-09 v6 上线时停用。** 所以 2025 年那些"切回 v5 会更好混音"的建议，现在不成立了。

## 七、额度与成本：credits 和 downloads 是两件事

| | Free | Pro | Premier |
|---|---|---|---|
| 价格 | 0 | $10/月（年付 $8） | $30/月（年付 $24） |
| 模型 | v6-mini | v6 / v6-wild / v6-mini | 同左 |
| 生成 | 50 credits/天（≈10 首） | 2,500/月（≈500 首） | 10,000/月（≈2,000 首） |
| **下载** | **无** | **20 首/月** | **60 首/月** |
| 商用权 | ❌ 歌归 Suno | ✅ | ✅ |
| 分轨 | ❌ | 2 种（Auto / Split from mix） | 3 种（+ Advanced，近 100 种乐器） |
| Studio | ❌ | ❌ | ✅ |
| 局部替换 / 加段 | ❌ | ❌ | ✅ |

**一句话：credits 管"能不能试"，downloads 管"能不能拿走"。Pro 能生成 500 首，但只能拿走 20 首。**

所以正确姿势是：**在浏览器里反复改到定稿，只对定稿花下载额度。** 反过来说，不要"生成时就想着下载"——那会让你不敢试。

三个附带事实：

1. **credits 不累积**（日清/月清）；top-up 买的 credits 不过期，但需要订阅有效才能用。
2. **商用权跟"生成时所处的档位"走**，后来升级**不会追认**之前免费版生成的歌。所以"想发就先订阅，别先写"。
3. **有商用权 ≠ 有版权。** 美国法要求人类作者。你自己的词、旋律、编辑记录，是你唯一能主张的东西。

## 八、Pro 还是 Premier：分水岭不是 Studio

已有 Logic Pro 13 的话，Studio（浏览器 DAW，2.0 加了 MIDI 编辑、合成器、效果、自动化，可导 32bit/48kHz 多轨）**与 Logic 大面积重叠**。

**真正的分水岭是：Replace / Add Section 只有 Premier 有。**

| 你的实际行为 | 该选 |
|---|---|
| 生成一堆 → 挑一个 → 所有改造都在 Logic 里做 | **Pro** |
| 生成一堆 → 在 Suno 里就改到 90% → Logic 只做定稿 | **Premier** |
| 要"AI 严格照我写的旋律唱" | 两者都不够 → 见 [[AI辅助写歌工作流]] §七（ACE / SV） |

**建议路径：先 Pro 一个月，只记一个数——"我因为不能只改一段而整首重生成的次数"。** 每周超过 3 次，Premier 的 $20 差价买的是时间不是功能；低于每周 1 次，Pro 就一直够用。

## 九、什么时候该离开浏览器

Suno 的成品是一条混好的波形 → **你不能在 Suno 里"只把贝斯往下拉 2 dB"**。要动细节只有三条路：

| 路 | 代价 | 什么时候走 |
|---|---|---|
| **Suno Stems（Pro 起）** | 有损分离，会有串音 | **90% 的情况**。拆出来进 Logic 做裁剪、拼接、对齐 |
| **Suno Studio（Premier）** | 只能在浏览器里，好处是可导 32bit/48kHz 多轨 | 你想"留在 Suno 里做完" |
| 直接拿成品当素材 | 最省事 | 只要氛围，不要求细节可控 |

> **Stems 的真实定位不是"给你分轨去混音"，是"给你分轨去重新排列"。** Suno 的结构缺陷只能靠"拆开 → 重排 → 拼回去"来补，这一步落在 Logic。

## 十、操作矩阵

### A. 创作

| 动作 | 入口 | 底层在做什么 |
|---|---|---|
| Simple Create | 首页一句话 | 模型自己补齐所有层，可控性最低 |
| **Custom Mode** | 切 Custom | 打开 Style 与 Lyrics 两个框——**可控性的唯一来源** |
| Inspire | 选一个歌单 | 用一个歌单当风格锚 |
| Magic Song Descriptions | Style 框旁 | 把一两个词扩成完整描述（省事，但会加进你没要的东西） |
| 上传音频 | Advanced | 当音色/律动锚；免费 8 min，付费 30 min |
| 上传 MIDI | Create / Studio | 当音符骨架锚；Pro 起，v6-wild |

### B. 改造

| 动作 | 保住什么 |
|---|---|
| Extend → `Get Whole Song` | 前段全部，把分次接成整首 |
| Cover | 旋律与结构 |
| Remaster | 演奏与演唱 |
| Replace Section / 改单句 | 其余全部（Premier） |
| Mashup | 基本不保，纯采样 |

### C. 输出

| 动作 | 用途 |
|---|---|
| Download MP3 | 快速试听、发人听 |
| **Download WAV** | **进 DAW 必须用这个**，MP3 的有损压缩已经发生过了 |
| Extract Stems | 拆轨进 Logic；先试 Auto 模式 |
| Studio 导出多轨 | 把整条链留在 Suno 里做完时 |

### D. 管理

| 动作 | 说明 |
|---|---|
| **版本树命名** | 每次 Extend / Cover / Replace 都长分支；**标题里带用途**（"v3-副歌更炸"），否则三天后你分不清 |
| Persona / Voices | 固定一把嗓子；是"跨歌一致"的唯一手段 |
| Custom Model | 上传 ≥6 首自己的歌训练，Pro 可建 3 个。**慎用**——它会把你锁进一种风格，而你现在要的是探索 |
| 公开发布 | 发出去带社交属性，**不代表版权保护** |

## 十一、四周路线 + 精通三判据

| 周 | 目标 | 具体练习 |
|---|---|---|
| **W1** | 打通链路 | 一首歌从提示到 WAV 到 Logic，全程 90 分钟；不追求好听 |
| **W2** | 结构控制 | 同一段词给三种不同段落标签，听差别；练到"想让副歌晚 8 秒进"能做到 |
| **W3** | 局部改造 | 拿 W1 那首，**只改一段副歌，不整首重生成**；再 Cover 成另一种风格，比较哪一层变了 |
| **W4** | 完整交付 | 走完 [[AI辅助写歌工作流]] 的十天闭环，Suno 侧只用 Custom + Replace + Stems |

**"精通"的三个判据：**

1. 任何不满，能说出它塌在**解析 / 结构 / 生成 / 混音**哪一段。
2. 任何修改，能说出它动的是**整首还是一段**，以及会不会丢掉已有的"意外的对"。
3. 拿到一首别人的 Suno 作品，能**反推**出它大概用了什么风格词、什么结构标签。

## 十二、十二个高频坑

| # | 坑 | 正解 |
|---|---|---|
| 1 | 描述堆太多 | 超过 5–8 个概念就开始平均化；**砍词比加词有效** |
| 2 | 只写歌词不放 `[标签]` | 得到标准三分钟模板；每段都加标签 |
| 3 | 副歌每次重新措辞 | 模型不认它是钩子；**逐字重复** |
| 4 | 一不满意就整首重生成 | 丢掉"意外的对"；先判断能不能只改一段 |
| 5 | 把 Weirdness 当质量档 | 它是分布宽度；调到 100 只会更怪 |
| 6 | 拿艺术家名当锚 | 多数被屏蔽或平均化；描述特征 |
| 7 | 期待 MIDI 决定音色 | MIDI 里只有音符；骨架与肉体是两件事 |
| 8 | 用免费版认真做歌 | 歌归 Suno 且不可商用；想发就先订阅 |
| 9 | 用 MP3 进 Logic | 有损压缩已发生；导 WAV |
| 10 | 以为下载额度 = 生成额度 | Pro 只能拿 20 首；**改到定稿再下载** |
| 11 | 以为"能商用"= "有版权" | 人类作者才产生版权；保住自己的词与编辑记录 |
| 12 | 想用 Studio 替代 Logic | 两者重叠且 Studio 绑订阅；已有 Logic 就不为它升档 |
