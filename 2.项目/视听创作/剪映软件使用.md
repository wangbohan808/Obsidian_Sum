# 音视频编解码核心概念

## 分辨率

本质：图像空间采样密度，`宽 × 高`，代表横向、纵向像素采样点总数。

- 低分辨率 = 空间采样稀疏，细小纹理、细节因为采样不足直接丢失；
- 改变分辨率方法--缩放（scale）是独立重采样操作（插值算法 bicubic/lanczos），**不属于编码算法本身**；
- 单纯编解码（不加缩放滤镜）：分辨率不会自动改变；码流头记录宽高，解码器原样输出对应尺寸 YUV。
- ⚠️ 播放器把小视频铺满大屏：只是显示插值放大，素材本身分辨率不变，不能恢复丢失细节。


## 码率

原始帧 → 帧内 / 帧间预测 → 算出预测值 原图像素 − 预测值 = **残差（residual）** 残差做 DCT 变换 → **量化（Qp）** → 熵编码写入码流

- 预测：找画面运动、相似块，尽量让残差变小。**预测和码率无关。**
- 量化：决定残差能保留多少细节。**Qp 由码率预算约束**
    - 高码率预算 → Qp 小 → 量化步长很小 → 残差里的高频细节不容易被清零 → 重建画面更贴近原图
    - 低码率预算 → Qp 大 → 很多高频系数直接归零 → 细节丢失、方块、色带、糊

> 形象比喻： 预测 = 猜画面长什么样； 残差 = “猜的结果和真实画面差多少”； 码率 = 你愿意花多少文字，去记录这个差值。 钱多（高码率）：差值写得很精细；钱少（低码率）：差值粗略写，很多小差别直接忽略。



## Preset（编码预设）

控制编码器搜索复杂度--同一套编码算法，控制编码速度以及精度：`veryfast / medium / slow`

- slow：做多轮预分析、精细预测搜索、自适应量化；同等码率画质上限更高，编码慢；
- veryfast：简化搜索，编码速度优先；同等码率画质上限更低（Proxy 常用 veryfast）。


## 两种信息丢失

1. **空间缩放损失（分辨率降低）** 采样点数量变少；属于预处理；哪怕后续无损编码，细节永久无法还原。
2. **同分辨率有损编码量化损失** 采样点数量不变；像素数值被近似；丢失高频纹理，产生压缩伪影。

> Proxy = 【原素材缩放降分辨率 + 色度降采样】 + 【H.264 veryfast 低码率有损编码】，两类损失叠加。


## 有损编码vs无损编码

### 有损编码（H.264 / HEVC / AV1 / ProRes）

- 核心损失来源：**量化步骤**，丢弃人眼不敏感的高频信息，信息不可逆；
- 流程：变换 → 量化（丢信息） → 熵编码；解码：熵解码 → 反量化 → 反变换；
- 重点：**编码器决定丢哪些信息、怎么丢；合规解码器只负责按码流规范还原，同一个码流，不同合规解码器输出 YUV 几乎一致，画质差异主要来自编码器**；
- 同分辨率、同输入 YUV，更换编码标准 / 编码器实现，重建画面清晰度、伪影形态会不一样；
- ProRes / DNxHR：属于 “可控有损中间格式”，专门抑制代际损失，适合剪辑多次叠加渲染；分发用 H.264/HEVC 压缩比更高。

### 无损编码（H.264 Lossless / FFV1 / Ut Video）

- 没有量化步骤，只做熵压缩（类似 zip）；
- 编码→解码，YUV 逐像素完全一致，**编码链路内部无信息丢失**；
- 局限：压缩倍率低，文件体积大；
- 坑：如果编码前已经做了缩放、色度降采样，哪怕用无损编码，前面丢失的信息依然找不回来。


1. **量化**

- 仅有损编码拥有；
- 作用：对频域系数做除法取整，大量高频系数归零；
- 信息影响：**不可逆丢失信息**；Q 越大（码率越低）丢得越多；
- 结果：画面细节丢失、出现方块、色带等压缩伪影。

2. **熵编码 / 熵解码**

- 有损、无损编码都存在；
- 作用：基于概率分配变长码字，把整数序列打包成紧凑二进制码流；
- 信息影响：**完全无损，不丢失任何信息；解码可以精准还原出编码前那一组数字**；
- 它不决定画质好坏，只决定码流写得省不省空间。
