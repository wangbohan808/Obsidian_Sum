# 01 项目定位与简历路径

> **能写进简历，但不是"用 GStreamer 推流到 B 站"这个形态。**
> 判据只有一条：面试官问"这段是你写的吗"，你能指着代码说的比例。
> 目标是从"配置一个现成管线"升级成"实现并测量一条自己搭的管线"。

---

## 一、项目 vs 配置：一条硬分界

| 形态 | 你写的代码占比 | 面试官会怎么归类 | 写在哪一栏 |
|---|---|---|---|
| `gst-launch-1.0 ... ! rtmpsink` 一行命令 | ~0% | "会用工具" | 技能栏 |
| 自己的 C 程序：V4L2 采集 + MPP 编码 + 自己封 FLV/RTMP | ~60% | **工程项目** | 项目栏 |
| 上面再加 AI 旁路 + 端到端延迟分解 + 带宽实测 | ~80% | **有差异化的工程项目** | 项目栏（首位） |

**为什么必须跨过第一道坎**：GStreamer 那一行命令，任何一个看过两小时教程的人都能敲出来。它证明不了你会 V4L2 的 buffer 模型、证明不了你懂 DMA-BUF、更证明不了你能定位"为什么延迟下不来"。

**它不是没有价值——它的价值是"对照组"**：先用 gst-launch 跑通拿到基线延迟，再用 C 重写，然后对比"我的实现比 GStreamer 少了多少延迟、为什么"。这个对比本身就是面试里的高含金量材料。

## 二、三层递进（每层都能独立停下）

| 层 | 做什么 | 产出 | 简历价值 | 时间 |
|---|---|---|---|---|
| **L1 跑通** | gst-launch 单命令推 B 站，1080p60 | 能开播 + 一份管线笔记 | 0（技能栏） | 1 个周末 |
| **L2 重写** | C 实现：V4L2 QBUF/DQBUF 环形队列 + RGA 转 NV12 + MPP 编码 + 自己封 FLV + RTMP 发送 | 可编译运行的仓库 + 与 GStreamer 的延迟对比 | **主体** | 2–3 个周末 |
| **L3 加压** | 加 AI 旁路（抽帧 → RKNN → OSD 回注）+ 端到端延迟分解 + DDR 带宽实测 | 数据表 + 架构取舍说明 | **差异化** | 2 个周末 |

**L2 是必做项，L3 是拉开差距项。** 只做 L1 等于没做；只做 L1+L2 是一份合格的音视频项目；做到 L3 才有"能一个人扛一条多媒体管线"的说服力。

## 三、为什么音视频和端侧 AI 能合成一个项目（不是硬凑）

**在 RK3588 上，它们争的是同一份硬件资源：**

| 共享项 | 音视频侧 | AI 侧 | 冲突表现 |
|---|---|---|---|
| **DDR 带宽** | VENC 读写参考帧 | NPU 读权重 + 中间层特征图 | 编码掉帧、推理变慢 |
| **DMA-BUF** | V4L2 导出 fd → MPP 导入 | 同一帧直接喂 NPU，不 copy | 不做零拷贝就吃掉 1–2 个 A76 核 |
| **RGA** | YUY2→NV12、缩放 |  resize 到 640×640 输入 | 都抢 RGA 通道 |
| **16.7 ms 帧预算** | 60fps 硬约束 | 单帧推理 30ms，根本跑不满 | 必须抽帧 + 结果复用 |

**所以这不是"我又学了个 AI"，而是"我在一个实时约束下同时跑了视频和推理，并且量化了它们的资源竞争"。** 这句话在音视频岗和端侧 AI 岗都成立，而且比单讲任何一边都值钱。

## 四、AI 旁路的三个关键设计（面试就讲这个）

| 决策 | 做法 | 理由（要能说出来） |
|---|---|---|
| **抽帧而非逐帧** | 10fps 抽帧推理，其余帧复用上一次的框 | 60fps 只有 16.7ms 预算，推理 30ms 跑不满；检测滞后 100ms 对画面无感，掉帧却是致命的 |
| **旁路解耦** | 独立线程 + 有界队列，队列满**丢最旧帧** | 主链路绝不因推理排队而阻塞。宁可丢推理结果，不能丢视频帧 |
| **回注而非叠加在编码后** | 坐标回注 RGA 的 OSD 阶段，硬件 blend | 全程零拷贝；软件画框要再读一遍帧，DDR 直接翻倍 |

**这三条的共同点：所有设计都服务于"主链路不掉帧"，AI 是可降级的附加物。** 这个优先级判断本身，就是面试官想听的工程成熟度。

```
项目名称：基于 ROCK 5C 的低延迟音视频推流终端（1080p60 · AI 叠加）
定位：把直播推流当作真实需求，从零实现并测量一条 V4L2 → RGA → MPP → RTMP 管线

- 用 C 自行实现采集-编码-推流管线（不经 GStreamer），V4L2 多缓冲环形队列 +
  DMA-BUF 零拷贝直通 MPP，1080p60 端到端延迟 X ms（GStreamer 同链路基线 Y ms）；
- 全链路无 CPU 参与像素搬运：YUY2→NV12 与 OSD 叠加均由 RGA 完成，
  编码由 VENC 硬编承担，整机 CPU 占用 <Z%；
- 在同板并行部署 RKNN INT8 检测模型（抽帧 10fps + 结果复用 + 有界队列丢旧帧），
  量化后 mAP 损失 <1%，NPU 与 VENC 并发时编码帧率下降 <N 帧；
- 定位并量化瓶颈：1080p60 下 DDR 带宽需求 A GB/s，实测占理论峰值 B%，
  证明瓶颈在内存带宽而非编码单元算力。
```

**四个空格里的数字必须自己测。** 没测出来的就不写——这一行的每一个数，面试官都可能追问三层（怎么测的 / 什么条件下 / 为什么是这个值）。

## 七、面试必答的五个取舍

1. **为什么不用 GStreamer？** → 要精确控制延迟和内存；GStreamer 的 clock/buffer 管理带来不确定开销。但 GStreamer 是基线，保留了对比数据。
2. **延迟怎么测的？** → 逐段打点：采集出帧时间戳 → 编码完成 → 发送 → 接收端解码 → 显示。不能只测首尾，否则定位不到瓶颈。
3. **为什么 GOP 120？** → 2 秒，平台要求 + 新观众进房出画时间上限；再稀观众要黑屏等。
4. **为什么禁用 B 帧？** → B 帧要等后续帧，引入重排序延迟；格斗/直播场景延迟优先于压缩率。
5. **AI 为什么抽帧？** → 见 §四，帧预算是硬约束，且可降级。

## 八、风险与时间

| 风险 | 说明 | 应对 |
|---|---|---|
| **时间被加班吃掉** | 一/三/五 21:00 下班，周六上班，只有二/四晚 + 周日 | L2 拆成 3 个周末，每个周末只做一个模块（采集 / 编码 / 推流） |
| **12 月直播要上线** | 不能等 L2 完成才开播 | L1 用 gst-launch 先保开播，L2 并行做 |
| **贪多** | Q8B 也想要、AI 也想做成重点 | Q8B 暂缓；AI 只做旁路，不做重点 |
| **UVC 兼容性** | 便宜采集卡在 Linux 下可能只出 MJPG | 先 `v4l2-ctl --list-formats-ext` 验证再买/再写代码 |

**顺序不可颠倒：L1 保底 → L2 建主体 → L3 拉差异。** L2 没跑通就做 L3，结果会是两个都半成品。
