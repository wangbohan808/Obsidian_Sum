# Docker / WSL2 / Linux 环境

> **核心一句话**：用户态 rootfs（库、工具、目录）是绝大多数报错来源；内核是否重要，取决于你的工作流要不要操作硬件、特殊 ioctl、内核模块。**Docker 只能管用户态，管不了宿主机内核。**

---

## 先分清三层

| 层 | 是什么 | Docker 能否控制 |
|---|---|---|
| ① CPU 架构 | 指令集（x86-64 / ARM），硬件硬约束 | 能选对镜像架构 |
| ② 用户态 rootfs | 程序、库、目录（glibc、gcc、工具链） | ✅ 能锁定 |
| ③ 内核层 | 内核版本与配置（模块、ioctl、USB 驱动） | ❌ 复用宿主机，不可控 |

---

## 一、Docker 要点

1. 镜像**只含用户态 rootfs**（程序/库/目录），**不带内核**，容器复用宿主机内核。
2. 同一 Linux 镜像可在 Ubuntu/Debian/Arch 等不同宿主机跑，**不要求宿主机与镜像发行版一致**。
3. `pull` 只下载不校验；`run` 时才校验 CPU 架构 → 不匹配报 `exec format error`。
4. 多架构 manifest 镜像会**自动拉对应架构版本**；无多架构则「下载成功但启动失败」。
5. Windows 上 Docker Desktop 底层 = WSL2/Linux 虚拟机，Linux 容器复用**虚拟机内核**（非 Windows 原生内核）；Windows 容器镜像只能跑 Windows 内核。
6. Docker **锁不住宿主机内核版本与配置** → 无法完全解决嵌入式 SDK 的内核依赖问题。

---

## 二、WSL2 要点

| 角度 | 结论 |
|---|---|
| rootfs | 完整的 Ubuntu 发行版 |
| 内核 | **微软定制裁剪的 WSL2 内核**，非 Ubuntu 官方内核 |
| 升级 | `apt` 只更新用户态软件；内核跟随 Windows 更新 |
| 优势 | 轻量、秒启动、Windows–Linux 互通；适合纯应用层开发、普通编译、跑业务容器 |

**短板**
- 默认不能原生直通 USB 设备；
- 不支持随意 `insmod` 加载内核模块；
- 部分 `ioctl`、`/sys`、`/proc`、loop 设备行为与标准 Linux 内核有差异；
- systemd、cgroup 存在限制。

**适用边界**
- ✅ 纯交叉编译（只生成固件文件，不碰硬件/特殊 ioctl/内核模块）→ 可用；
- ❌ 含 USB 烧录、串口、块设备操作、加载内核模块 → **不可用**，改用普通 VM 虚拟机 / 物理双系统。

> 厂商文档一刀切禁止 WSL2：规避内核残缺导致的**固件静默损坏**、**硬件识别异常**等难排查 bug。

---

## 三、嵌入式 SDK 的三层约束

SDK 能否正常工作，由三层共同决定：

1. **CPU 架构（硬件层，硬约束）**
   - 预编译二进制工具绑定指令集；x86-64 的 SDK 工具不能原生跑在 ARM。
   - QEMU 模拟会引入静默 bug，厂商一般不支持。
   - ⚠️ 编译主机是 x86-64，交叉编译产出 **ARM 开发板固件**。
2. **用户态 rootfs 层（最常见报错来源）**
   - glibc 版本不匹配 → 预编译闭源二进制直接无法运行；
   - 工具链版本（gcc/dtc/mkfs）不对 → 可能编译无报错但固件损坏；
   - 文件目录、包名、脚本硬编码路径；
   - udev 设备权限、系统工具行为差异。
   - → **这就是厂商指定特定 Ubuntu 版本的主因**，Docker 可以锁定该层。
3. **内核层（次要，按需生效）**
   - 仅当流程涉及 USB 硬件、特殊 ioctl、loop 块设备、内核模块加载时，内核版本/配置才成为硬要求；
   - 纯文件交叉编译，内核差异几乎无影响。

---

## 四、环境选型速记

1. **普通业务开发**：WSL2、Docker，优先满足用户态即可。
2. **开发板 SDK**
   - 仅编译生成固件文件 → WSL2 有可能可用；
   - 需要烧录 / 调试硬件 → **必须 VM 虚拟机或原生物理 Linux**（保证发行版原版内核）。

## 关键区分表格

| 环境 | 用户态 Ubuntu22.04 | 原版 Ubuntu 内核 | x86-64 | 适合嵌入式 SDK |
|---|---|---|---|---|
| 物理机 Ubuntu22.04 | ✅ | ✅ | ✅ | ✅ |
| VM 虚拟机 Ubuntu22.04 | ✅ | ✅ | ✅ | ✅ |
| WSL2 Ubuntu22.04 | ✅ | ❌ 微软 WSL 内核 | ✅ | 仅纯编译可用 |
| Docker ubuntu:22.04（跑 WSL2） | ✅ | ❌ 继承 WSL 内核 | ✅ | 仅纯编译可用 |
| Docker ubuntu:22.04（跑原生 Ubuntu） | ✅ | ✅ 宿主机内核 | ✅ | ✅ |
| Arch Linux（x86-64） | ❌ | ✅ | ✅ | ❌ 用户态不匹配 |
