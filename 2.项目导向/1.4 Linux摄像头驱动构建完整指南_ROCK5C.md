# 第一部分：摄像头硬件与软件栈全景

## 1.1 RK3588/S 摄像头硬件架构

```
RK3588S 摄像头数据流:

┌──────────────┐    MIPI D-PHY/      ┌──────────────┐    CSI-2       ┌──────────────┐
│  摄像头       │───►C-PHY──────────►│  MIPI PHY     │───►(2.5Gbps)──►│  MIPI CSI-2  │
│  Sensor       │    2/4 lanes       │  dcphy0/1    │    per lane   │  Host Ctrl   │
│  (IMX415等)   │                    │  dphy0/1/2   │               │  mipi0/1/2   │
└──────────────┘                    └──────────────┘               └──────┬───────┘
                                                                         │
                                    ┌────────────────────────────────────┘
                                    ▼
                              ┌──────────────┐
                              │    RKCIF     │  ← Video Input Controller
                              │  (VIP/VICAP) │     裁剪/缩放/格式转换
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  RKISP 3.0   │  ← Image Signal Processor
                              │  (ISP30)     │     3A (AE/AWB/AF)
                              │              │     HDR/降噪/LSC/颜色校正
                              └──────┬───────┘
                                     │
                                     ▼
                              ┌──────────────┐
                              │  V4L2 框架   │  ← Video4Linux2
                              │  /dev/video* │     标准Linux视频接口
                              └──────┬───────┘
                                     │
                    ┌────────────────┼────────────────┐
                    ▼                ▼                 ▼
              ┌──────────┐   ┌──────────┐   ┌──────────────┐
              │ rkaiq    │   │ rkisp    │   │ GStreamer    │
              │ 3A Server│   │ Demo     │   │ / FFmpeg     │
              │ (用户态)  │   │ (调试)   │   │ (应用层)     │
              └──────────┘   └──────────┘   └──────────────┘
```

### RK3588 vs RK3588S 摄像头能力差异

| 特性 | RK3588 | RK3588S (ROCK-5C) |
|------|--------|-------------------|
| MIPI DCPHY | 3路 (dcphy0/1 + dphy2) | 2路 (dcphy0/1) |
| MIPI DPHY | 2路 (dphy0/1) | 1路 (dphy0) |
| 最大摄像头数 | 6-7个 | 2-3个 |
| ISP | ISP 3.0 (双ISP) | ISP 3.0 (双ISP) |
| 最大分辨率 | 48MP | 48MP |

> **关键点**: ROCK-5C 使用 RK3588S，仅有 dcphy0/dcphy1 两路 MIPI，适配时注意硬件连接限制。

# 第二部分：摄像头驱动构建 — 前置准备

## 2.1 确认硬件连接

在开始软件工作之前，**必须**确认硬件连接正确：

```
MIPI CSI 接口引脚 (ROCK-5C 26Pin FPC):

标准 15-pin / 22-pin MIPI CSI 排线连接:
  Pin 1-2:  GND
  Pin 3:    MIPI_CLK_P     (时钟差分正)
  Pin 4:    MIPI_CLK_N     (时钟差分负)
  Pin 5-6:  GND
  Pin 7:    MIPI_DATA0_P   (数据通道0正)
  Pin 8:    MIPI_DATA0_N   (数据通道0负)
  Pin 9:    MIPI_DATA1_P   (数据通道1正)
  Pin 10:   MIPI_DATA1_N   (数据通道1负)
  Pin 11-12: GND
  Pin 13:   MIPI_DATA2_P   (数据通道2正, 2-lane模式可NC)
  Pin 14:   MIPI_DATA2_N   (数据通道2负)
  Pin 15:   MIPI_DATA3_P   (数据通道3正, 2-lane模式可NC)
  Pin 16:   MIPI_DATA3_N   (数据通道3负)
  Pin 17-18: GND
  Pin 19:   SCL (I2C Clock, 通常I2C3或I2C6)
  Pin 20:   SDA (I2C Data)
  Pin 21:   RESET/PDN (Sensor复位)
  Pin 22:   VCC_3V3 / VCC_5V0

关键检查清单:
  [ ] MIPI 排线方向正确 (注意防呆口)
  [ ] 摄像头供电正常 (万用表测量 3.3V/5V)
  [ ] I2C 上拉电阻安装正确 (通常 2.2kΩ-4.7kΩ)
  [ ] Sensor XCLK 时钟 (通常 24MHz, 由主控提供)
  [ ] RESET 引脚电平正常 (通常低有效, 需拉高才能工作)
  [ ] PWDN 引脚电平正常 (通常高有效, 需拉低才能工作)
```

## 3.2 Camera Sensor 驱动架构

每个 MIPI CSI sensor 驱动是一个标准的 **I2C + V4L2 subdev** 驱动：

```
驱动文件结构 (以 IMX415 为例):

drivers/media/i2c/imx415.c
├── struct imx415                    ← 设备私有数据结构
├── imx415_probe()                   ← I2C probe (设备发现)
│   ├── 读取 chip_id 验证硬件
│   ├── 初始化 v4l2_subdev
│   ├── 初始化 media_pad
│   ├── 配置 v4l2_ctrl_handler
│   │   ├── V4L2_CID_EXPOSURE        ← 曝光
│   │   ├── V4L2_CID_ANALOGUE_GAIN   ← 增益
│   │   ├── V4L2_CID_HBLANK          ← 水平消隐
│   │   ├── V4L2_CID_VBLANK          ← 垂直消隐
│   │   ├── V4L2_CID_PIXEL_RATE      ← 像素时钟
│   │   └── V4L2_CID_LINK_FREQ       ← MIPI链路频率
│   └── 注册 V4L2 subdev
├── imx415_set_fmt()                 ← 设置格式 (分辨率/编码)
├── imx415_get_fmt()                 ← 获取当前格式
├── imx415_set_stream()              ← 开始/停止数据流
│   ├── 上电序列 (power on sequence)
│   │   ├── 设置 XCLK
│   │   ├── 拉高 PWDN
│   │   ├── 延时 1ms
│   │   ├── 拉低 RESET
│   │   ├── 延时 5ms (等待晶振稳定)
│   │   └── 拉高 RESET
│   ├── 写 sensor 寄存器 (通过 I2C)
│   │   ├── 设置工作模式 (软硬复位/standby)
│   │   ├── 设置 MIPI 通道数
│   │   ├── 设置输出格式
│   │   ├── 设置分辨率
│   │   ├── 设置帧率
│   │   └── 开始流输出
│   └── 停止序列 (stream off)
├── imx415_enum_mbus_code()         ← 枚举支持的 media bus 格式
├── imx415_enum_frame_size()        ← 枚举支持的分辨率
├── imx415_get_selection()           ← 获取 crop/compose 区域
└── imx415_power_on/off()            ← 电源管理 (runtime PM)

驱动入口:
module_i2c_driver(imx415_i2c_driver)

关键数据结构:
static const struct v4l2_subdev_video_ops imx415_video_ops = {
    .s_stream = imx415_set_stream,   ← 最重要的函数!
};
static const struct v4l2_subdev_pad_ops imx415_pad_ops = {
    .set_fmt = imx415_set_fmt,
    .get_fmt = imx415_get_fmt,
    .enum_mbus_code = imx415_enum_mbus_code,
    .enum_frame_size = imx415_enum_frame_size,
    .get_selection = imx415_get_selection,
};
```

## 3.3 从零添加一个 Camera Sensor 驱动（完整步骤）

### Step 1: 确定 Sensor 基本信息

```bash
# 从 datasheet 获取:
SENSOR_NAME="my_sensor"        # 型号
SENSOR_I2C_ADDR=0x10           # I2C 地址
SENSOR_CHIP_ID=0x0415          # 芯片ID寄存器值
SENSOR_LANES=2                 # MIPI 通道数 (2或4)
SENSOR_FORMAT="MEDIA_BUS_FMT_SRGGB10_1X10"  # RAW10格式
SENSOR_WIDTH=1920              # 默认宽度
SENSOR_HEIGHT=1080             # 默认高度
SENSOR_XCLK_FREQ=24000000      # 外部时钟频率 24MHz
SENSOR_LINK_FREQ=450000000     # MIPI 链路频率 450MHz
```

### Step 2: 在 DTS 中添加设备树节点

```dts
// 文件: arch/arm64/boot/dts/rockchip/rk3588s-rock-5c.dts
// 在文件末尾添加以下内容:

// =====================================================
// 1. 使能 MIPI DCPHY0 (摄像头使用)
// =====================================================
&csi2_dcphy0 {
    status = "okay";

    ports {
        #address-cells = <1>;
        #size-cells = <0>;
        port@0 {
            reg = <0>;
            #address-cells = <1>;
            #size-cells = <0>;

            // Sensor 连接到 dcphy0 的 endpoint@1
            mipi_in_dcphy0: endpoint@1 {
                reg = <1>;
                remote-endpoint = <&my_sensor_out>;
                data-lanes = <1 2>;  // 2-lane 模式
            };
        };
        port@1 {
            reg = <1>;
            #address-cells = <1>;
            #size-cells = <0>;

            csidcphy0_out: endpoint@0 {
                reg = <0>;
                remote-endpoint = <&mipi0_csi2_input>;
            };
        };
    };
};

// =====================================================
// 2. 使能 MIPI CSI-2 控制器
// =====================================================
&mipi0_csi2 {
    status = "okay";

    ports {
        #address-cells = <1>;
        #size-cells = <0>;

        port@0 {
            reg = <0>;
            #address-cells = <1>;
            #size-cells = <0>;

            mipi0_csi2_input: endpoint@1 {
                reg = <1>;
                remote-endpoint = <&csidcphy0_out>;
            };
        };

        port@1 {
            reg = <1>;
            #address-cells = <1>;
            #size-cells = <0>;

            mipi0_csi2_output: endpoint@0 {
                reg = <0>;
                remote-endpoint = <&cif_mipi_in0>;
            };
        };
    };
};

// =====================================================
// 3. 使能 RKCIF (VIP 控制器)
// =====================================================
&rkcif {
    status = "okay";
};

&rkcif_mipi_lvds {
    status = "okay";
    port {
        cif_mipi_in0: endpoint {
            remote-endpoint = <&mipi0_csi2_output>;
        };
    };
};

&rkcif_mipi_lvds_sditf {
    status = "okay";
    port {
        mipi_lvds_sditf: endpoint {
            remote-endpoint = <&isp0_in>;
        };
    };
};

&rkcif_mmu {
    status = "okay";
};

// =====================================================
// 4. 使能 ISP
// =====================================================
&rkisp0 {
    status = "okay";
};

&rkisp0_vir0 {
    status = "okay";
    port {
        #address-cells = <1>;
        #size-cells = <0>;

        isp0_in: endpoint@0 {
            reg = <0>;
            remote-endpoint = <&mipi_lvds_sditf>;
        };
    };
};

&rkisp0_mmu {
    status = "okay";
};

// =====================================================
// 5. 使能 I2C 总线 (Sensor 挂载的总线, 例如 i2c3)
// =====================================================
&i2c3 {
    status = "okay";
    pinctrl-names = "default";
    pinctrl-0 = <&i2c3m0_xfer>;  // 正确的 pinmux 配置
    clock-frequency = <400000>;   // 400kHz Fast Mode

    // =====================================================
    // 6. Camera Sensor 设备节点
    // =====================================================
    my_sensor: camera-sensor@10 {
        compatible = "vendor,my-sensor";     // 必须与驱动中的 of_match 一致!
        reg = <0x10>;                        // I2C 地址 (7位)
        clocks = <&cru CLK_MIPI_CAMARAOUT_M0>;
        clock-names = "xvclk";
        power-domains = <&power RK3588_PD_VI>;
        pinctrl-names = "default";
        pinctrl-0 = <&mipim0_camera_clk>;    // MIPI camera 时钟引脚
        rockchip,grf = <&sys_grf>;

        // GPIO 控制
        reset-gpios = <&gpio1 RK_PB3 GPIO_ACTIVE_LOW>;  // RESET: 低有效
        pwdn-gpios = <&gpio1 RK_PB4 GPIO_ACTIVE_HIGH>;  // PWDN: 高有效
        // 电源 (如果有独立 LDO 使能引脚)
        // dovdd-supply = <&vcc_1v8_cam>;
        // avdd-supply = <&vcc_2v8_cam>;
        // dvdd-supply = <&vcc_1v2_cam>;

        // 摄像头模块元数据
        rockchip,camera-module-index = <0>;      // 摄像头索引 (0=第一个)
        rockchip,camera-module-facing = "back";   // 朝向: front/back
        rockchip,camera-module-name = "MySensor"; // 模块名称
        rockchip,camera-module-lens-name = "default";

        // lens-focus = <&vcm_driver>;            // 自动对焦 VCM (如果有)

        port {
            my_sensor_out: endpoint {
                remote-endpoint = <&mipi_in_dcphy0>;
                data-lanes = <1 2>;
            };
        };
    };
};

// =====================================================
// 7. 添加 pinctrl 配置 (如果 mipim0_camera_clk 未定义)
// 注意: 这通常已在 rk3588s-pinctrl.dtsi 中定义
// 只需要确认以下引脚:
//   - REFCLK (MIPI CAMERA CLK, 24MHz)
//   - I2C3 SCL/SDA
//   - RESET GPIO
//   - PWDN GPIO
// =====================================================
```

## 4.1 GStreamer 管道架构

Rockchip 的 GStreamer 包含硬件加速插件：

```
GStreamer 摄像头数据流（RK3588）:

┌─────────────────────────────────────────────────────────────────────┐
│ GStreamer Pipeline 示例                                              │
│                                                                     │
│  v4l2src device=/dev/video0                                         │
│    │  (V4L2 从 ISP 输出节点获取 YUV/NV12 帧)                        │
│    ▼                                                                │
│  capsfilter video/x-raw,format=NV12,width=1920,height=1080          │
│    │  (格式协商)                                                     │
│    ▼                                                                │
│  mpph264enc                    ← RK MPP 硬件 H.264 编码器           │
│    │  (RK3588 VPU, 8K@30fps 实时编码)                               │
│    ▼                                                                │
│  h264parse                                                            │
│    │  (H.264 字节流解析为对齐单元)                                   │
│    ▼                                                                │
│  rtph264pay                                                           │
│    │  (RTP 打包)                                                     │
│    ▼                                                                │
│  udpsink host=192.168.1.100 port=5000                                 │
│    (网络发送)                                                        │
└─────────────────────────────────────────────────────────────────────┘
```

Rockchip GStreamer 关键插件:

```
插件类型          | 插件名            | 用途
────────────────────────────────────────────────────
Source           | v4l2src           | 标准 V4L2 视频源
Video Encoder    | mpph264enc        | MPP H.264 硬件编码
                 | mpph265enc        | MPP H.265 硬件编码
                 | mppvp8enc         | MPP VP8 硬件编码
                 | mppjpegenc        | MPP JPEG 硬件编码
Video Decoder    | mpph264dec        | MPP H.264 硬件解码
                 | mpph265dec        | MPP H.265 硬件解码
                 | mppvp9dec         | MPP VP9 硬件解码  (8K60!)
Video Converter  | rkpp              | RGA 2D 加速格式转换
                 | rkisp             | ISP 硬件预处理
Display Sink     | waylandsink       | Wayland 显示
                 | kmssink           | 直接 KMS/DRM 输出
                 | rkximagesink      | Rockchip X11 输出
```

## 4.2 摄像头调试命令大全

```bash
# ======================================================
# 1. 硬件检测
# ======================================================

# 检查 MIPI PHY
dmesg | grep -E "dcphy|dphy|mipi"
# 期望输出:
#   rk-dcphy dcphy0: ... initialized

# 检查 I2C 设备 (确认 sensor 在 I2C 总线上可见)
i2cdetect -r -y 3    # 检查 I2C-3 总线
# 期望看到: 10 或 1a 等 sensor I2C 地址

# 检查 V4L2 设备
ls -la /dev/video*
# 期望输出:
#   /dev/video0      ← ISP 主输出 (YUV/NV12)
#   /dev/video1      ← ISP 自检路径 (RAW)
#   /dev/video2      ← ISP 参数设备 (3A 使用)
#   /dev/video3      ← ISP 统计设备 (3A 使用)
#   /dev/video4      ← RKCIF 输出 (缩放/裁剪)

# 查看 media 拓扑
media-ctl -p
# 展示完整的 media pipeline:
#   sensor → csi2_dcphy → mipi_csi2 → rkcif → rkisp

# ======================================================
# 2. V4L2 设备检查
# ======================================================

# 查看设备能力
v4l2-ctl -d /dev/video0 --all
# 重要信息:
#   Driver Info: driver=rkisp-video
#   Format Video Capture: NV12, NV16, ...
#   Framesizes: 支持的分辨率列表

# 查看 sensor 支持的格式和分辨率
v4l2-ctl -d /dev/v4l-subdev0 --all
# (subdev0 通常是 sensor)

# 列出 sensor 支持的所有格式
v4l2-ctl -d /dev/v4l-subdev0 --list-subdev-mbus-codes

# 设置 sensor 格式
v4l2-ctl -d /dev/v4l-subdev0 \
    --set-subdev-fmt pad=0,code=0x3007,width=1920,height=1080
# 0x3007 = MEDIA_BUS_FMT_SRGGB10_1X10

# ======================================================
# 3. 采集测试
# ======================================================

# 捕获单帧 RAW 数据
v4l2-ctl -d /dev/video0 \
    --set-fmt-video=width=1920,height=1080,pixelformat=NV12 \
    --stream-mmap=3 \
    --stream-to=test_frame.raw \
    --stream-count=1

# 使用 media-ctl 配置 pipeline, 然后采集
# (完整 pipeline 配置, 适合复杂场景)

# ======================================================
# 4. GStreamer 测试
# ======================================================

# 最简单: 预览摄像头 (需要显示器)
gst-launch-1.0 v4l2src device=/dev/video0 ! \
    video/x-raw,format=NV12,width=1920,height=1080 ! \
    waylandsink

# 预览 + 录制 H.264
gst-launch-1.0 -e v4l2src device=/dev/video0 num-buffers=300 ! \
    video/x-raw,format=NV12,width=1920,height=1080,framerate=30/1 ! \
    mpph264enc ! h264parse ! \
    splitmuxsink location=video_%02d.mp4 max-size-time=60000000000

# RTSP 推流 (需要 rtsp-server)
# 先安装: apt install gstreamer1.0-rtsp
gst-launch-1.0 v4l2src device=/dev/video0 ! \
    video/x-raw,format=NV12,width=1920,height=1080,framerate=30/1 ! \
    mpph264enc ! h264parse ! rtph264pay name=pay0 pt=96

# 拍照 (JPEG)
gst-launch-1.0 v4l2src device=/dev/video0 num-buffers=1 ! \
    video/x-raw,format=NV12,width=1920,height=1080 ! \
    mppjpegenc ! filesink location=photo.jpg

# ======================================================
# 5. 性能测试
# ======================================================

# 测试 ISP 输出帧率
v4l2-ctl -d /dev/video0 \
    --set-fmt-video=width=1920,height=1080,pixelformat=NV12 \
    --stream-mmap --stream-count=100 2>&1 | grep "fps"

# 测试编码性能 (gst 内建 fps 显示)
gst-launch-1.0 v4l2src device=/dev/video0 ! \
    video/x-raw,format=NV12,width=3840,height=2160,framerate=30/1 ! \
    mpph265enc ! fakesink -v 2>&1 | grep fps

# ======================================================
# 6. ISP 3A 调试 (rkaiq)
# ======================================================

# 启动 3A server (通常在后台运行)
rkaiq_3A_server &

# 使用 rkaiq_tool_server 进行 ISP 调试
# (需要配套 IQ 文件, 路径: /etc/iqfiles/)
ls /etc/iqfiles/   # 检查 IQ 参数文件

# 检查 3A 状态
cat /sys/class/video4linux/video0/name
```

## 5.1 什么是 3A

```
3A = AE (Auto Exposure) + AWB (Auto White Balance) + AF (Auto Focus)

rkaiq_3A_server 工作流程:

   ISP Stats (v4l2 video node)          IQ 参数文件 (.json)
   ┌─────────────────────┐         ┌──────────────────────┐
   │ 亮度直方图           │         │  Camera 模组校准数据  │
   │ 颜色统计             │         │  - 黑电平校正         │
   │ 对焦统计             │         │  - 镜头阴影校正(LSC)  │
   │ 运动检测             │         │  - 颜色校正矩阵(CCM)  │
   └─────────┬───────────┘         │  - Gamma曲线          │
             │                     │  - 降噪参数           │
             ▼                     └──────────┬───────────┘
        ┌─────────────────────────────────────┼──────┐
        │            rkaiq_3A_server          │      │
        │                                     │      │
        │  ┌──────────┐  ┌─────────┐  ┌─────┐ │      │
        │  │ AE 算法   │  │AWB 算法  │  │AF    │◄┘      │
        │  │(曝光计算) │  │(白平衡)  │  │算法  │        │
        │  └─────┬────┘  └────┬─────┘  └──┬───┘        │
        └────────┼────────────┼───────────┼────────────┘
                 ▼            ▼           ▼
        ┌─────────────────────────────────────────────┐
        │         ISP 参数 (v4l2 video node)           │
        │  - 曝光时间 / 增益  - 白平衡增益              │
        │  - 对焦位置          - 降噪强度               │
        └─────────────────────────────────────────────┘
```

# 第六部分：从 MCU 到 BSP — 思维转型指南

## 6.1 MCU vs Linux BSP 核心差异

```
                    MCU 开发                      Linux BSP 开发
────────────────────────────────────────────────────────────────
运行环境      | 裸机/RTOS, 无MMU           | Linux 内核+用户态, MMU保护
内存管理      | 静态分配, 手动管理          | 虚拟内存, kmalloc/vmalloc/dma
外设访问      | 直接寄存器读写              | 通过内核子系统 (I2C/SPI/V4L2)
驱动模型      | 轮询/中断服务函数            | probe/remove/ioctl 框架
编译/构建     | IDE + 交叉编译              | Kbuild/Makefile + DT overlay
调试方式      | JTAG/SWD, 逻辑分析仪        | dmesg, printk, debugfs, kgdb
代码复用      | 复制粘贴/CMSIS库            | 内核框架 + 设备树
并发         | Superloop/RTOS task         | workqueue/tasklet/kthread/irq
时间系统      | 定时器中断 + 计数器         | jiffies/hrtimer/ktime
错误处理      | 死循环/看门狗               | 错误码返回 + dev_err/probe_defer
```

## 6.2 MCU 工程师最容易踩的坑

### 坑1: 直接用寄存器地址

```c
// ❌ MCU 做法 — 内核中直接操作寄存器会崩溃
#define MY_PERIPH_BASE 0xFF000000
*(volatile u32 *)(MY_PERIPH_BASE + 0x04) = 0x1234;

// ✅ BSP 做法 — 使用内核 API
#include <linux/io.h>
void __iomem *base = ioremap(0xFF000000, 0x1000);
writel(0x1234, base + 0x04);
// 或使用 regmap API (推荐)
#include <linux/regmap.h>
regmap_write(map, reg_offset, value);
```

### 坑2: 忙等延时

```c
// ❌ MCU 做法 — 阻塞 CPU, 浪费功耗
for (int i = 0; i < 1000000; i++);  // busy wait

// ✅ BSP 做法
usleep_range(1000, 2000);   // 微秒级睡眠
msleep(10);                  // 毫秒级睡眠
mdelay(1);                   // 不得已才用忙等
```

### 坑3: 全局变量满天飞

```c
// ❌ MCU 做法
int g_sensor_mode = 0;  // 全局变量

// ✅ BSP 做法 — 使用驱动私有数据
struct my_sensor {
    int mode;
    struct i2c_client *client;
    struct v4l2_subdev sd;
    // ... 所有状态都封装在这里
};

// 通过 container_of 获取
struct my_sensor *sensor = to_my_sensor(sd);
```

### 坑4: 不理解 probe-defer 机制

```c
// ❌ MCU 思维: 所有初始化在 main() 中顺序执行
// ✅ BSP 思维: 驱动可能因为依赖未就绪而延迟

static int my_sensor_probe(struct i2c_client *client)
{
    // 获取 GPIO — 可能返回 -EPROBE_DEFER
    gpiod = devm_gpiod_get(&client->dev, "reset", GPIOD_OUT_HIGH);
    if (IS_ERR(gpiod)) {
        if (PTR_ERR(gpiod) == -EPROBE_DEFER)
            // GPIO 控制器还没加载, 稍后重试
            // 这是正常的! 不要 panic!
            return -EPROBE_DEFER;
        return PTR_ERR(gpiod);
    }
    // ...
}
```

### 坑5: 用 printk 代替正确的错误处理

```c
// ❌ MCU 做法
if (!valid) {
    printk("ERROR!\n");
    while(1);  // 死循环 — 在内核中是灾难!
}

// ✅ BSP 做法
if (!valid) {
    dev_err(&client->dev, "Invalid chip ID: 0x%02x\n", chip_id);
    return -ENODEV;  // 返回错误, 让框架处理清理
}
```

## 6.3 MCU → BSP 技能映射表

```
MCU 技能                        Linux BSP 对应技能
─────────────────────────────────────────────────────
GPIO 读写                       gpiod_set_value / gpiod_get_value
PWM 控制                        pwm_apply_state / pwm_config
I2C 通信                        i2c_transfer / regmap_i2c
SPI 通信                        spi_write / spi_read / regmap_spi
UART 通信                       serial8250 / tty 驱动框架
定时器                          hrtimer / timer_list / workqueue
中断处理                        request_irq / threaded_irq
DMA 传输                        dmaengine API
ADC 采集                        IIO 子系统
Flash 存储                      MTD / SPI NOR 驱动
寄存器位操作                     readl/writel / regmap_update_bits
中断优先级                      IRQF_NO_THREAD (top half) / workqueue (bottom half)
看门狗                          watchdog subsystem
低功耗/休眠                     runtime PM / system suspend
```

# 第七部分：摄像头调试排错速查

## 7.1 问题: `i2cdetect` 看不到 sensor

```
排查步骤:
1. 检查供电 — 用万用表测量 sensor VDD (通常 2.8V/1.8V/1.2V)
2. 检查 RESET 引脚 — 确保为高电平 (低有效 sensor)
3. 检查 PWDN 引脚 — 确保为低电平 (高有效 sensor)
4. 检查 XCLK — 用示波器测 sensor XCLK 引脚, 应有 24MHz 时钟
5. 检查 I2C 上拉电阻 — 确保 SDA/SCL 有上拉 (2.2k~4.7k)
6. 检查 I2C 引脚 pinmux — 查看 pinctrl 配置
7. 换一根排线 — MIPI 排线容易接触不良
8. 换一个 camera 模组 — 排除硬件损坏
```

## 7.2 问题: sensor 探到但 `/dev/video0` 不存在

```
排查步骤:
1. 确认 MIPI 数据通路正确:
   dmesg | grep -E "mipi|csi|dcphy|rkisp"
2. 确认 s_stream 回调被调用了
3. 用 media-ctl 检查 pipeline 连通性
4. 尝试手动初始化 pipeline:
   media-ctl -d /dev/media0 --set-v4l2 "'m00_f_imx415 1-0010':0[fmt:SRGGB10_1X10/1920x1080]"
```

## 7.3 问题: 有 `/dev/video0` 但采集黑屏

```
排查步骤:
1. 确定 sensor 有数据输出:
   - 用示波器测 MIPI 数据线有无信号
2. 检查 ISP 输出格式 (YUV/NV12?)
3. 检查链路频率配置与 sensor 输出一致
4. 检查 IQ 文件是否正确加载
5. 用 v4l2-ctl --stream-mmap 采集原始数据, 用十六进制查看是否有非零值
```

## 7.4 问题: 图像花屏/条纹

```
可能原因:
1. MIPI 信号完整性 — 布线过长/无阻抗匹配
2. 链路频率过高 — 降低 MIPI 速率
3. Lane 数配置错误 — 2-lane sensor 配成 4-lane
4. 像素时钟计算错误 — PCLK vs LINK_FREQ 的关系
5. DMA buffer 对齐问题
6. ISP 裁剪区域配置错误
```

# 第八部分：进阶 — UVC Gadget (将 ROCK-5C 作为 USB 摄像头)

如果你想将 ROCK-5C 变成一个 USB 摄像头设备:

```bash
# 1. 内核配置
CONFIG_USB_GADGET=y
CONFIG_USB_CONFIGFS=y
CONFIG_USB_CONFIGFS_F_UVC=y

# 2. 创建 UVC gadget 配置
mkdir -p /sys/kernel/config/usb_gadget/rock5c-uvc
cd /sys/kernel/config/usb_gadget/rock5c-uvc

# 3. 设置 VID/PID
echo 0x1d6b > idVendor
echo 0x0104 > idProduct
echo 0x0100 > bcdDevice
echo 0x0200 > bcdUSB

# 4. 创建配置
mkdir -p configs/c.1
echo 500 > configs/c.1/MaxPower

# 5. 创建 UVC 功能
mkdir -p functions/uvc.usb0
echo 2048 > functions/uvc.usb0/streaming_maxpacket
echo 1 > functions/uvc.usb0/streaming_interval

# 6. 链接功能
ln -s functions/uvc.usb0 configs/c.1/

# 7. 绑定 USB 设备控制器
echo fc000000.usb > UDC

# 8. 在用户空间, 将 V4L2 输出通过 UVC gadget 发送
# 使用 uvc-gadget 工具
uvc-gadget /dev/video0 /dev/video_uvc
```
