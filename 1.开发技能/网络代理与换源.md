# 网络代理与换源

> [!info] 一句话结论
> 国内拉取代码与软件包慢，本质是两个独立问题：**「下载地址」慢靠换源，「出口链路」差靠代理**。二者是「接力」而非冲突——镜像里有该文件就直连下载、不触发代理，只有镜像缺失才回退原始 URL 交给代理。

## 要点
- 代理工具两类：Watt Toolkit（Host 模式优选物理服务器）与 Clash（混合端口 `7897` 同时支持 HTTP/SOCKS5）。
- 优先级：环境变量 `http_proxy` < 工具自身配置 < 命令行参数，越精确越优先；`unset` 只影响当前 shell。
- **换源只改下载地址、不改内容**，且每个包管理器都要单独配（apt / pip / npm / repo / Buildroot / Yocto…）。
- 镜像与外网代理配合时，务必把国内镜像域名放进 `NO_PROXY`，否则会绕远路。
- 需要长期后台运行的进程用 systemd 管理；用户级服务须 `systemctl --user enable`，跨登录需 `loginctl enable-linger`。
- Watt 自签证书可导入系统与 Firefox，从而**替代 `http.sslVerify false`**，兼顾可用与安全。

## 代理工具

### Watt Toolkit
- Windows 下微软应用商店可直连下载安装；Linux 使用需先解决证书写入权限：
  ```bash
  sudo chmod a+w /etc/hosts
  ```
- 同一域名会解析到不同物理服务器，**Host 模式会挑选更优的一台**。
- 代理之所以快：VIP 通道人少不堵、手续少（省去官方通道的检查环节）。

两条链路对比：

```text
电脑 → 国内默认路由 → 国际出口（拥堵/丢包）→ GitHub
电脑 → 127.0.0.1:26561 → 代理客户端 → 优选专线/轻量国际出口 → GitHub
```

> [!note] 开不开代理，PC 的默认网关都不变；变化的是「浏览器/工具把请求交给谁转发」——不再直连国际出口，而是先发给本机代理端口。

### Clash
- 混合端口 `7897` 同时支持 HTTP 与 SOCKS5。
- **使用直连节点通常无法下载**，必须选择一个稳定的代理节点。
- 配置分两种粒度：环境变量（全局 shell）或工具专属配置（仅作用于该工具，如包管理器、编译系统）。

```bash
export HTTP_PROXY=http://127.0.0.1:7897
export HTTPS_PROXY=http://127.0.0.1:7897
export ALL_PROXY=socks5://127.0.0.1:7897
export NO_PROXY=localhost,127.0.0.1,::1
```

## 通用代理原理与验证

### 优先级与作用域
环境变量 `http_proxy` < 工具自身配置（如 `http.proxy`）< 命令行参数。

> [!warning] `unset` 只清当前 shell，不改配置文件
> 若代理写在 `~/.bashrc` 里，`unset http_proxy` 只对当前终端生效；**新开终端又会自动加载旧代理**。要永久去除必须编辑 `~/.bashrc`。

### 直连例外 NO_PROXY
`127.0.0.1` 是 IPv4 回环、`::1` 是 IPv6 回环，本机程序访问本机端口不应走代理：

```bash
export NO_PROXY=localhost,127.0.0.1,::1
```

> [!error] 漏配 NO_PROXY 的典型故障
> `curl http://localhost:3000/api` 被转发到 Clash:7897 → Clash 去外网找 `localhost`（不存在）→ 连接失败。加上 `no_proxy` 后才会直连本机 3000 端口。

常用工具对环境变量的支持：

| 工具 | 是否读取代理环境变量 |
| --- | --- |
| curl / wget | `http_proxy`、`https_proxy`、`no_proxy` |
| git | 优先自身 `http.proxy` 配置，也支持环境变量 |
| pip / apt | 支持标准代理变量 |
| docker pull | 支持 `HTTP_PROXY` |

### 镜像与代理的接力关系
- 镜像与代理**不冲突**：镜像内有该文件就直接下载，不会访问原始 URL、不触发代理；
- 仅当镜像缺失或下载失败，才回退原始 URL，此时才需要代理。

### 代理与软件源协同
| 配置 | 实际请求地址 | 出口 | 结果 |
| --- | --- | --- | --- |
| 无镜像 + 无代理 | `github.com` | 本地直连 | 慢（跨国） |
| 无镜像 + 代理（规则模式） | `github.com` | 代理服务器 | 取决于节点质量 |
| 清华源 + 无代理 | `mirrors.tuna.tsinghua.edu.cn` | 本地直连 | **快** |
| 清华源 + 代理（规则模式） | 同上，命中 `DIRECT` | 本地直连 | **快**，且不耗代理流量 |
| 清华源 + 代理（全局模式） | 同上，无例外全走 `PROXY` | 代理绕路 | 慢，浪费流量 |

### 验证与清理
```bash
# 查看工具自身代理配置
git config --global --list | grep proxy
# 查看当前 shell 的代理环境变量
env | grep -i proxy
# 测试代理是否生效（只看响应头）
curl -I https://www.google.com 2>&1 | grep -i proxy
```

## 各类包管理器换源

**换源只替换下载地址，内容完全相同**；同一包管理器的不同镜像只是「拉取位置」和「网速」不同。

| 包管理器 | 适用场景 | 配置文件/命令 | 配置示例 |
| --- | --- | --- | --- |
| APT | Debian/Ubuntu 系统包 | `/etc/apt/sources.list` | 手动替换仓库地址 |
| YUM/DNF | CentOS/RHEL/Fedora | `/etc/yum.repos.d/*.repo` | 手动替换 `.repo` 地址 |
| pip | Python 包 | `~/.pip/pip.conf` | `pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple` |
| npm | Node.js 包 | `~/.npmrc` | `npm config set registry https://registry.npmmirror.com` |
| Docker | 容器镜像 | `/etc/docker/daemon.json` | 加 `registry-mirrors` 字段 |
| Go | Go 模块 | 环境变量 `GOPROXY` | `go env -w GOPROXY=https://goproxy.cn,direct` |
| repo | 多仓同步 | `REPO_URL` 环境变量 | 见下节（Yocto/Buildroot 均依赖） |

三类配置方式：
1. **改配置文件**：APT、YUM、Docker，直接编辑对应文件替换 URL；
2. **专用命令行**：pip、npm、Go，一条命令切换；
3. **URL 替换**：Git / repo 通过 `insteadOf` 让访问原地址时自动跳到镜像。

> [!tip] 常用镜像站：清华 `tuna`、阿里云、中科大 `ustc`；一般选离你最近的。临时使用可 `pip install -i <镜像地址>`。

## 编译与仓库换源

### repo 换源（清华）
```bash
# 1. 永久指定 repo 清华源
echo 'export REPO_URL=https://mirrors.tuna.tsinghua.edu.cn/git/git-repo' >> ~/.bashrc
source ~/.bashrc

# 2. 把 ~/bin 加入 PATH
mkdir -p ~/bin
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

# 3. 下载 repo 启动脚本
curl -sSL https://mirrors.tuna.tsinghua.edu.cn/git/git-repo -o ~/bin/repo
chmod a+x ~/bin/repo

# 4. 制作本地缓存，后续新项目直接拷贝，免排队
mkdir -p ~/repo-cache && cp ~/bin/repo ~/repo-cache/
```

### Buildroot 个别包下载失败
适用场景：只配了代理、编译时个别包 `403/404/超时`。

1. 从报错日志提取三要素：`host-包名-版本`、阻塞的**完整文件名**（含 `.tar.gz`/`.tar.lz` 等所有后缀）、临时目录 `output/rockchip_rk3588/build/`。
2. 进入 Buildroot 缓存目录手动补包：
   ```bash
   cd ~/rk3588_sdk/buildroot/dl/包名
   # 首选 GNU 官方源（http 兼容性最好）；403 时用 curl 伪装浏览器
   curl -L -A "Mozilla/5.0" http://ftp.gnu.org/gnu/包名/完整文件名 -o 完整文件名
   # 备选国内镜像
   curl -L -A "Mozilla/5.0" https://mirrors.aliyun.com/gnu/包名/完整文件名 -o 完整文件名
   ```
3. **清理编译残留（核心步骤）**，再重新编译：
   ```bash
   cd ~/rk3588_sdk
   rm -rf buildroot/output/rockchip_rk3588/build/host-包名-版本*
   ./build.sh           # 或 cd buildroot && make
   ```

| 报错 | 处理 |
| --- | --- |
| 403 Forbidden | 弃用 `wget`，改用 `curl + 浏览器 UA` |
| 404 Not Found | 严格核对文件名、版本、后缀，补全缺失格式 |
| 连接超时 | 换镜像源，或用手机/他机下载后 `scp`/U 盘传入 |

> [!tip] 速记：读日志 → 提取包名/版本/文件名 → `dl/包名` 手动下包 → 清 `output/build` 残留 → 重新编译。

### Yocto / BitBake 换源
清掉可能干扰的代理后，用镜像优先策略（完整 `local.conf` 见 `2.项目/猫咪监控/02_Yocto镜像构建.md`）：

```text
# 通配替换：优先走国内镜像
PREMIRRORS_prepend = "\
    git://.*/.* http://mirrors.tuna.tsinghua.edu.cn/git/yocto/ \n \
    https://.*/.* http://mirrors.tuna.tsinghua.edu.cn/yoctoproject/ \n \
    ftp://.*/.* http://mirrors.tuna.tsinghua.edu.cn/yoctoproject/ \n \
"
INHERIT += "own-mirrors"
SOURCE_MIRROR_URL = "http://mirrors.tuna.tsinghua.edu.cn/yoctoproject/"
# 提高 wget 重试与超时，应对网络抖动
FETCHCMD_wget = "/usr/bin/env wget -t 10 -T 180"
```

也可为所有 Yocto 构建建一份全局镜像配置：

```bash
mkdir -p ~/.bitbake
cat > ~/.bitbake/site.conf <<'EOF'
BB_GENERAL_MIRROR = "http://mirrors.ustc.edu.cn/yocto/sources/ http://mirrors.tuna.tsinghua.edu.cn/yocto/sources/"
EOF
```

> [!warning] Yocto 仓库默认用被拦截的 `git://` 协议，需强制转为 `https://` 才能走代理/镜像：
> ```bash
> git config --global url."https://".insteadOf git://
> ```

## 系统加速与开机自启

### 程序后台运行
```bash
# & 后台运行，立即返回终端
/opt/watt/Steam++.sh &

# nohup 脱离终端（关终端不被杀）+ 日志重定向 + 后台
nohup /opt/watt/Steam++.sh > ~/watt.log 2>&1 &

# 批量结束名称包含 Steam++ 的进程
pkill -f "Steam++"
```

> [!tip] 终端输出滚屏太快来不及复制：**`Ctrl+S` 暂停 → 鼠标选中 → `Ctrl+Shift+C` 复制 → `Ctrl+Q` 继续**。

### 用 systemd 管理服务
Linux 的「服务」就是被 `systemd` 统一管控、长期后台运行的进程。**用户级服务更适合依赖图形会话的 GUI 程序**（如 Watt）：

```bash
# 用户服务（推荐用于 Watt）：等网络和图形会话都就绪再启动
mkdir -p ~/.config/systemd/user
nano ~/.config/systemd/user/watt-toolkit.service
```
```ini
[Unit]
Description=Watt Toolkit (Steam++)
After=graphical-session.target network-online.target

[Service]
Type=simple
Environment=DISPLAY=:0
Environment=XAUTHORITY=%h/.Xauthority
WorkingDirectory=%h
ExecStart=/opt/watt/Steam++.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
```
```bash
systemctl --user daemon-reload
systemctl --user enable --now watt-toolkit
systemctl --user status watt-toolkit
```

> [!warning] 配成系统级服务后可能反而**无法访问 GitHub**，此时应改用上面的用户级服务。
> ```bash
> # 系统级（不适用 GUI 程序，仅作对照）
> sudo systemctl daemon-reload && sudo systemctl enable --now watt-toolkit.service
> ```

### 开机自启常见位置
| 层级 | 位置 | 说明 |
| --- | --- | --- |
| 系统 systemd | `/etc/systemd/system/`、`/lib/systemd/system/` | `systemctl enable <svc>` |
| 系统 systemd(用户) | `/etc/systemd/user/` | 需 `linger` 生效 |
| SysV 兼容 | `/etc/init.d/`、`/etc/rc*.d/` | 由 `update-rc.d` 管理 |
| 启动脚本 | `/etc/rc.local` | 需可执行 + `rc-local.service` |
| 环境变量 | `/etc/environment`、`/etc/profile`、`/etc/profile.d/*.sh` | 登录时执行，代理残留常见来源 |
| PAM | `/etc/security/pam_env.conf`、`/etc/default/locale` | 被 `pam_env` 读取 |
| 定时任务 | `/etc/crontab`、`/etc/cron.d/*` | 可用 `@reboot` |
| 显示管理器 | `/etc/gdm3/*`、`/etc/lightdm/*`、`/etc/X11/Xsession.d/` | X 会话启动时执行 |
| 用户 shell | `~/.profile`、`~/.bash_profile`、`~/.bashrc`、`~/.zshrc` | 登录/交互 shell |
| 用户 systemd | `~/.config/systemd/user/` | `systemctl --user enable` |
| 桌面自启 | `~/.config/autostart/*.desktop` | 桌面环境自动启动目录 |

> [!info] 用户服务跨登录自启需开启 linger：`sudo loginctl enable-linger <username>`。

## 证书与系统配置

### 系统/终端证书（curl、Git、系统工具）
```bash
# 1. 建证书目录（Ubuntu 22.04 必做）
sudo mkdir -p /usr/local/share/ca-certificates/
# 2. 复制 Watt 证书并改为 .crt、设标准权限
sudo cp ~/.local/share/Steam++/Plugins/Accelerator/SteamTools.Certificate.cer \
        /usr/local/share/ca-certificates/steamtools.crt
sudo chmod 644 /usr/local/share/ca-certificates/steamtools.crt
# 3. 更新系统证书缓存
sudo update-ca-certificates
```
```text
# 让 Git 信任该证书，替代关闭 SSL 校验：
git config --global --unset http.sslVerify
git config --global http.sslCAInfo /usr/local/share/ca-certificates/steamtools.crt
```

> [!danger] `git config --global http.sslVerify false` 会全局关闭 SSL 校验，长期使用存在中间人风险，仅可临时规避证书报错；正式的替代方案是上面的 `http.sslCAInfo`。

验证：
```bash
curl --proxy http://127.0.0.1:26561 https://github.com   # 无需 -k
```

### Firefox 单独导入证书
Firefox 使用独立证书库，不共用系统证书，需手动导入：设置 → 隐私与安全 → 查看证书 → 证书颁发机构 → 导入（`Ctrl+H` 显示隐藏目录，进入 `.local/share/Steam++/Plugins/Accelerator`）→ 勾选「信任此 CA 以标识网站」→ 重启。

> [!tip] 找不到隐藏目录时，先把证书拷到桌面再导入。

### 卸载清理
```bash
sudo rm /usr/local/share/ca-certificates/steamtools.crt
sudo update-ca-certificates
git config --global --unset http.sslCAInfo
```
Firefox 则在「查看证书 → 证书颁发机构」中删除对应 Watt 根证书。

## 网络排查

### 代理残留排查
当常见 shell 配置与 systemd 用户环境都查过、代理变量却仍存在时，重点检查：

| 顺序 | 位置 | 命令 |
| --- | --- | --- |
| 1 | `/etc/profile.d/`（可能无 `.sh` 后缀） | `grep -r proxy /etc/profile.d/` |
| 2 | `/etc/X11/Xsession.d/`（X 会话启动前执行） | `grep -r proxy /etc/X11/Xsession.d/` |
| 3 | `~/.xprofile`（可能含隐藏字符） | `cat -A ~/.xprofile` |
| 4 | 桌面自启动目录 | `ls ~/.config/autostart/` |
| 5 | PAM 环境 | `cat /etc/security/pam_env.conf`、`/etc/default/locale` |

> [!tip] 想登录时自动清除持久化代理，可在 `~/.profile` 末尾加：
> ```bash
> unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY all_proxy ALL_PROXY
> ```

### 常用排查命令
```bash
echo $http_proxy $https_proxy          # 看当前代理
top                                     # 查看各进程 CPU 资源占用
curl -v http://localhost:8080 2>&1 | grep -i "no proxy"   # 验证 no_proxy
```
