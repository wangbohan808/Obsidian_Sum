# Logic Pro 13 · 本质模型与功能全图

> **一句话核心：Logic 不是录音机，是一台虚拟机——工程文件是一份"程序"（里面没有一个采样），播放才是执行它；程序里只有两种数据（离散事件、连续采样），执行时沿一张有向图逐块求值。界面上的两百个功能，全是在往这三样东西上写东西。**

> **定位**：工具层·本质 + 手册。与 [[06_剪映精通教程-底层逻辑与操作细节]] 严格对称——那是画面侧的"引用 + 参数 + 图层"，本篇是声音侧的"程序 + 信号图 + 两种数据"。
> **读法**：§一~§七 是**本质**（为什么必须是这样，九个"玄学"在这里归零）；§九~§十六 是**手册**（查表用）。**本质没读通就翻手册，只会重新变成记菜单。**
> **环境实测**（2026-11-11）：Logic Pro 13.0（`/Applications/Logic Pro Creator Studio.app`，bundle id `com.apple.mobilelogic`）· Apple M5 / 16GB / 341GB 可用 · macOS 26.6.2 · 音色库**分两处**：本机 1.8GB（最小安装）+ 外接盘 62GB（完整），**Logic 当前只读本机那份** · 工程存于外接盘 `Logic_Projects`。

## 一、本质一：两期分离（一切"所见非所得"的根）

**工程文件里没有一个采样。** 它存的是一份程序：**何时、以什么参数、驱动哪个音源**。按播放，Logic 启动一个实时线程去执行它。

| 期 | 里面是什么 | 谁在跑 |
|---|---|---|
| **编辑期** | 位置（tick）、音符与自动化断点、插件状态快照、Region 对音频文件的引用 | 主线程，随便慢 |
| **运行期** | 每一块被求值出来的采样 | 实时线程，**必须有 deadline** |

所有"灵异现象"都能在这两期里归位：

| 现象 | 在两期里的真实位置 |
|---|---|
| 预览卡、导出正常 | 实时执行有 deadline，离线执行没有 |
| 导出比试听响 / 差一点 | Bounce 多了一步 Normalize（对输出再乘系数），不是混音变了 |
| 从中间起播，混响尾巴不对 | 运行期有**内部状态**（滤波器、混响的记忆），中途起播是从冷态开始 |
| 开 Low Latency Mode 音色变了 | 它不是"优化"，是**换了一份程序**——高延迟插件被旁通，不是被优化 |
| 同一工程换个插件顺序，导出结果不同 | 离线执行跑的是同一张图，但图变了（见 §五 Insert 不可交换） |
| Freeze 之后 CPU 掉一半 | 运行期不再求值这条轨 |

> [!important] 最有用的一句类比
> **Freeze = 编译成 object file（可还原）；Bounce = 链接出可执行文件（不可还原）。**
> 这解释了为什么 Freeze 能一键解冻而 Bounce 改不回来——**缓存可以丢，成品不能拆。**
> 也解释了为什么"定稿前别 Bounce"：那等于提前链接，之后所有调试都失去源码。

## 二、本质二：只有两种数据，一个转换点

| | 事件流（MIDI / 自动化） | 采样流（音频） |
|---|---|---|
| 形态 | 离散、稀疏、带时间戳 | 连续、密集、固定速率 |
| 分辨率 | tick（1/960 拍 ≈ 0.52 ms @120BPM） | 一个采样 20.8 µs @48kHz |
| 存哪 | 工程文件里（就是"程序"本身） | 音频文件 / 内存里的块 |
| 谁能改它 | 编辑器（Piano Roll、List、自动化） | 只能重采样（Flex）或重录 |

> [!important] 全文第二个关键句
> **音源（Software Instrument / Sampler / Drummer / Quick Sampler）是这台机器上唯一把事件变成采样的地方。**
> 它是整台 DAW 的中心转换点。记住这一句，下面五个问题同时解开。

| 问题 | 答案（都由"一个转换点"推出） |
|---|---|
| 改 BPM，为什么 MIDI 跟着走、音频不跟 | 事件的时间单位是 tick，换算是 BPM 的函数；音频已经烧成波形 |
| 为什么 MIDI 轨必须冻结 / 渲染才有音频 | 没有音源，就没有采样流 |
| 为什么 velocity 会改变音色 | 它是**事件**参数，音源按力度换采样层——它不是音量旋钮 |
| 为什么自动化能弯任何旋钮 | 自动化本身就是事件，活在 tick 网格上 |
| 为什么音频能剪得比 MIDI 细两个数量级 | 20.8 µs 对 0.52 ms |

## 三、本质三：五个位置（同一件事的五个落点）

新手把五个旋钮当成"一个问题的五种解法"。**它们不是五种解法，是信号链上的五个不同位置，语义完全不同。**

| # | 旋钮 | 站在哪 | 动的是什么 | 副作用 |
|---|---|---|---|---|
| 1 | **Velocity** | 事件层（音源**之前**） | 事件的力度参数 | **会改音色**（采样器换层） |
| 2 | **Region Gain / Fade** | 片段层（进链之前） | 素材幅度 | 不改音色、不改包络；Fade 会削瞬态 |
| 3 | **压缩 / Insert 内的 Gain** | 信号层（串联） | **动态关系**，不是电平 | 改变响度对比，不只是整体 |
| 4 | **Fader** | 通道出口 | 通道总幅度 | 影响 post-fader send 的量 |
| 5 | **Bus 压缩 / Master Limiter** | **求和之后** | 所有轨的总和 | 看不见单轨，只能救整体 |
| — | **Automation** | 不占位置，占**时间维** | 让上面任一个位置随时间变 | 不是第六个旋钮，是"函数" |

**判据（比记住五个名字重要）：先问"这个决定应该跟着谁走"？**

| 应该跟着 | 就放在 |
|---|---|
| **素材**（换工程也要带着） | Region Gain / Fade |
| **乐器**（换片段也该保留） | Insert / Fader / Track 自动化 |
| **整体**（所有轨一起） | Bus / Master |

> [!warning] 放错层 = 后面改不动
> 外层只能看见总和，看不见个体。所以"在 Stereo Out 上挂个限制器就以为母带做完了"必然失败；"在 Fader 上压下去的量，压缩器救不回来"。
> **这就是"问题要在出问题的轨道上修"的真正理由**——不是习惯，是拓扑。

## 四、本质四：功能不按菜单归类，按"你脑子里那句话"归类

**两百个功能不是两百件事，是六类动词的多种实现。** 在菜单里找功能永远找不到；说一句"我想让它\_\_\_"，立刻归位。

### A. 都想让"时间对上"

| 你脑子里的话 | 工具 | 它动的对象 |
|---|---|---|
| "这几颗音弹早了 / 晚了" | Quantize（强度 **70~85%**，别 100%） | **事件的时间戳** |
| "我想要那个鼓手 / 那首歌的律动" | Groove Track / Groove Template | **参考轨的偏移量**，不是网格 |
| "录音跟拍子不齐，但别改音高" | Flex Time | **音频的采样时刻**（切片 / 重采样） |
| "整个工程速度就不对，但音频得跟着变" | Smart Tempo | **速度函数本身**（Tempo Map） |

四个不同对象。**分不清就会拿 Quantize 去修一个本质是速度问题的工程**，然后越修越乱。

### B. 都想"再来一遍 / 拉长"

| 做法 | 数据有几份 | 改一处的后果 |
|---|---|---|
| 复制 `Cmd+D` | N 份，互相独立 | 只改一份 |
| 循环延展（拖 Region 右下角） | 1 份，被引用多次 | 改源 → 全部变 |
| **Region 别名（Alias）** | 1 份数据，多个引用 | **删源 → 全断** |

第三条是新手最常踩的"我以为只删了一个副本"。它和剪映的"复合片段"同族：**看起来是 N 个东西，其实是 1 个东西的 N 个视图。**

### C. 都想"分出空间感"

混响 / 延迟**必须** Send → Aux。表面理由是省 CPU，**真实理由是数学的**：Insert 是 100% 湿（干声被替换），Send 是抽一路出去、干声照旧走主路，湿声从 Aux 回来再相加。要"保留干声再加一点房间"，只能是并联。（细节见 [[02_声音与效果底层原理]] §二）

### D. 都想"把几轨并起来"

| 工具 | 信号真的汇到一起吗 | 什么时候用 |
|---|---|---|
| **Bus / Aux** | **是**（一个求和点） | 要"粘"在一起、要共享同一个效果 |
| **VCA** | 否，只远程控推子 | 要一起调音量，但不想要共同处理 |
| **Folder Stack** | 否，视觉分组 | 只想收起来不看 |
| **Track Stack（Summing）** | 是，本质就是个 Bus | 同上 |

**唯一判据：要不要真的把采样加在一起。** 这个"加"字决定了它能不能做并联压缩、能不能侧链。

### E. 都想"输出成音频"

| 做法 | 可逆吗 | 用途 |
|---|---|---|
| **Freeze** | 可逆（随时解冻回插件） | 只是想让 CPU 歇一下 |
| **Bounce in Place** | 半可逆（生成新轨，源轨留不留由你） | 这条轨定稿 |
| **Bounce / Export** | 不可逆 | 交付给别人 |

### F. 都想"对齐到画面"

SMPTE 那套坐标，跟音乐时间**是两套**。做配乐先把工程帧率设成成片帧率（25/30/60），否则对点会飘——与剪映"帧率开工就定死"是同一条纪律。

## 五、本质五：信号图（轨道列表不是信号流）

**轨道从上到下的顺序是视觉顺序，不是求值顺序。** 求值顺序由 Output / Send 决定——它是一张**有向图**，轨道列表只是这张图的一种渲染。

四条判据，全是图论：

| 判据 | 内容 | 能诊断什么 |
|---|---|---|
| **连通性** | 一个声音要被听见，必须存在一条通往 `Stereo Out` 的路径 | **90% 的"没声音"是路径断了**：Output 设成 No Output、Aux 忘了接 Output |
| **求和点** | Bus / Stereo Out 是入度为 n 的节点，运算是**相加** | 两条音轨同放是相加、不是覆盖（剪映那条"音频没有图层概念"是同一件事的音频侧表述） |
| **路径等长** | **PDC = 在每条路径上插延迟线，让所有路径总延迟相等** | 为什么录音监听时你的输入也被推后（它必须走同样对齐过的路径）→ Low Latency Mode / direct monitoring 才是解 |
| **禁止环** | 反馈环在实时图里只能"延迟一块"（这一块的输出不能在同块内喂回输入） | Bus 自环会晚一截；这也是模拟建模插件"过采样"要额外延迟的原因 |

**Insert 顺序不可交换**，因为压缩器、EQ、混响都是**有状态算子**：把 EQ 放到压缩之后，压缩器看到的信号分布已经变了，触发点和增益衰减全变。**视频里同一帧内的滤镜可以换序重算，音频不行**——见 §七。

## 六、本质六：时间有三个坐标系（外加一个速度函数）

| 坐标 | 单位 | 谁的分辨率 | 用在哪 |
|---|---|---|---|
| **音乐时间** | 小节 : 拍 : tick（**1 tick = 1/960 拍**；4/4 一小节 = 3840 tick） | 编辑分辨率 | 编曲、量化、和弦、循环 |
| **采样** | 20.8 µs @48 kHz | 数据分辨率 | 音频剪切、Flex |
| **绝对时间** | 时 : 分 : 秒 : 帧（SMPTE） | 交付分辨率 | 对画面、配乐、影视同步 |
| **Tempo Map** | BPM 作为时间的函数 | — | 变速、渐快、Smart Tempo |

```
采样位置 = tick × (60 / BPM) × 采样率 / 960
```

> [!important] 两个必须记住的推论
> **① 改 BPM：tick 不变、换算变了 → MIDI 自动跟着走；音频钉死在采样上 → 不跟**，必须 Flex Time / Smart Tempo。这不是 bug，是两层数据性质不同。
> **② tick 的物理长度随 BPM 变，采样的不变。** 一个 tick 在 120 BPM 是 0.52 ms，在 60 BPM 是 1.04 ms——**所以同一套量化设置在慢歌里更细、在快歌里更粗**。两套坐标不是简单换算，是"变速齿轮"。

## 七、音频和视频是**反**的（跨域对照）

这一节是把 [[06_剪映精通教程-底层逻辑与操作细节]] 和 [[音视频底层原理]] 接上的地方：

| 维度 | 视频 | 音频 |
|---|---|---|
| 基本单位 | 帧（40 ms @25fps） | 采样（20.8 µs），但**处理单位是块** |
| 层间关系 | **合成**：alpha 覆盖，上层盖住下层 | **求和**：相加，没有"盖住" |
| 能否跳着算 | 能，每帧独立、无状态 | **不能**，滤波器 / 压缩 / 混响都依赖之前的样本 |
| 瓶颈 | **带宽**（1080p60 未压缩 237 MB/s） | **延迟**（deadline 到就得交货） |
| 批大小 | GOP / tile | **I/O Buffer** |
| 顺序重要吗 | 图层顺序重要，同帧内可任意重算 | **Insert 顺序不可交换**：压缩后 EQ ≠ EQ 后压缩 |

> [!important] 最重要的一句
> **视频是"一堆互不相干的图"，音频是"一条有记忆的流"。**
> 所以视频可以跳到任意一帧开始渲染，音频不行——这解释了为什么从中间起播混响要暖机、为什么某些工具 Bounce 要先 pre-roll、为什么"导出和试听可能不一样"。

**带宽账**：48 kHz × 24 bit × 立体声 = 288 KB/s；100 轨 28.8 MB/s，相对 M5 的 153 GB/s 富余约 5000 倍。**音频不需要任何零拷贝优化，但必须为延迟做一切。**

## 八、实时性与性能边界（为什么"CPU 才 40% 也爆音"）

### 1. 音频线程就是一个周期性中断

声卡每 N 个采样向主机要一次数据 → 这一块（I/O Buffer）必须在下一次要数据前算完并交回。**算不完是爆音，不是变慢。**

| Buffer | 48 kHz 单程 | 场景 |
|---|---|---|
| 32 | 0.67 ms | 纯录音，插件极少 |
| 64 | 1.33 ms | 录音 |
| 128 | 2.67 ms | 编曲 |
| 256 | 5.33 ms | **混音（Air 甜点）** |
| 1024 | 21.3 ms | 放弃实时演奏 |

**单程不是实际延迟。** 真实演奏延迟 ≈ 输入缓冲 + 输出缓冲 + AD/DA + 插件延迟，128 常落到 8~15 ms；人耳可察觉阈值约 10 ms，超过会觉得"琴键发飘"。所以"16GB M5 不必为性能牺牲延迟"要加条件：**短时录音不必牺牲，长时间满载会因热降频自己变差。**

### 2. 三条推论（不用记，都能推）

- **缓冲越大能放越多插件**：N 越大唤醒越少、固定开销摊薄、缓存命中更好。同"DMA 一次搬一帧 vs 一字节一次中断"。
- **"CPU 才 40%" 基本是单核满**：EQ→压缩→混响有数据依赖，只能排在一条核上。M5 是 **4 超级核 + 6 能效核、无超线程** → 同时有信号的独立串行分支约 4 条，第 5 条开始排队。**轨道数 ≠ 线程数。**
- **PDC 是双向的**：它对齐各轨让它们同相，但录音监听时输入也被推后 → Low Latency Mode 或 direct monitoring。

### 3. 爆音三因诊断

| 判据 | 成因 | 处置 |
|---|---|---|
| **只在开工 15~25 分钟后出现**，重开工程能好一会儿 | Air 无风扇，持续负载降频 | 缓冲 128→256；Freeze 定稿轨；抬高机身 |
| 单个核顶到 100% | 串行链太重（长卷积混响、Alchemy） | 合并到 Bus；Space Designer 换 ChromaVerb |
| 内存压力**变黄 / 变红** | 采样库在换页 | 开磁盘流；精简模板；别挂 40 轨 |

## 九、开箱前必须处理的四件事

| 1 | **把外接盘的完整音色库接上** | 完整库在外接盘（62GB），Logic 只读本机 1.8GB。**不接上，六成乐器点开是空的**。见 9.1 |

### 9.1 音色库：完整版在外接盘，但 Logic 没在用它

| 项 | 外接盘 `Logic_Library/` | 本机 `~/Music/` | 倍数 |
|---|---|---|---|
| 总大小 | **62 GB** | 1.8 GB | 34× |
| Apple Loops | 6.8 GB / **16253** 个 | 421 MB / 1588 个 | 10× |
| Samples | 52 GB / **36721** 个 | 1.1 GB / 1635 个 | 22× |
| Patches 预设 | 1.1 GB / **6770** 个 | 289 MB / 1850 个 | 3.7× |
| Impulse Responses | 897 MB | 14 MB | 64× |

**根因**：Logic 只从 **`~/Music/Logic Pro Library.bundle`** 这一个固定路径读库。放到 `/Volumes/Logic_FCP/Logic_Library/` 不会自动生效——那里是"囤着"，不是"在用"。

#### 方案 A：符号链接（推荐）

```bash
mv ~/Music/"Logic Pro Library.bundle" ~/Music/"Logic Pro Library.bundle.mini.bak"
ln -s "/Volumes/Logic_FCP/Logic_Library/Logic Pro Library.bundle" ~/Music/"Logic Pro Library.bundle"
ls -l ~/Music/"Logic Pro Library.bundle"   # 应显示 -> /Volumes/Logic_FCP/...
```

完成后**退出并重开 Logic**，让它在 Unified Browser 里重建索引（首次几分钟）。

> 与官方 `Relocate Sound Library` 机制等价：官方也是"移动库 + 原位留符号链接"。手工做的区别只是"指向已有的库"而不是"再搬一次"。

| 代价 | 说明 | 应对 |
|---|---|---|
| 必须先挂盘 | 盘没挂载时链接悬空，工程报"找不到采样" | 工程本来就在外接盘，习惯已有 |
| 卷名不能变 | 挂成 `Logic_FCP 1` 时链接失效 | 不要在磁盘工具里改卷名 |
| 运行中别拔盘 | 会崩或索引损坏 | 退出 Logic 再推出磁盘 |
| 首次要重建索引 | 索引基于旧库 | Browser 里刷新，等它扫完 |
| 备份先别删 | `.mini.bak` 占 1.8GB | 跑通一周再删 |

#### 方案 B：搬回本机（不想依赖外接盘）

本机还有 339GB，62GB 放得下。用 `ditto` 合并而不是覆盖：

```bash
ditto "/Volumes/Logic_FCP/Logic_Library/Logic Pro Library.bundle" "$HOME/Music/Logic Pro Library.bundle"
```

代价是占 62GB 内置空间，换来"永远不用插盘"。**Logic 是主力工具的话，这个更省心。**

#### 方案 C：只把素材夹加进 Browser（补充，不替代 A/B）

13.0 的 Unified Browser 支持把任意文件夹加为搜索位置，可把 `/Volumes/Logic_FCP/Sono_Music` 加进去让自制素材与官方库同框搜索。**但它不能替代 A/B**——Loops / Patches / Samples 仍走 bundle 路径。

> **不要用 `Relocate Sound Library` 处理这个场景**：它是"把当前库移到新位置"，而当前库是 1.8GB 精简版，移过去会和已有的 62GB 冲突。

### 9.2 关于 13.0 的 AI 助手（Intelligent Assistant）

**现在用不了**，四个条件同时满足才行：Creator Studio 订阅 + Apple silicon + **macOS 27 或更高** + 英文环境。系统是 26.6.2，卡在第三条。

> 不要花时间找这个菜单——找不到是正常的。等系统升级后它会出现，且**它会改变学 Logic 的顺序**（部分编排变成对话），现在按手动路径学不影响任何基础能力。

## 十一、功能全景查表

> 这一节是**查表用**，不承担"本质"。找不到东西时按 §四 的六个动词先想一遍，再回来查。

### A. 音源（声音从哪来）

| 功能 | 是什么 | 什么时候学 |
|---|---|---|
| **Software Instrument 轨** | 虚拟乐器轨，接收 MIDI | **Day 1** |
| **Audio 轨** | 录真实声音 | **Day 1** |
| **Drummer** | 虚拟鼓手，选风格+复杂度自动生成 | **Day 1**（最快出成品） |
| **Apple Loops** | 现成乐句，拖入自动匹配 BPM 与调性 | **Day 1** |
| **Session Player** | 键盘/贝斯/鼓手"虚拟乐手"，懂和声进行 | Week 2 |
| **Quick Sampler** | 拖一个音频进去就变成可演奏乐器 | Week 3 |
| **Sampler (EXS24)** | 多层采样器，多音区与力度层 | 需要时 |
| **Alchemy** | 加法/波表/颗粒/采样，Logic 最强音源 | Month 2+ |
| **Retro Synths** | ES2 / Retro Synth / Sculpture | Month 2+ |

### B. 编排

| 功能 | 是什么 | 什么时候学 |
|---|---|---|
| **Region 编辑** | 切割、合并、循环、复制、量化 | **Day 1** |
| **Folder / Folder Stack** | 多轨装进文件夹轨（可折叠、可整体处理） | Week 2（超 10 轨必需） |
| **Arrangement Marker** | 给段落打标记（Intro/Verse/Chorus），可整体拖拽改结构 | Week 2 |
| **Chord Track** | 和弦轨：写进行，自动喂 Session Player 与 Chord Pad | Week 3 |
| **Live Loops** | 格子式现场演出/拼接 | 需要快速实验时 |
| **Tempo Track / Tempo Set** | 速度自动化，渐变、突变 | 影视配乐会用到 |
| **Transposition / Signature** | 全局移调、拍号变化 | 需要时 |

### C. MIDI 编辑

| 功能 | 是什么 | 什么时候学 |
|---|---|---|
| **Piano Roll** | 改音符音高/时值/力度 | **Day 1** |
| **Step Sequencer** | 步进音序器，做鼓组与节奏型最快 | Week 2 |
| **Drum Machine Designer** | 多个采样拼成一套鼓，配 Step Sequencer | Week 3 |
| **Score** | 五线谱视图 | 需要写谱时 |
| **Quantize / Groove Template** | 对齐到网格 / 借用某段录音的律动 | Week 2 |
| **Transform** | 批量变换 MIDI（移调、随机化、压缩力度） | 进阶 |
| **MIDI Draw** | 在钢琴卷帘里画控制器曲线（CC11 表情、CC1 调制） | Week 3 |

### D. 音频处理

| 功能 | 是什么 | 什么时候学 |
|---|---|---|
| **Flex Time** | 不改变音高的时间伸缩（修节奏） | Week 3 |
| **Flex Pitch** | 改音高（修音准） | Week 3 |
| **Stem Splitter** | 拆成人声/鼓/贝斯/其他（13.0 可再拆鼓组） | 需要采样或重混时 |
| **Audio File Editor** | 破坏性编辑（去杂音、剪开头、反转） | 需要时 |
| **Pitch Shifter / Varispeed** | 变调 / 变速 | 需要时 |
| **Bounce in Place** | 把一条轨"烤"成音频，释放 CPU | Week 2 |

### E. 效果器（按用途记，别按名字记）

| 类别 | 主力插件 | 解决什么 |
|---|---|---|
| **EQ** | Channel EQ / Linear Phase EQ | 给每个乐器分配频段，去掉不需要的低频 |
| **动态** | Compressor / Limiter / Multipressor / DeEsser | 控制起伏、让声音"实"、压齿音 |
| **混响** | ChromaVerb / Space Designer / PlatinumVerb | 造空间与远近（**放 Aux，用 Send 送**） |
| **延迟** | Stereo Delay / Tape Delay / Echo | 造宽度与重复 |
| **调制** | Chorus / Flanger / Phaser | 加宽、加动感 |
| **失真/箱模** | Overdrive / Amp Designer / Pedalboard | 吉他与"脏"音色 |
| **音高** | Pitch Correction / Vocal Transformer | 修音、变声 |
| **总线/母带** | Compressor / Limiter / Loudness Meter | 最后一步，做响做稳 |

> **学习顺序**：**EQ → Compressor → Reverb(Send) → Delay**，这四个覆盖 80%，其余等具体问题出现再学。

### F. 混音

| 功能 | 说明 | 什么时候学 |
|---|---|---|
| **Channel Strip** | 一条通道的完整链路（Insert → Send → Pan → Fader → Output） | Week 2 |
| **Bus / Aux** | 多条轨汇到一条统一处理 | Week 2 |
| **Send（Pre/Post Fader）** | 送多少去 Aux；Post 跟随推子，Pre 不跟随 | Week 3 |
| **Automation** | 参数随时间变化，5 种模式：Off / Read / Touch / Latch / Write | Week 3 |
| **VCA / Group** | 一个推子控一组轨（不汇信号） | 轨多时 |
| **Metering** | 峰值、响度（LUFS） | 导出前 |

| Automation 模式 | 行为 | 用在哪 |
|---|---|---|
| Off | 记录但不起作用 | 临时关掉 |
| **Read** | 播放已记录的自动化 | 日常 |
| **Touch** | 按下去才覆盖，松手恢复 | 微调 |
| **Latch** | 按下后一直保持新值 | 整体改 |
| **Write** | 一播放就覆盖（危险） | 精细重写 |

### G. 导出与交付

| 功能 | 用途 |
|---|---|
| **Bounce（File → Bounce → Project or Section）** | 导出成品：整工程 / 定位符区间 |
| **Export Selected Tracks** | 分轨导出（给混音师、给剪辑） |
| **Export All Tracks as Audio Files** | 一次导出所有轨 |
| **Project Alternatives** | 同一工程多版本，**不用复制文件** |
| **Import / Export XML（AAF/OMF）** | 与 Pro Tools / 剪辑软件交换 |

| 导出参数（配乐交付） | 值 | 理由 |
|---|---|---|
| 格式 | WAV / AIFF，**24-bit** | 视频后期要无损 |
| 采样率 | **48 kHz**（配视频）· 44.1 kHz（纯音乐） | 视频行业标准 48k |
| Normalize | **Off**（自己控电平） | 开它会改变你混好的动态 |
| Dither | 降到 16-bit 时才开 | 保持 24-bit 时关掉 |
| 范围 | 定位符区间 | 别把前后空白导进去 |

| 功能 | 说明 | 你要不要 |
|---|---|---|

## 十三、第一次上手：90 分钟跑通一首 30 秒

目标不是好听，是**打通全链路**：音源 → 编排 → 编辑 → 混音 → 导出。

| 步 | 动作 | 时间 |
|---|---|---|
| 1 | `File → New`（Empty Project，48k）→ 设 BPM 与调号 | 3 min |
| 2 | 加 **Drummer 轨**：选风格，复杂度/响度拉到中等 | 10 min |
| 3 | 加 **Software Instrument 轨**，选 Pad 或 Piano | 5 min |
| 4 | `Cmd+K`，用铅笔（`T`）画 4–8 小节和弦（每小节一个音也行） | 15 min |
| 5 | `Y` 搜 Apple Loops 里的 Bass 拖进来（自动跟 BPM 与调） | 10 min |
| 6 | 循环播放，听三个层是否各在各的位置（低/中/高频别打架） | 10 min |
| 7 | 建 Aux 混响：某轨 Send 拧到 −12 dB 左右，听"远近"变化 | 10 min |
| 8 | 拉 Locator 定义 8 小节 → Bounce → 24-bit WAV | 10 min |
| 9 | 导出后**用手机外放听一遍**——最有效的审美检查 | 5 min |

> **硬判据：第一次做超过 2 小时，说明在翻菜单而不是在做事。**

## 十四、路径：按六个动词走，六周

| 周 | 只练这一类动词 | 判据（达到就往下走） |
|---|---|---|
| 1 | **出声音**（音源、Region、导出） | 30 秒能从头到尾出一条，每天一条不管好坏 |
| 2 | **对上**（Quantize 强度、Groove、循环/别名） | 能说出你改的是四个对象里的哪一个 |
| 3 | **变大变小**（五个位置的取舍） | 不看教程能选对位置 |
| 4 | **分出空间**（Send→Aux、Pan、EQ 分频） | 混响不再挂在 Insert 上；声音有前后 |
| 5 | **并起来**（Bus 压缩、VCA、Folder Stack） | 能解释 Bus 与 VCA 的区别 |
| 6 | **交出去**（Bounce、分轨、LUFS） | 导出两条不同用途的文件 |

**每周检验**：把成品给一个不听这类音乐的人，问"哪一段让你想跳过"。**记原话，不要记"挺好"。**

> [!note] 本节管"会用软件"，不管"练成技能"
> 六周练的是六个动词，产出的是操作熟练度。**要练键盘手与编曲能力，走 [[07_Logic 十二周实操路线]]**——那篇才是主线，本篇是它的工具箱。两者可并行，别混读。

## 十五、不要碰 / 常见问题

### 15.1 现在不要碰（防掉坑）

| 不要碰 | 为什么 |
|---|---|
| Alchemy / Sculpture / 复杂合成器 | 音色设计是 Month 2 的事，先用预设 |
| 母带链（多段压缩 + 立体声增强） | 先把平衡做对，做响最后 |
| 上百轨的模板 | 5–10 轨足够练判断力 |
| 第三方插件（Waves / FabFilter） | 自带插件够用，买插件常是逃避学习 |
| 抄"专业工程模板" | 别人的总线设置对你不成立，音源与审美都不同 |
| 追求"录音棚级"监听 | 16GB M5 + 一副 300 元以上的封闭耳机，够练到"能交付" |

### 15.2 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 点乐器没声音 | 链接悬空 / 库没接上 / **Output 没路径**（§五连通性） | 先 `ls -l ~/Music/"Logic Pro Library.bundle"`；再查 Output 是否 No Output |
| 播放爆音卡顿 | Buffer 太小 / 单核满 / 热降频 | §八 三因诊断 |
| 拖 Loop 进去速度被改 | 工程 BPM 被 Loop 改了 | 关 Smart Tempo 自动改速，或先锁 BPM |
| 找不到 Loop Browser | 13.0 已并入 Unified Browser | 按 `Y` |
| 导出比工程里小 | Normalize 关 + 主输出没加 Limiter | 主输出加 Limiter，看 LUFS |
| 导出比试听"糊"/相位薄 | 插件离线渲染或 PDC 差异 | 把问题插件 Bounce in Place 后对比 |
| 从中间播放混响不对 | 运行期有状态，冷启动 | 正常现象，回退几秒再播（§一） |
| 录音监听有延迟、越录越飘 | PDC 把输入也推后了 | Low Latency Mode 或声卡 direct monitoring（§五） |
| 工程打不开 / 文件损坏 | 放在 iCloud 或同步盘 | 移回本地 |
| 快捷键和教程不一样 | 教程是旧版或键位不同 | `Option+K` 自查 |
