# 创作 · 索引

> [!info] 本区定位
> **从"想做出东西"出发的探索与实践。** 摄影 / 剪辑 / 音乐制作三条域平行，共享同一套底层；**作品是跨域的**（一首歌的 MV 同时是三者），所以作品与复盘不能塞进任何一个域里，只能独立放在外层。
> 一句话结构：**三域往里收，作品往外放，复盘往上长。**

## 为什么是这五个位置

| 位置 | 放什么 | 什么才算该进来 |
| --- | --- | --- |
| `1_音乐制作` | 编曲、DAW、混音、AI 生成、词曲 | 下一步动作是"做一首歌" |
| `2_剪辑` | 时间线、节奏、图层、编码导出、成片 | 下一步动作是"出一条片" |
| `3_摄影` | 拍摄、曝光、构图、光线、器材 | 下一步动作是"拍到一个画面" |
| `4_作品` | 一次创作的完整档案（词/工程/导出/封面） | **有交付物**才进来；想法不进 |
| `5_复盘与感悟` | 做完之后的判断、改判、审美变化 | 每次做完写一条，**不写"下次一定"** |

> [!important] 归属判据：看"下一步动作"，不看主题词
> - 同一篇"音视频原理"，拿去面试 → 留 [[00_开发技能MOC]]；拿去做片 → 进本区。所以 [[音视频底层原理]] **仍留在开发技能**（求职主线，Linux 音视频栈）。
> - 反过来 [[01_Logic Pro 本质模型与功能全图]] 虽是技术原理，但下一步是"做歌"，所以在这里。
> - 基础学科不迁：[[乐理]] 留在 [[00_阅读与艺术MOC]]——它服务于"听懂"，不是"做出来"。

## 四、作品

**一次创作一个文件夹**，命名 `年份-作品名`（例：`2026-逆流河`）。文件夹内固定四样：`词.md`、工程文件、导出成品、封面。
新建时复制 [[_作品模板]]，`type: 作品`，把 `作品名 / 类型 / 状态 / 完成日` 填进 frontmatter——下表自动收它。

```dataview
TABLE WITHOUT ID file.link AS 作品, 类型, 状态, 完成日
FROM "10.创作/4_作品"
WHERE type = "作品" AND !startswith(file.name, "_")
SORT 完成日 DESC
```

## 五、复盘与感悟

**只写三件事**：这次哪个判断是对的、哪个是错的、下次怎么改。
不写"下次一定努力"——那是情绪，不是判断。

```dataview
TABLE WITHOUT ID file.link AS 复盘, 对应作品, created AS 日期
FROM "10.创作/5_复盘与感悟"
WHERE type = "复盘" AND !startswith(file.name, "_")
SORT created DESC
```
