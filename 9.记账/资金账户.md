# 资金账户

> [!info] 这一页只放两个数字
> `initial_cash` = 期初净资产，`initial_date` = 期初日期。[[00_记账仪表盘]] 靠这两个数算净资产曲线。
> 只在新账期里**手动对账**时才改，日常记流水不要动这里。

## 1. 期初快照（2026-10-20）

| 账户 | 余额 |
|---|---|
| 余额宝 | 30,000 |
| 银行卡 | 3,000 |
| **合计** | **33,000** |

前提条件（用户确认）：

- 已收到 10/20 工资 9,990
- 已结清京东白条、花呗（**历史账不追溯**，从现在起干净起步）
- **房租已付**，走银行卡
- 因此 **33,000 = 干净起点**：工资和房租都不能再进流水

> [!warning] 首期有两个数不能入流水
> 1. **10/20 工资 9,990**：已含在 33,000 里，再记一次净资产虚高 9,990。
> 2. **10/20 付的房租 1,680**：付款发生在期初资金之前，已从 33,000 里扣掉了。再记一次净资产虚低 1,680。
>
> 判断标准：**这笔钱是在 33,000 之前花的，还是在之后花的。** 之前的都不记。

## 1.1 账期边界规则（首期之后怎么处理）

每个发薪日，你的固定动作是：**结清白条/花呗 → 付下月房租 → 领工资 → 开新账期**。这三件事都发生在「新账期开始」之前，按说都不该进流水。但有个问题：

> 房租让现金 −1,680，工资让现金 +9,990。如果两笔都不记，净资产公式从第二个账期起就会失真 8,310 元。

所以从**第二个账期（2026-11-20）开始**，把这两笔**倒记在账期第一天**：

```
2026-11-20,收入,工资,9990,银行卡,,11月工资
2026-11-20,固定,房租,1680,银行卡,,预付12月房租
```

| 账期 | 工资 | 房租 | 处理 |
|---|---|---|---|
| 2026-10-20（首期） | 不记 | 不记 | 都已在期初 33,000 里 |
| 2026-11-20 起 | 记 `收入` | 记 `固定/房租` | 日期都写发薪日当天 |

这样净资产链条才连续：`上期期末 − 房租 + 工资 = 本期期初`。看板会自动识别首期（账期起点 = 期初日期），把首期预算里的 1,680 扣掉，不需要你手动改参数。


## 2. 净资产口径

```
净资产 = initial_cash + Σ全部收入 − Σ全部支出
```

三条规则决定了这个式子成立：

1. **还款不进支出**。还花呗/白条只是「现金变少、负债也变少」，净资产不变。记成 `类型=还款` 后，看板会把它整个排除在统计之外。
2. **消费发生时就记**，哪怕付的是花呗。因为那一刻负债已经产生，净资产确实减少了。
3. **转账不算收支**。余额宝转银行卡记 `类型=还款`（内部调拨），不要记成收入或支出。

按这个口径，你的净资产永远等于「真正属于你的钱」，与手上有多少现金无关。

## 3. 对账方式

每月 20 号结清之后，做一次 30 秒核对：

1. 打开余额宝 + 银行卡，看实际总额
2. 对比看板上的「当前净资产」预估
3. 差额超过 200 元就说明有漏记，检查当月的现金支出（小额现金最容易漏）

对完账后，把 `initial_cash` 改成实际总额、`initial_date` 改成当天，即可重置基线——**但只在差额确实无法追查时才这么做**，否则会掩盖漏记问题。

## 4. 首月观察项

- 历史账不追溯，从 2026-10-20 干净起步。上月白条+花呗结清 3,000 元以上这个量级只当背景信息，不再拆解。
- **本账期真正的目标是「记录完整度」**，不是数字准确。第一个完整账期能坚持逐笔记，比月底对账差 50 块重要得多。
- 若新账期内连续两个月信用账单都超过 2,000，说明固定项之外存在稳定的第二消费层，那时再单独立项。
