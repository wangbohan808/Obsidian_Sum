# 10 猫咪监控项目：AI 行为识别与事件录制

> 目标：实现"只在猫咪进食/饮水时录像；仅仅是停留/路过不录"，且能区分进食与饮水。
> 前置：文档 09 的采集链路已跑通；PC 端已装好 RKNN-Toolkit2（文档 05）。

---

## 1. 算法方案总览

```text
每帧（如 10fps 抽帧）
   │
   ├─ 1. 运动门控（帧差，CPU，<1ms）────────── 无运动 → 跳过 NPU，回到空闲
   │        有运动
   ▼
   ├─ 2. 猫咪检测（YOLOv8n 单类 cat，RKNN INT8，640x640）
   │        检测到猫 → 得到猫框 bbox + 置信度
   ▼
   ├─ 3. 头部定位（YOLOv8n-pose 头部关键点；或 bbox 上部区域近似）
   ▼
   ├─ 4. 行为判定（规则为主）：
   │        head_point 落入 碗区ROI  → 候选"进食"
   │        head_point 落入 水区ROI  → 候选"饮水"
   │        都不在 → "停留/其他"
   ▼
   ├─ 5. 时序状态机（迟滞 + 连续帧确认）→ 输出事件：
   │        IDLE → CANDIDATE → ACTIVE(eat/drink) → COOLDOWN → IDLE
   ▼
   └─ 6. 录制控制：ACTIVE 期间启动/继续 GStreamer 硬编码写盘
```

### 为什么用"检测 + 头部位置规则"而不是"端到端行为分类器"？

1. **可解释**：规则看得见、调得动（ROI 画框即可标定），排查误报快。
2. **样本少也能跑**：行为分类需要大量"进食/饮水/停留"标注视频；头部位置规则只需标定两个 ROI。
3. **可扩展**：之后若想加"吃了几口/喝了几口"，关键点轨迹本身就是输入。
4. 可选增强：用一个小型分类器（MobileNetV3-Small）对"猫头+碗"裁剪图做二分类兜底，两路结果加权。

### 6.2 主推理循环（Python 原型）

```python
# app/ai_engine.py —— 单帧推理封装
import cv2
import numpy as np
from rknnlite.api import RKNNLite

CLASSES = ['cat']

class CatEngine:
    def __init__(self, det_path, cls_path=None, input_size=640):
        self.det = RKNNLite()
        self.det.load_rknn(det_path)
        self.det.init_runtime(core_mask=RKNNLite.NPU_CORE_AUTO)  # 3 核自动调度
        self.cls = None
        if cls_path:
            self.cls = RKNNLite()
            self.cls.load_rknn(cls_path)
            self.cls.init_runtime(core_mask=RKNNLite.NPU_CORE_0)
        self.input_size = input_size

    def letterbox(self, img):
        h, w = img.shape[:2]
        r = self.input_size / max(h, w)
        nh, nw = round(h * r), round(w * r)
        resized = cv2.resize(img, (nw, nh), interpolation=cv2.INTER_LINEAR)
        canvas = np.full((self.input_size, self.input_size, 3), 114, np.uint8)
        top, left = (self.input_size - nh) // 2, (self.input_size - nw) // 2
        canvas[top:top+nh, left:left+nw] = resized
        return canvas, r, top, left

    def detect(self, bgr):
        boxed, r, top, left = self.letterbox(bgr)
        rgb = cv2.cvtColor(boxed, cv2.COLOR_BGR2RGB)
        outs = self.det.inference(inputs=[rgb])
        # 解析 YOLOv8 输出：[1, 84, 8400] -> boxes + scores（以 convert.py 输出结构为准）
        boxes = self._postprocess(outs[0], r, top, left)
        return boxes  # [{xyxy, conf, cls}]

    def _postprocess(self, output, r, top, left):
        # 简化版：输出形状 [1, 4+1+nc, 8400]
        pred = output[0]  # (85, 8400)
        conf = pred[4:5].max(0)
        mask = conf > 0.35
        if not mask.any():
            return []
        pred = pred[:, mask]
        conf = conf[mask]
        cls = pred[5:].argmax(0)
        cx, cy, w, h = pred[0], pred[1], pred[2], pred[3]
        boxes = []
        for i in range(len(conf)):
            if conf[i] < 0.35 or CLASSES[int(cls[i])] != 'cat':
                continue
            x1 = (cx[i] - w[i] / 2 - left) / r
            y1 = (cy[i] - h[i] / 2 - top) / r
            x2 = (cx[i] + w[i] / 2 - left) / r
            y2 = (cy[i] + h[i] / 2 - top) / r
            boxes.append({'xyxy': [x1, y1, x2, y2], 'conf': float(conf[i])})
        return boxes

    def release(self):
        self.det.release()
        if self.cls:
            self.cls.release()
```

> 说明：YOLOv8 后处理（NMS）也可在 NPU 上用 RKNN 的 `RKNN_OP_NMS` 内置算子完成；原型阶段在 Python 做即可。正式版建议移植官方 `rknn_yolov8_demo` 的 C 后处理（`rknpu2/examples/`），性能更好。

## 7. 事件状态机与录制控制

### 7.1 状态定义

```text
IDLE ──(检测到猫，且头部在任一 ROI 附近)──▶ CANDIDATE
CANDIDATE ──(连续 candidate_frames 帧保持)──▶ ACTIVE
CANDIDATE ──(头部离开 ROI 或猫消失)──▶ IDLE
ACTIVE ──(连续 exit_frames 帧不在 ROI)──▶ COOLDOWN（或直接 IDLE）
COOLDOWN ──(post_record_s 秒后)──▶ IDLE
ACTIVE 期间：头部在 food ROI → 标签 eat；water ROI → drink；标签变化 → 新片段
```

关键点：

- **迟滞（hysteresis）**：进入 ACTIVE 需要连续 N 帧，退出需要连续 M 帧（M>N），避免猫抬头/低头瞬间反复触发。
- **预录**：事件开始前 6 秒的画面保留在环形缓冲区（GStreamer `shmsink` + 双端队列，或应用层保留最近 6 秒编码流）。
- **最长时长**：`max_record_s` 兜底，防止传感器误判导致无限录制。
- **冷却**：事件结束后 1~2 秒内不重新触发，避免"喝一口水就停"的碎片。

### 7.2 状态机实现（Python 原型）

```python
# app/event_state.py
class EventStateMachine:
    def __init__(self, cfg):
        self.cfg = cfg
        self.state = 'IDLE'
        self.label = None
        self.candidate_cnt = 0
        self.exit_cnt = 0
        self.event_start = None
        self.record_until = None

    def inside(self, pt, roi):
        dx, dy = pt[0] - roi['x'], pt[1] - roi['y']
        return dx * dx + dy * dy <= (roi['r'] * roi['r'])

    def step(self, head_pt, now_ts):
        cfg = self.cfg['decision']
        label = None
        if head_pt:
            if self.inside(head_pt, self.cfg['roi']['food']):
                label = 'eat'
            elif self.inside(head_pt, self.cfg['roi']['water']):
                label = 'drink'

        if self.state == 'IDLE':
            if label:
                self.candidate_cnt += 1
                if self.candidate_cnt >= cfg['candidate_frames']:
                    self.state = 'ACTIVE'
                    self.event_start = now_ts
                    self.candidate_cnt = 0
                    print(f"[EVENT] START {label}")
            else:
                self.candidate_cnt = 0

        elif self.state == 'ACTIVE':
            if label:
                self.exit_cnt = 0
                self.label = label          # 支持 eat→drink 切换，切标签时由上层另存新文件
            else:
                self.exit_cnt += 1
                if self.exit_cnt >= cfg['exit_frames']:
                    self.state = 'COOLDOWN'
                    self.record_until = now_ts + cfg['post_record_s']
                    print(f"[EVENT] END {self.label}")

        elif self.state == 'COOLDOWN':
            if now_ts >= self.record_until:
                self.state = 'IDLE'
                self.event_start = None

        return self.state, self.label
```

### 7.3 录制控制（与 GStreamer 对接）

主循环伪代码：

```python
# app/main_loop.py
while True:
    frame = get_frame_from_camera()          # 视频帧
    motion = motion_gate(frame)              # 帧差门控
    if motion:
        boxes = engine.detect(frame)         # NPU 推理
        head = head_point(boxes[0]) if boxes else None
    state, label = fsm.step(head, time.time())

    if state == 'ACTIVE':
        if recorder is None:
            recorder = start_gst_recorder(label)   # 启动 mpph264enc 管线
        recorder.write(frame)                      # 写入编码器
    elif state == 'COOLDOWN':
        if recorder: recorder.write(frame)         # 事件尾段继续录
    else:
        if recorder:
            recorder.stop()                        # 收尾、命名、入上传队列
            recorder = None
```

录制实现建议（两种）：

**方式一：GStreamer appsink 拿帧 + 应用内维护环形缓冲**

```python
import subprocess

GST = (
    "v4l2src device=/dev/video0 ! "
    "video/x-raw,width=1280,height=720,framerate=15/1,format=YUY2 ! "
    "videoconvert ! video/x-raw,format=I420 ! "
    "mpph264enc bps=2000000 bps-max=3000000 rc-mode=vbr ! h264parse ! mp4mux ! "
    "filesink location={path}"
)

def start_gst_recorder(path):
    return subprocess.Popen(
        ["gst-launch-1.0", "-e", *GST.format(path=path).split()],
        stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
```

**方式二（推荐正式版）：纯 GStreamer 应用（Python gi 或 C）**

在应用内建 `v4l2src → tee`，一路 `appsink` 给 AI，一路 `queue → mpph264enc → splitmuxsink`，用 pad 事件或 `appsink` 控制录制启停；预录用 `queue max-size-time=6` 天然实现。

```python
import gi
gi.require_version('Gst', '1.0')
from gi.repository import Gst, GLib

Gst.init(None)

def build_recorder():
    pipeline = Gst.parse_launch(
        "v4l2src device=/dev/video0 ! "
        "video/x-raw,width=1280,height=720,framerate=15/1,format=YUY2 ! "
        "tee name=t "
        "t. ! queue max-size-buffers=1 ! videoconvert ! appsink name=ai_sink "
        "t. ! queue max-size-time=6000000000 ! videoconvert ! "
        "video/x-raw,format=I420 ! mpph264enc ! h264parse ! "
        "splitmuxsink name=mux max-size-time=300000000000 location=/data/videos/%Y-%m-%d/%04d.mp4"
    )
    return pipeline
```

> `splitmuxsink` 每 5 分钟自动切文件；文件名模板用 `%Y-%m-%d` 会自动按日期建目录（mux 支持 strftime）。

## 8. 误报压制策略（重要）

| 误报场景 | 压制手段 |
| --- | --- |
| 猫只是蹲在碗边睡觉 | 头部位置在 ROI 内 + 连续帧计数 + **运动幅度**（帧差能量需 > 阈值） |
| 手/玩具伸进 ROI | 检测器只认"猫"类；可加"人脸/人手"负类或在 ROI 加禁区 |
| 猫喝水抬头又低头 | 迟滞（exit_frames 大）+ COOLDOWN 防止碎片 |
| 夜间红外闪烁 | 固定曝光增益；降低检测阈值波动（用长期均值自适应） |
| 猫走过 ROI 一帧 | 连续 candidate_frames 才进 ACTIVE |

运动幅度计算（简单有效）：

```python
def motion_energy(gray_prev, gray_cur):
    diff = cv2.absdiff(gray_prev, gray_cur)
    return float((diff > 25).mean())
# 阈值：0.002~0.01 视场景而定；只用于门控，不用来判定行为
```

## 10. 常见问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 推理很慢（>200ms） | 用了 CPU 而非 NPU | 确认 rknn-toolkit-lite2 与 `/dev/rknpu`；`core_mask=NPU_CORE_AUTO` |
| 检测不到猫 | 模型没微调/阈值太高 | 降到 0.25 试；补夜晚数据重训练 |
| 一直触发录制 | ROI 太大/门控失效 | 缩小 ROI；检查运动能量阈值 |
| 视频文件损坏 | 进程被 kill / splitmux 未收尾 | 用 `-e` 收尾；systemd `KillMode=control-group`；或加 mp4 修复脚本 |
| 高帧率推理跟不上 | 10fps 抽帧即可 | 把推理帧率与录制帧率解耦（AI 10fps，录制 15fps） |
