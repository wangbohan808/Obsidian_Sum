# 第一部分：生态系统全景概述

## 1.1 四个项目的关系与定位

Radxa（瑞莎）的 BSP 开发生态系统由四个紧密协作的项目组成，覆盖从底层固件到上层操作系统镜像的完整构建链路：

                               ▲

│                     rsdk (RadxaOS SDK)                           │

│   • 根文件系统生成 (mmdebstrap)                                   │
│   • 磁盘镜像创建 (libguestfs/guestfish)                           │
│   • Bootloader 安装                                              │
│   • CI/CD 基础设施自动化                                          │
│   • 产品数据库 (products.json)                                    │

                               ▲ 消费 .deb 包

## 1.2 硬件架构基础：RK3588 SoC

RK3588 是 Rockchip 的旗舰 8nm 制程 SoC：

```
RK3588 内部架构:
┌─────────────────────────────────────────────────────┐
│  CPU Cluster 0: 4× Cortex-A76 @ 2.4GHz             │
│  CPU Cluster 1: 4× Cortex-A55 @ 1.8GHz             │
├─────────────────────────────────────────────────────┤
│  GPU: Arm Mali-G610 MP4 (Valhall架构)               │
│  NPU: 6 TOPS 独立神经网络处理器 (3核)               │
│  VPU: 8K@60fps 解码 + 8K@30fps 编码                │
│  ISP: 48MP 图像信号处理器                           │
│  RGA: 2D 图形加速引擎                               │
├─────────────────────────────────────────────────────┤
│  存储: eMMC 5.1, SD 3.0, SATA 3.0, PCIe 3.0×4     │
│  显示: 双HDMI 2.1 (8K), DP 1.4, MIPI DSI, eDP      │
│  网络: 双千兆以太网                                  │
│  接口: USB 3.1×2, PCIe 3.0, CAN, I2C, SPI, UART   │
└─────────────────────────────────────────────────────┘
```

### 🔑 rk3588.inc 关键内容

```bitbake
# 文件: meta-rockchip/conf/machine/include/rk3588.inc
MACHINEOVERRIDES =. "rk3588:"
SOC_FAMILY = "rk3588"
require conf/machine/include/rockchip-arm64-common.inc
require conf/machine/include/mali.inc

# GPU配置
MALI_GPU = "valhall-g610"        # Mali GPU型号
MALI_VERSION = "g13p0"           # Mali驱动版本
MALI_PLATFORM = "${@...}"        # 自动检测wayland/x11

# 摄像头ISP配置
RK_ISP_VERSION = "3.0"           # ISP v3.0 (RK3588专属)

# 默认内核版本
PREFERRED_VERSION_linux-rockchip ??= "6.1%"
```

## 2.4 机器配置模板 (machine/*.conf)

**🔑 文件**: `meta-rockchip/conf/machine/rockchip-rk3588s-rock-5c.conf`

每个板卡配置文件只需三要素：

```bitbake
# 1. 继承SoC家族配置
require conf/machine/include/rk3588.inc

# 2. 内核设备树 (DTS → DTB)
KERNEL_DEVICETREE = "rockchip/rk3588s-rock-5c.dtb"

# 3. U-Boot defconfig
UBOOT_MACHINE = "rk3588_defconfig"

# 4. WiFi/BT固件 (可选)
RK_WIFIBT_RRECOMMENDS = " \
    rkwifibt-firmware-ap6275p-wifi \
    rkwifibt-firmware-ap6275p-bt \
"
```

**当前支持的33个板卡**包括：ROCK 5A/5B/5B+/5C/5D/5ITX/5T, CM5/NX5/E52C/E54C 及 EVB 各版本。

## 3.4 🔑 板级 Defconfig 详解

RK_KERNEL_DTS_NAME="rk3588-rock-5b"

其他配置通过 Kconfig 默认值自动推导：

    │   ├── mk-misc.sh     → misc.img
    │   ├── mk-loader.sh   → U-Boot + rkbin打包

### 6.4.2 I2C 设备驱动示例

```c
// drivers/iio/light/my_light_sensor.c

#include <linux/module.h>
#include <linux/i2c.h>
#include <linux/iio/iio.h>
#include <linux/of.h>

struct my_light_data {
    struct i2c_client *client;
    struct mutex lock;
};

static int my_light_probe(struct i2c_client *client)
{
    struct my_light_data *data;
    struct iio_dev *indio_dev;

    indio_dev = devm_iio_device_alloc(&client->dev, sizeof(*data));
    if (!indio_dev)
        return -ENOMEM;

    data = iio_priv(indio_dev);
    data->client = client;
    mutex_init(&data->lock);

    // 验证芯片ID
    int ret = i2c_smbus_read_byte_data(client, 0x00);
    if (ret < 0 || ret != 0xAB) {
        dev_err(&client->dev, "Invalid chip ID: 0x%02x\n", ret);
        return -ENODEV;
    }

    return devm_iio_device_register(&client->dev, indio_dev);
}

static const struct of_device_id my_light_of_match[] = {
    { .compatible = "myvendor,my-light-sensor" },
    { }
};
MODULE_DEVICE_TABLE(of, my_light_of_match);

static struct i2c_driver my_light_driver = {
    .driver = {
        .name = "my_light_sensor",
        .of_match_table = my_light_of_match,
    },
    .probe = my_light_probe,
};
module_i2c_driver(my_light_driver);

MODULE_AUTHOR("BSP Engineer");
MODULE_DESCRIPTION("My Light Sensor Driver");
MODULE_LICENSE("GPL");
```

## 8.3 场景三：调试启动问题

```
问题: 新板卡上电后无串口输出

排查流程:

1. 检查电源
   - 测量各电源轨电压 (VCC_DDR, VCC_IO, VCC_CORE等)
   - 验证上电时序 (PMIC是否正常工作)

2. 检查时钟
   - 24MHz 晶振是否起振
   - 示波器测量

3. 检查复位
   - nPOR/nRST 电平是否正常
   - 复位时序

4. 检查烧录连接
   - USB线是否支持数据传输 (非仅充电线)
   - Maskrom模式是否进入: lsusb | grep 2207

5. 检查 DDR 配置
   - DDR bin 文件是否正确
   - DDR 频率是否在规格内

6. 串口配置
   - UART2 (默认调试串口)
   - 波特率 1500000 (RK3588)
   - TTL电平 3.3V

7. 分析启动日志
   - SPL阶段输出
   - ATF阶段输出
   - U-Boot启动信息
   - 内核启动信息

常用调试命令:
  # 进入 Maskrom 模式
  rkdeveloptool ld    # 列出设备
  rkdeveloptool db rk3588_spl_loader_v1.18.bin  # 下载 MiniLoader

  # 擦除 eMMC
  rkdeveloptool ef

  # 烧录镜像
  upgrade_tool uf update.img
```
