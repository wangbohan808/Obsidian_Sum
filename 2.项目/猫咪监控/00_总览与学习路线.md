# ROCK 5C 镜像构建全攻略 —— 总览与学习路线

> 适用对象：需要在 Radxa ROCK 5C（RK3588S）上构建自己的 Linux 发行版，只包含自己需要的驱动，并集成端侧 AI（RKNN / RKLLM）部署能力的开发者。
>
> 本套文档基于 Radxa 官方文档（docs.radxa.com/rock5/rock5c）以及本机已下载的四个 SDK 整理而成，所有命令均可直接在本机执行。

## 1. 你要学习的四种镜像构建方式

本机已经下载并（部分）构建过以下四个 SDK：

| 构建方式 | 本地目录 | 官方文档位置 | 主要产出 | 构建原理一句话 |
| --- | --- | --- | --- | --- |
| BSP（u-boot / kernel 开发） | `/home/wbh808/bsp` | 底层开发 → U-boot / Kernel 开发 | u-boot、linux-image 的 **deb 包** | 用容器 + profile 配置统一拉取源码、打补丁、交叉编译并打包成 Debian 软件包 |
| Yocto | `/home/wbh808/yocto-rockchip-sdk` | 其他系统 → Yocto | `core-image-*.rootfs.update.img` / `.wic` | OpenEmbedded/BitBake 按 recipe 从源码构建整个发行版（内核、rootfs、bootloader 全流程） |
| Buildroot（rk3588_sdk） | `/home/wbh808/rk3588_sdk` | 其他系统 → Buildroot | `rockdev/update.img`（RK 格式整包） | Rockchip 官方 Linux SDK：顶层脚本编排 u-boot、kernel、buildroot rootfs、recovery，一次生成整包镜像 |
| rsdk（编译 RadxaOS） | `/home/wbh808/rsdk` | 底层开发 → 编译 RadxaOS | `out/<产品>_<套件>_<版本>/output.img` | mmdebstrap/bdebstrap 基于 Debian 软件源直接组装 rootfs，jsonnet 模板控制包与定制脚本，guestfish 生成磁盘镜像 |

它们的关系可以这样理解：

```text
                          ┌──────────────────────────────────────┐
                          │  你自己的 Linux 发行版（最终目标）    │
                          └──────────────────────────────────────┘
                                            │
             ┌──────────────────────────────┼──────────────────────────────┐
             │                              │                              │
       硬件层（Bootloader + Kernel）   根文件系统 A（Debian 系）      根文件系统 B（嵌入/极简）
             │                              │                              │
        BSP 工具构建 u-boot/kernel     rsdk（RadxaOS）              Buildroot / Yocto
        （deb 包，可被 rsdk 使用）        （apt 组装，易装 AI 包）       （源码级构建，体积最小/最可控）
```

## 2. 四条路线的原理差异（必须先理解）

### 2.1 BSP：只管"引导 + 内核"，输出 deb 包

- `bsp` 是 Radxa 维护的构建工具，内部用 Podman/Docker 容器提供交叉编译环境，避免污染宿主机。
- 它按 **profile**（如 `rk2410`）和 **product**（如 `rock-5c`）组织构建配置：每个 profile 下有 `fork.conf`（仓库地址、分支、产品列表）、`kconfig.conf`（内核配置）、以及若干补丁目录。
- 源码放在 `.src/`（u-boot、linux、rkbin、arm-trusted-firmware、radxa-overlays）。
- 产物是 **arm64 的 Debian 包**（`u-boot-rk2410_2017.09-999_arm64.deb`、`linux-image-*.deb`），可以直接 `dpkg -i` 安装到任意 Debian 系系统（包括 RadxaOS），也可以被 rsdk 通过 `--debs` 集成进新镜像。
- 这是"定制驱动"最关键的一层：改内核配置、加驱动、改设备树都在这一层完成。

### 2.2 Yocto：源码级构建整个系统

- Yocto 用 BitBake 调度"配方（recipe）"，每个软件包一个 recipe，从源码编译（也可用预编译缓存 sstate）。
- 关键概念：**layer**（功能分层，如 `meta-rockchip` 提供板级支持）、**machine**（硬件配置，如 `rockchip-rk3588s-rock-5c`）、**image recipe**（决定最终装什么，如 `core-image-minimal`）、`local.conf`（本地配置入口）。
- 优点：完全可复现、镜像内容 100% 可控、适合量产级发行版；缺点：学习曲线陡、首次构建极慢（数小时到一整天）、需要 32GB 内存 + 90GB 磁盘。
- 本机 `build/tmp/deploy/images/rockchip-rk3588s-rock-5c/` 下已有构建产物，可直接做增量修改。

### 2.3 Buildroot（rk3588_sdk）：极简嵌入式系统

- Buildroot 本身是一套用 Makefile 组织的构建系统，选择 `defconfig` 后下载/编译所有组件，产出极小的 rootfs（busybox + 你选的包）。
- Rockchip 的 `rk3588_sdk` 在此基础上把 **u-boot、kernel、buildroot、recovery、rkbin（固件）** 打包成一个完整 SDK，顶层 `./build.sh` 负责编排，最终生成 RK 格式的 `update.img`。
- 优点：镜像小（几十 MB 到几百 MB）、启动快、非常适合"只包含所需驱动"的专用设备；缺点：装 Python/AI 运行时需要自己逐包选配，Debian 系软件不能直接装。

### 2.4 rsdk：用 Debian 软件源"拼装"RadxaOS

- rsdk 使用 `mmdebstrap`（Debian 官方推荐的 rootfs 生成工具，类似增强版 debootstrap）从软件源直接解包安装 Debian 包，因此天然支持 `apt` 生态——RKNN/RKLLM 的板端运行时大多以 Debian 包或 Python wheel 形式发布，集成最省力。
- `rootfs.jsonnet` 是 rootfs 模板入口：`packages` 字段决定安装哪些包，`customize-hooks` 字段决定安装后的定制动作（写文件、装本地 deb、配 systemd 服务等）。
- `image.jsonnet` 生成 `guestfish` 脚本，负责把 rootfs 变成可启动的磁盘镜像。
- rsdk 本身用 `devenv`（Nix 系）管理开发环境，但**rsdk 构建过程不依赖 Nix**，只是开发容器里预装好了工具。

## 3. 学习路线（推荐顺序）

```text
阶段 0  阅读本文档 + 摸清四个 SDK 目录
   │
阶段 1  BSP：构建/定制 u-boot 与内核（理解硬件层）         ← 文档 01
   │     产物：u-boot deb、linux-image deb
   │
阶段 2  rsdk：编译一份官方 RadxaOS（理解 Debian 系组装）   ← 文档 04
   │     产物：output.img
   │
阶段 3  Buildroot：用 rk3588_sdk 构建极简系统             ← 文档 03
   │     产物：update.img
   │
阶段 4  Yocto：完整源码级构建（可选，理解后可用可不用）    ← 文档 02
   │     产物：core-image-minimal 镜像
   │
阶段 5  端侧 AI：RKNN（视觉）+ RKLLM（大模型）部署         ← 文档 05
   │
阶段 6  综合实战：定制内核 + 定制 rootfs + AI 运行时       ← 文档 06
          最终产出：你自己的"专用 AI 发行版"
```

**给初学者的建议**：

1. 先跑通 01（BSP）和 04（rsdk），这两条路线最快出结果，且能覆盖"内核驱动定制 + Debian 生态"两大需求。
2. 03（Buildroot）适合在"要把体积压到最小、做成专用设备固件"时再深入。
3. 02（Yocto）是三条 rootfs 路线里最重的一条，如果你已经有 rsdk/Buildroot 能满足需求，Yocto 可作为"可复现量产"的进阶选项学习。
