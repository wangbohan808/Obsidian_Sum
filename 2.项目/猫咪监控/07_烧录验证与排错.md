# 07 烧录、验证与排错

> 官方文档：Getting Started → Install OS（boot-from-sd-card / boot_from_emmc / nvme），以及各构建方式文档的烧录章节。

---

## 1. ROCK 5C 启动介质与烧录方式总览

| 启动介质 | 官方推荐烧录方式 | 适用镜像 | 备注 |
| --- | --- | --- | --- |
| microSD 卡 | SDDiskTool（Windows）/ dd（Linux） | RadxaOS 的 `.img`、Yocto 的 `.update.img/.wic`、Buildroot 的 `update.img` | 开发调试首选，烧录方便、可随时换卡 |
| eMMC | upgrade_tool（Linux/macOS）/ RKDevTool（Windows），Type-A 烧录口 | 任意整包镜像 | 需要进入 MaskROM/Loader 模式 |
| NVMe/SSD | 先用 SD 卡启动，再把系统 dd 到 NVMe，或从 USB 烧录 | 任意 | ROCK 5C 需要 SPI Flash 支持（或一直插 SD 引导） |

> ROCK 5C 默认**不带 SPI Flash**，从 NVMe 启动通常需要额外购买/焊接 SPI Flash，或用 SD 卡做引导。开发期建议用 SD 卡。

## 2. 烧录到 SD 卡

### 2.1 Linux（dd）

适用：`*.img`、`*.wic`、`*.update.img`（RK 格式整包也能 dd，但更推荐专用工具）。

```bash
# 1) 确认设备名（重要！别烧错盘）
lsblk
# 卸载分区（如果已自动挂载）
sudo umount /dev/sdb? 2>/dev/null || true

# 2) 写入镜像
sudo dd if=/home/wbh808/rsdk/out/rock-5c_bookworm_cli/output.img \
    of=/dev/sdb bs=4M conv=fsync status=progress

# 3) 检查
sudo sync
lsblk   # 应看到 sdb1(s)/sdb2 等分区
```

### 2.2 Windows（SDDiskTool，烧 RK 格式 update.img）

1. 打开 `SD_Firmware_Tool.exe`，插入 SD 卡。
2. 选择正确盘符，功能模式选 **SD 启动**。
3. 升级固件选择 `update.img`（RK 格式整包），点"开始创建"。

若提示"清空 MBR"问题：

```cmd
diskpart
list disk
select disk 3            ← 换成你的 SD 卡编号
clean
convert gpt
exit
```

（Linux 对应：`sudo fdisk /dev/sdb` → `g` 转 GPT → `wq`。）

### 2.3 通用图形工具

balenaEtcher / Win32DiskImager / Rufus（DD 模式）均可烧 `*.img` / `*.wic` 类镜像。

## 3. 烧录到 eMMC

### 3.1 进入烧录模式

ROCK 5C 的 Type-A 烧录口连接 PC，按住板上的 MaskROM 按键（或按住 Recovery 键）再上电，PC 识别到设备：

```bash
lsusb   # 应看到 Rockchip 相关设备（2207:350b 等）
```

### 3.2 Linux / macOS：upgrade_tool

```bash
# rk3588_sdk 自带（tools/linux/Linux_Upgrade_Tool/... 或 rkbin/tools/），也可单独下载
UPGRADE_TOOL=/home/wbh808/rk3588_sdk/tools/linux/Linux_Upgrade_Tool/Linux_Upgrade_Tool/upgrade_tool
sudo "$UPGRADE_TOOL" uf /path/to/update.img
```

常用子命令：

```bash
upgrade_tool uf update.img    # 烧录整包（含 loader）
upgrade_tool ld               # 列出设备
upgrade_tool rd               # 复位设备
```

### 3.3 Windows：RKDevTool

1. 打开 RKDevTool，确认设备出现在列表。
2. 选"升级固件"页 → 加载 `update.img` → 点"升级"。

## 4. 启动与验证

### 4.1 首次启动

1. 插入 SD 卡/接好 eMMC，接 HDMI 或串口（`/dev/ttyUSB0`，115200 8N1），接 5V Type-C 电源。
2. 观察串口日志：`U-Boot ...` → 内核启动 → 登录提示。
3. 默认账号：RadxaOS 通常 `radxa` / `radxa`（首次登录会要求改密码），自制系统以构建配置为准。

### 4.2 系统验证清单

```bash
# 内核与硬件
uname -a
cat /etc/os-release
lsblk
dmesg | grep -iE 'error|fail' | head

# 网络
ip a && ip route

# NPU
lsmod | grep rknpu
ls -l /dev/rknpu
sudo dmesg | grep -i rknpu

# AI 推理（按文档 05 部署后）
systemctl status my-ai.service
journalctl -u my-ai.service -n 50
```

### 4.3 更新 u-boot / 内核（已在跑的系统的热更新）

```bash
# 板子上安装 bsp 产物
sudo dpkg -i linux-image-*.deb linux-dtb-*.deb
sudo update-initramfs -c -k all

# u-boot 写入启动介质
cd /usr/lib/u-boot/rock-5c/
sudo ./setup.sh update_bootloader /dev/mmcblk1   # 按实际介质
sudo reboot
```

## 5. 常见问题速查表

| 现象 | 可能原因 | 解决 |
| --- | --- | --- |
| 上电无任何输出 | 供电不足 / 介质未识别 | 用 5V/3A+ 官方电源；换 SD 卡；查串口 |
| 串口停在 U-Boot | 内核镜像损坏/不匹配 | 重新烧录；检查 dtb 与内核版本匹配 |
| 卡在 "Starting kernel" | dtb 与板型不符 | 确认烧的是 rock-5c 的镜像（不是 5B/5A） |
| 能进系统但无网络 | 驱动裁剪过头 / 固件缺失 | 补回网卡驱动与固件；检查 `dmesg` |
| /dev/rknpu 不存在 | 内核未开 rknpu / dtb 缺节点 | 见文档 06 步骤 1；`CONFIG_ROCKCHIP_RKNPU=y` |
| RKLLM 报驱动版本低 | NPU 驱动 < 0.9.8 | 升级系统或重编内核（文档 05 §4.4） |
| 系统能起但设备树外设不工作 | overlay 未开 | RadxaOS 用 `sudo rsetup → Overlays`；自制系统在 dtb 或 config 里开启 |
| apt 报源 404 / 签名错误 | 源配置错误 | 用文档 04 的镜像参数重新构建，或修正 `/etc/apt/sources.list.d/` |
| SD 卡烧完没分区 | 镜像格式不对 | RK 格式整包用 SDDiskTool；裸盘镜像用 dd |
| eMMC 烧录失败 | 未进 MaskROM/Loader 模式 | 按住 MaskROM 键再上电；换 Type-A 线（数据线） |

## 6. 备份与恢复

```bash
# 备份整张 SD 卡（恢复用）
sudo dd if=/dev/sdb of=backup.img bs=4M status=progress

# 只备份系统分区
sudo dd if=/dev/sdb2 of=rootfs-backup.img bs=4M status=progress
```

开发阶段建议：**每次烧录前备份当前可用镜像**，裁剪内核时"留一个能启动的备份卡"。
