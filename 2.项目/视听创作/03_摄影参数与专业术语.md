# 摄影参数与专业术语 · 底层原理

> **一句话核心：摄影只有三件事——收了多少光（物理层）、光怎么变成数字（映射层）、数字怎么被写进文件（文件层）。所有参数和名词都挂在这三层上某一根轴上；找不到归属的名词，就是还没学懂的名词。**

> 定位：[[02_声音与效果底层原理]] 的**影像对称篇**。声音是"频率×振幅×时间×相位"四条轴，影像是"光量×时间×映射×编码"四层。两篇框架同构，可对照读。
> 用途：遇到任何一个不认识的参数、菜单项、行业黑话，回到本篇判断它属于哪一层、动的是哪条轴。
> 工程侧出口：本篇的映射层与文件层，就是 [[音视频底层原理]] §一§二 的同一套内容，只是换成了摄影的语汇。设备侧见 [[手机作音视频实验台]]。

---

## 零、三层框架（总纲）

| 层 | 问的问题 | 关键参数 | 决定什么 |
|---|---|---|---|
| **物理层** | 收了多少光、收了多久、从哪来 | 光圈、快门、ISO、ND、色温、焦距 | 曝光对不对、虚不虚、糊不糊 |
| **映射层** | 光怎么变成数字 | 传递函数（gamma/Log/PQ/HLG）、色域、位深、白平衡 | 后期有没有余量、会不会断层 |
| **文件层** | 数字怎么被写进文件 | 编码、码率、色度采样、元数据字段 | 别人能不能正确显示 |

> **三层的关系是单向的：物理层错了，后两层救不回来吗——部分能（宽容度），但代价巨大。文件层错了，前两层白做。**
> 新手只学第一层，所以永远解释不了"为什么我拍的时候看着好好的，导出来发灰"——那是第二、三层的问题。

## 一、物理层：曝光四变量

### 1. 曝光三角 + 一个被忽略的第四项

| 参数 | 记法 | 物理含义 | 动它的副作用 |
|---|---|---|---|
| **光圈** | f/N，N = 焦距 ÷ 通光口径 | 单位时间进光量（面积） | 改景深；收太小触发衍射 |
| **快门** | 秒（1/50）或角度（180°） | 进光持续时间 | 改运动模糊；与帧率耦合 |
| **ISO** | 数值（100/400/3200） | 增益倍数（**不是**传感器灵敏度） | 放大噪点、压缩高光余量 |
| **ND 滤镜** | 减光档数（ND8 = 3 档） | 物理减光 | **几乎无画质副作用** |

> [!important] 视频为什么必须有 ND
> 拍视频时快门角被 180° 法则锁定（见 §四），快门不是自由变量。光线太强时只剩两条路：收光圈（改景深，通常不能动）或上 ND。
> **所以"视频摄影师"和"摄影师"在器材观上最大的分野就是 ND 滤镜——照片可以不买，视频必买。** 手机上靠的是系统自动 ND（多帧合成），这也是计算摄影介入最深的地方之一。

### 2. 光圈档位的数学

标准整档序列（每档光量 ×2，N 按 √2 递增）：

```
f/1.0  1.4  2  2.8  4  5.6  8  11  16  22
      ← √2 ≈ 1.414 →（N² 才是面积，故面积按 2 倍变）
```

- **N 值越大 = 孔越小 = 光越少**。f/2 进光量是 f/2.8 的 2 倍。
- **T 值**（T-stop）：电影镜头标注的实际透光率，已扣除镜片吸收。摄影说 f，电影说 T，同一件事的"理论值"与"实测值"。
- **"大一档/小一档"** 在中文语境里歧义极大：说"大一档光圈"通常指**开大**（N 变小、进光变多）。口头交流时说"加一档曝光"更安全。

### 3. EV：把三个变量归一化

$$EV = \log_2\frac{N^2}{t}\quad(\text{ISO 100 基准})$$

- EV 是**无量纲的对数尺度**，1 EV = 1 档 = 光量 2 倍。
- 等曝光组合：f/2.8 + 1/125 ≡ f/4 + 1/60 ≡ f/5.6 + 1/30（各差一档，互补）。
- 场景亮度参考：晴天户外 EV15、阴天 EV12、室内 EV7–8、烛光 EV2。
- **曝光补偿（±EV）** 不是第四个物理变量，它是"你对测光结果的不信任程度"，本质是告诉自动档"再多给/少给几档"。

### 4. 18% 中灰：一个反直觉的锚点

测光表的假设是"这个世界平均反射率 18%"。

- **为什么不是 50%**：50% 反射率在感知上已经接近"白"，而现实场景的平均亮度更接近 18%（天空、土地、人脸的加权）。
- 18% 反射率经 Rec.709 传递函数后在数字上约等于 **41 IRE**（0–100 标度），不是 50 IRE。**记住这个数**——你要在波形图上找的"标准灰"就在 40 出头的位置，不在中间。
- 灰卡的作用就是把"平均 18%"这个假设变成物理事实，从而让测光、白平衡都有基准。**拍摄对照实验必备，十块钱一张。**

### 5. 手机上的物理层还原度

| 参数 | 真实相机 | iPhone + 飓风相机 | 后果 |
|---|---|---|---|
| 光圈 | 物理可变（1/3 档步进） | **固定物理光圈，App 里的 f 值是模拟曝光量** | 学不到景深与衍射 |
| 快门 | 机械/电子，1/8000 起 | 电子快门可调 | ✅ 可学 |
| ISO | 模拟增益 + 双原生 | 有限档位（多在 25–3200） | ⚠️ 降噪介入，噪点不真实 |
| ND | 物理滤镜 | 无，靠多帧合成 | ❌ 学不到 |
| 焦距 | 可换镜头 | 多摄定焦 + 数码裁切 | 部分可学（0.5/1/2/3× 是物理切换或裁切） |

> 结论：**手机能学"曝光决策"和"时间维度"，学不到"光学"**。这条边界在 [[手机作音视频实验台]] §六 已经算过账——它恰好是求职不需要的那部分。

## 二、映射层：光如何变成数字

这一层是**摄影与音视频工程真正的交汇处**，也是"拍得好看"和"懂原理"的分水岭。

### 1. 传递函数（Transfer Function）：最该先搞懂的名词

传感器输出的是**线性光**，人眼和显示器都是**非线性**的。把线性光塞进有限码值的规则，就叫传递函数。

| 类型 | 代表 | 曲线形状 | 用途 |
|---|---|---|---|
| **Gamma** | 2.2 / sRGB / Rec.709 OETF | 幂函数，压暗部细节省码值 | 日常显示 |
| **Log** | Apple Log 2 / S-Log3 / V-Log | 对数，**暗部给多、高光压平** | 拍摄记录，留后期余量 |
| **HLG** | Rec.2100 HLG | 兼容 SDR 显示器的 HDR |  broadcast / 手机 HDR 视频 |
| **PQ** | SMPTE ST.2084 | 绝对亮度，0–10000 nit | 杜比视界、HDR10 |

> [!important] "Log 是灰的"的物理解释
> 不是加了滤镜，是**把原本集中在暗部的码值匀了一部分给高光**。8 bit 只有 256 级，线性记录时高光一段挤掉大半动态范围；
> 对数曲线把"每一档光"都分配差不多的码值 → 于是"每一档都变得同样暗" → 画面看起来发灰、对比度低。
> **灰不是损失，灰是余量。** 你看到的灰，正是后期可以拉回来的部分。

**这正是"显示变换 ≠ 数据"的最直观教学案例**：飓风相机取景框里套 LUT 显示正常，文件里存的是未套的 Log——同一份数据，两种呈现。

### 2. 色域（Gamut）

| 色域 | 覆盖 CIE 1931 面积 | 用途 |
|---|---|---|
| sRGB / Rec.709 | ≈ 36% | 网络、SDR 视频 |
| DCI-P3 | ≈ 45% | 电影放映、Apple 屏幕 |
| Rec.2020 | ≈ 76% | UHD HDR |
| ACES / AP0 | 更大（虚拟） | 调色中间空间 |

三个常见故障，全都源于色域错配：

| 现象 | 原因 |
|---|---|
| 画面"过饱和到失真" | Rec.709 素材被当 sRGB 解码（矩阵接近但白点不同） |
| 肤色发青/发橙 | 色彩矩阵用错（BT.601 vs BT.709），**不报错** |
| HDR 素材发灰 | 缺色调映射，见 [[音视频底层原理]] §二 |

### 3. 位深（Bit Depth）

| 位深 | 灰阶级数 | 何时必须 |
|---|---|---|
| 8 bit | 256 | 成片交付（SDR） |
| 10 bit | 1024 | **Log / HDR 拍摄的最低要求** |
| 12 bit | 4096 | RAW |

**位深不足的直接表现是 banding（色带）**：天空出现一圈圈台阶。Log 曲线把码值重新分配后，8 bit 的 Log 极易在暗部断层——所以 Log 几乎总是和 10 bit 一起出现，这两个参数是一对。

### 4. 白平衡：从色温到增益

- **色温（K）定义的是光源本身**：黑体加热到某温度时的光谱。
- **反直觉点：数值越大越蓝。** 3200K（钨丝灯）偏橙，5600K（日光）中性，6500K（阴天/D65）偏蓝。
- **拍摄端白平衡的实质**是：告诉相机"这个颜色应该是白"，相机据此计算 R/B 通道的**增益系数**。所以白平衡错 = R/B 增益错 = 整幅画面偏色，且是可逆的（后期能改，但 8 bit 下会损失）。
- **Tint（绿-品红轴）**：严格说白平衡是二维的（色温 × tint），因为荧光灯/钠灯的光谱偏离黑体轨迹。
- **AWB（自动白平衡）** 是算法持续估计，会漂移——这正好是 ISP 里 3A 的 A 之一，也是视频里"同一场景前后两段颜色不一样"的根源。

### 5. 动态范围与三个容易混的名词

| 名词 | 定义 | 常见值 |
|---|---|---|
| **动态范围 DR** | 传感器能同时记录的**最亮/最暗**之比，单位档（stops） | 人眼瞬时 ≈14 档；手机视频 ≈10–12；电影机 14–16 |
| **宽容度 Latitude** | 曝光失误后**能救回**的余量 | 负片 2 档+；Log 视频 1.5–2 档 |
| **信噪比 SNR** | 信号与噪声之比，决定暗部干净程度 | 与光子数的平方根成正比 |

> 三个数不是一回事：动态范围是"能装多少"，宽容度是"装错了还能不能救"，信噪比是"暗部有多脏"。
> **Log 提高的是"记录下来的动态范围"，不提高传感器的物理上限**——它只是把本来被裁掉的高光塞进了码值里。

## 三、文件层：参数如何变成字段

拍完那一刻，物理层和映射层的所有决策都会浓缩成几行元数据。**读得懂这几行，才算真的懂这些参数。**

| 摄影语汇 | 文件里的字段 | 取值样例 |
|---|---|---|
| 色彩空间 / 色域 | `color_primaries` | `bt709` / `bt2020` |
| 传递函数 | `color_transfer` | `bt709` / `arib-std-b67`(HLG) / `smpte2084`(PQ) |
| 色彩矩阵 | `color_space` | `bt709` / `bt601` / `bt2020nc` |
| 范围（Full/Limited） | `color_range` | `tv`(limited) / `pc`(full) |
| 位深 + 采样 | `pix_fmt` | `yuv420p` / `yuv422p10le` |
| 分辨率与帧率 | `width/height` `r_frame_rate` | `3840` `30000/1001` |
| 编码器 | `codec_name` / `profile` | `hevc` / `Main 10` |
| 码率 | `bit_rate` | `50000000` |

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,profile,width,height,r_frame_rate,pix_fmt,\
color_range,color_space,color_transfer,color_primaries,bit_rate,nb_frames \
  -of default=nw=1 input.mov
```

> **上面这 10 个字段，是摄影参数在工程世界的"身份证"。** 一件事在摄影里叫"色彩风格"，在文件里叫 `color_transfer`；
> 叫"画面发灰"，在文件里叫 `color_range=tv` 被当成 `pc` 解释。**同一个事实的两种命名，能互译就是跨过了那道坎。**

## 四、时间维度：视频独有的一套参数

照片没有"时间"，视频的一半参数来自时间。这一节是**照片摄影师转视频时最容易忽略的部分**。

### 1. 帧率（fps）

| 帧率 | 语境 | 备注 |
|---|---|---|
| 23.976 / 24 | 电影 | 24 是"运动模糊最像电影"的心理锚 |
| 25 / 50 | PAL 区（中国、欧洲） | **来自 50 Hz 电网** |
| 29.97 / 30 / 60 | NTSC 区（美、日） | 来自 60 Hz 电网，29.97 是历史遗留 |

> **帧率与电网频率的渊源是硬知识**：在中国拍 25/50 fps，能天然避开日光灯频闪；用 30 fps 拍 50 Hz 光源，会出现滚动黑条（flicker）。

### 2. 快门角（Shutter Angle）：比快门速度更本质的表述

$$\text{曝光时间} = \frac{\theta}{360°} \times \frac{1}{fps}$$

- **180° 法则**：快门 = 1/(2×帧率)。25 fps → 1/50 s；60 fps → 1/120 s。
- **为什么用角度**：来自胶片摄影机的旋转机械快门，叶片开合角度决定曝光占比。角度制的好处是**与帧率解耦**——"180°"在任何帧率下都代表同样的运动模糊观感。
- 角度的审美含义：**180° ≈ 人眼习惯的运动模糊量**。开大到 360° 更"糊"更梦幻，收到 90° 更"锐"更硬派（《拯救大兵瑞恩》式）。
- **这条对视频工程是真知识**：运动模糊直接决定帧间差异，而帧间差异决定码率（见 [[音视频底层原理]] §四）。

### 3. 滚动快门（Rolling Shutter）

CMOS 逐行读出，不是同时曝光。快速横摇时直线变斜、果冻效应（jello）。

- 判据：**读出时间**（readout time）。越快越好，手机普遍较慢。
- 与全局快门（Global Shutter）对立，后者一行同时曝光，工业相机常用（做检测必须）。
- **机器人视觉里这条是硬约束**：机械臂运动时滚动快门会让图像几何失真，标定全废。

### 4. 其他时间相关名词

| 名词 | 含义 |
|---|---|
| 丢帧 / 追帧 | 采集或编码跟不上，帧被丢或时间戳被拉平 |
| 时间码 TC | SMPTE 格式 `HH:MM:SS:FF`，剪辑对齐基准 |
| 变频拍摄（慢动作） | 高帧率拍、低帧率放，需要更高快门速度配合 |
| 果冻/频闪/拖影 | 三种不同的"糊"，分别对应滚动快门、光源频率、快门过慢 |

## 五、光学与画幅：手机学不到但必须认识

这一节的名词**不需要练，但必须能听懂**——面试和协作里随时出现。

### 1. 焦距与等效

- **焦距（mm）**：无限远对焦时，镜头光学中心到传感器的距离。视角随传感器尺寸变化。
- **等效焦距**：按 35mm 全画幅对角（43.27mm）折算的裁切系数。
  - 全画幅 1.0×、APS-C 1.5×、M43 2.0×、1" 2.7×、**iPhone 主摄 ≈3.5×**
  - iPhone 主摄实际约 6.8mm × 3.5 ≈ **24mm 等效**
- 视角（FOV）：广角 >60°、标准 ≈45°、长焦 <30°。

### 2. 景深（DOF）三要素

$$\text{景深} \propto \frac{N \cdot c \cdot d^2}{f^2}$$

| 动谁 | 景深怎么变 | 强度 |
|---|---|---|
| 焦距 f ↑ | 变**浅** | **最强** |
| 拍摄距离 d ↑ | 变**深** | 强（平方关系） |
| 光圈 N ↑（收小） | 变**深** | 中等 |

- **弥散圆（CoC）**：判断"糊"的阈值，全画幅常取 0.03mm。景深不是"清晰/模糊"的硬边界，是渐变。
- **衍射极限**：光圈收到太小时，艾里斑（≈2.44λN）超过像素尺寸，**反而变糊**。手机上像素只有 1µm 级，理论上 f/1.8 之后就开始软化——**所以手机的光圈是固定的**，不是厂商偷懒，是物理上没得选。

### 3. 画幅

| 画幅 | 尺寸 | 裁切 | 特点 |
|---|---|---|---|
| 中画幅 | 53.4×40 | 0.79× | 高像素、浅景深 |
| 全画幅 | 36×24 | 1.0× | 行业基准 |
| APS-C / S35 | 23.6×15.6 | 1.5× | 视频常用 |
| M43 | 17.3×13 | 2.0× | 轻便、防抖好 |
| 1" | 13.2×8.8 | 2.7× | 卡片机 |
| 手机 | 1/1.3" ≈ 10×7.5 | ≈3.5× | 小底 + 计算摄影 |

**Open Gate**：用满传感器全高（如 3:2）录制，后期再裁 16:9 或竖屏——飓风相机的这个选项就是在做这件事，本质是"用分辨率换构图自由度"。

### 4. 镜头缺陷名词（见到就认识即可）

| 名词 | 现象 | 成因 |
|---|---|---|
| 桶形/枕形畸变 | 直线变弯 | 广角/长焦的光学畸变 |
| 暗角 Vignetting | 四角变暗 | 边缘进光量下降 |
| 色散 CA | 高反差边缘出现紫/绿边 | 不同波长折射率不同 |
| 眩光 Flare | 光斑、雾化 | 镜片内反射 |
| 呼吸效应 Breathing | 对焦时视角微变 | 对焦组移动 |
| 变形宽银幕 Anamorphic | 椭圆光斑、横向拉丝 | 横向压缩拍摄 |

> **iPhone 的镜头畸变、暗角、色散全被 ISP 校正过**，所以你"看不到"不等于"不存在"。
> 这在机器人视觉里是同一个问题：**标定就是在把这些光学误差重新算出来。**

## 六、测量与判据：把"看着差不多"变成数字

这一节是**摄影里唯一能自检的部分**，也是飓风相机最值钱的功能。

| 工具 | 横轴 | 纵轴 | 判据 |
|---|---|---|---|
| **直方图** | 亮度 0–255（或 0–1023） | 该亮度的像素数 | 两端"顶墙"= 裁切（过曝/死黑） |
| **波形图 Waveform** | 画面的 X 位置 | 亮度（IRE） | 能看出**哪一块区域**过曝，直方图不行 |
| **斑马纹 Zebra** | — | — | 超过阈值（如 95 IRE）的区域打斜纹 |
| **伪色 False Color** | — | — | 用颜色标出 IRE 区间，最快 |

### IRE 速查

| IRE | 含义 | 8bit 有限范围码值 |
|---|---|---|
| 0 | 黑 | 16 |
| **≈41** | **18% 中灰（人脸曝光基准）** | ≈220 |
| 70–80 | 常规高光（仍可恢复） | ≈700 |
| 90 | 强高光（临界） | ≈800 |
| 100 | 白（裁切点） | 235 |

> **"过曝"的准确含义是"超过了 100 IRE 后被裁成同一个值"——不可恢复。**
> 而暗部"死黑"同理。两者不对称的地方在于：**高光一裁就彻底没了，暗部还能靠提高 ISO 补一点（代价是噪点）**。所以曝光策略是"保高光"。

### ETTR：向右曝光

在不过曝的前提下尽量往右（更亮）曝光，因为亮部的信噪比更高，后期压暗比提亮更干净。

> [!warning] Log 拍摄时 ETTR 不成立
> Log 的全部意义就是"给高光留余量"，此时把直方图推到最右等于自己放弃了那个余量。
> **规则随映射层改变——这是"参数没有绝对正确值，只有语境"的最好例子。**

## 七、名词总表：摄影语 → 工程语

这是本篇最该背下来的一张表。

| 摄影里说 | 工程里对应 | 出现的地方 |
|---|---|---|
| 画面发灰、不精神 | Limited 被当 Full 解释 / 缺色调映射 | `color_range`、色调映射 |
| 肤色不对、偏绿 | 色彩矩阵用错（601 vs 709） | `color_space` |
| 高光死白 | 超过 100 IRE 被裁切 | `bit_depth`、动态范围 |
| 暗部有噪点、色块 | 增益放大 + 位深不足 + 色度子采样 | SNR、`pix_fmt` |
| Log 灰片 | 对数传递函数，码值重新分配 | `color_transfer` |
| 电影感 | 24fps + 180° 快门 + 浅景深 + 宽色域 | `r_frame_rate`、色域 |
| 慢动作 | 高帧率拍摄 + 低帧率回放 | `r_frame_rate` |
| 果冻效应 | 滚动快门读出时间过长 | 传感器读出方式 |
| 卡顿、拖影 | 丢帧 / PTS 不连续 / 快门过慢 | 时间戳、码率 |
| 压缩糊、色块 | 码率不足、GOP 过长、QP 过高 | `bit_rate`、GOP |
| 原片、毛片 | 未调色的 Log / RAW 数据 | RAW、Log |
