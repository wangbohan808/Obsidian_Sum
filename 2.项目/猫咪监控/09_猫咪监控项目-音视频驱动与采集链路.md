# 09 猫咪监控项目：Linux 音视频驱动与采集链路

> 目标：让 ROCK 5C 稳定输出摄像头画面，并用 **MPP 硬件编码**生成 H.264/H.265 视频。
> 分两条路径：**方案 A（USB UVC，推荐起步）** 与 **方案 B（MIPI CSI，进阶/展示 BSP 功底）**。
> 本机资料：`/mnt/hgfs/camera_drivers/`（sensor 驱动、RK ISP 源码、DTS 参考、V4L2 头文件）。

---

## 1. 原理：Linux 视频驱动的层次结构（必须理解）

### 1.1 从摄像头到应用的数据通路

```text
摄像头 Sensor（OV5640/IMX219/IMX415 或 UVC 芯片）
   │  MIPI CSI-2 / USB
   ▼
控制器：MIPI CSI-2 Host（csi2_dcphy） 或 USB Host（xhci）
   │
   ▼
图像前端：RK CIF（rkcif）→ RK ISP（rkisp，自动曝光/白平衡/降噪）
   │
   ▼
V4L2 video device：/dev/video0（capture 节点）
   │
   ▼
用户态：v4l2-ctl / GStreamer / FFmpeg / OpenCV / 自研程序
```

### 1.2 关键内核框架

| 框架/组件 | 作用 | 相关源码位置 |
| --- | --- | --- |
| V4L2（Video for Linux 2） | 视频设备用户态 API（open/ioctl/mmap/streamon） | `drivers/media/v4l2-core/` |
| Media Controller | 把 sensor → CSI → ISP → video 节点连接成"媒体图" | `/dev/media0`，`media-ctl` 工具 |
| v4l2-subdev | sensor 等子设备驱动接口（s_power/s_stream/ctrl） | `drivers/media/v4l2-core/v4l2-subdev.c` |
| videobuf2 (vb2) | 内存缓冲区管理（mmap/dmabuf），GStreamer 靠它零拷贝取帧 | `drivers/media/common/videobuf2/` |
| UVC 驱动 | USB 摄像头（标准视频类）驱动，免厂商驱动 | `CONFIG_USB_VIDEO_CLASS=y` |
| rkcif / rkisp / rkispp | RK 平台的 Camera Interface / Image Signal Processor / 后处理 | `drivers/media/platform/rockchip/` |
| MIPI D-PHY/CSI-2 | RK3588 的 CSI 物理层与协议层 | `drivers/media/platform/rockchip/csi2-dphy/` 等 |

### 1.3 ROCK 5C 现状（已核实）

- 内核 `rockchip_linux_defconfig`（bsp 与 rk3588_sdk 相同）已内置：
  `CONFIG_VIDEO_ROCKCHIP_CIF=y`、`CONFIG_VIDEO_ROCKCHIP_ISP=y`、`CONFIG_VIDEO_ROCKCHIP_ISPP=y`、
  `CONFIG_VIDEO_IMX219=y`、`CONFIG_VIDEO_IMX415=y`、`CONFIG_VIDEO_OV5647=y`、`CONFIG_VIDEO_GC2093=y` 等。
- ROCK 5C 板级设备树 `rk3588s-rock-5c.dts` **尚未包含任何 camera 节点**（仅有 MIPI DSI 显示）。
- 硬件上有一个 **4-lane MIPI CSI 座子（31pin，FH35C-31S-0.3SHW）**，支持双通道（csi2_dcphy0 两条 lane 可拆分）。
- 因此：USB 摄像头插上即可用；MIPI 摄像头需要**自己写 DTS overlay**（见第 4 节）。

## 2. 方案 A：USB UVC 摄像头（推荐先做）

### 2.1 硬件与驱动

任意标准 UVC 摄像头（如罗技 C270/C920、OV5640 UVC 模组）。内核选项（bsp 的 `kconfig.conf` 中确认）：

```text
CONFIG_USB_VIDEO_CLASS=y        # UVC 驱动
CONFIG_USB_VIDEO_CLASS_INPUT=y  # UVC 按键输入（可选）
CONFIG_MEDIA_USB_SUPPORT=y
CONFIG_USB_XHCI_HCD=y           # USB3/2 控制器
```

### 2.2 板端验证步骤（官方 RadxaOS 或自制镜像均可）

```bash
# 1) 确认设备被枚举
lsusb | grep -i cam
# 期望：Bus ... ID 046d:0825 Logitech, Inc. Webcam C270 之类

# 2) 确认 V4L2 设备与格式
sudo apt install -y v4l-utils
v4l2-ctl --list-devices
# 期望输出类似：

#   HD USB Camera: HD USB Camera (usb-...)

#       /dev/video0

#       /dev/media0

# 3) 查看支持的格式/分辨率/帧率
v4l2-ctl -d /dev/video0 --list-formats-ext
# 期望出现 YUYV / MJPG，以及 1920x1080、1280x720 等

# 4) 测试单帧抓图（验证整条链路）
v4l2-ctl -d /dev/video0 --set-fmt-video=width=1280,height=720,pixelformat=YUYV \
         --stream-mmap --stream-count=1 --stream-to=/tmp/test.yuv
ls -lh /tmp/test.yuv

# 5) 看实时画面（开发期用 ffplay / gst-launch）
ffplay -f v4l2 -input_format mjpeg -video_size 1280x720 -framerate 30 /dev/video0
```

> 提示：UVC 摄像头通常提供 MJPG 压缩流（USB 带宽小）与 YUYV 原始流。**采集用 MJPG 更省带宽，但解码需 CPU；本项目推荐 YUYV + RGA/ISP 处理或直接 720p YUYV 喂给硬件编码。** 实际以测试为准。

### 2.3 推荐采集格式

- 视频采集：`YUYV 1280x720@15fps`（或 MJPG 1080p→由 mpp 解码）。
- AI 输入：单独低分辨率流（640x360 灰度/或 640x640 RGB 缩略帧），用 RGA 硬件缩放，避免和录制争抢。
- 本项目最终在应用里用 GStreamer 同时获得"AI 分析帧"与"录制帧"：

```bash
# 一条管线示例：v4l2src 捕获 → tee 分流

#   分支1：低分辨率帧 → appsink（喂给 AI）

#   分支2：720p 帧 → mpph264enc → 录制（事件触发后写盘）
```

## 3. 原理：GStreamer + Rockchip MPP 硬件编码

RK3588 内置 **VEPU（视频编码单元）**，GStreamer 通过 Rockchip 维护的 `gstreamer1.0-rockchip` 插件（`mpph264enc` / `mpph265enc` / `mppjpegenc`）与 **libmpp** 对接硬件编码。

```bash
# 板端安装（Debian 系）
sudo apt install -y gstreamer1.0-tools gstreamer1.0-plugins-base \
     gstreamer1.0-plugins-good gstreamer1.0-plugins-bad \
     gstreamer1.0-plugins-ugly \
     gstreamer1.0-rockchip1 librockchip-mpp1 librga2 librockchip-vpu0
# 注：包名以 Radxa 官方源为准（已核实）：gstreamer1.0-rockchip1 提供 mpph264enc，

#     librockchip-mpp1/librga2/librockchip-vpu0 为 MPP/RGA 运行时；

#     也可直接安装元包：task-rockchip-mpp（依赖上面全部）。

# 检查插件存在
gst-inspect-1.0 | grep -i mpp
# 期望：mpph264enc / mpph265enc / mppjpegenc / mppvideodec 等
```

### 3.1 手动验证硬件编码（命令行）

```bash
# 720p 硬编码测试：采集 → H.264 → 封装 MP4
gst-launch-1.0 -e \
    v4l2src device=/dev/video0 ! \
    video/x-raw,width=1280,height=720,framerate=15/1,format=YUY2 ! \
    videoconvert ! video/x-raw,format=I420 ! \
    mpph264enc ! h264parse ! mp4mux ! \
    filesink location=/tmp/test_720p.mp4

# 观察 CPU：应接近 0%（硬件编码）
top -d 1
```

参数建议（长期运行）：

```bash
mpph264enc bps=2000000 bps-max=3000000 rc-mode=vbr
# 注：mpph264enc 的码率属性是 bps（单位 bit/s，非 kbps）；1080p 建议 2~4 Mbps，720p 1~2 Mbps
```

### 3.2 录制帧率与码率估算（存储规划用）

| 分辨率 | 帧率 | 码率 | 每天事件时长 1h | 每天事件时长 2h |
| --- | --- | --- | --- | --- |
| 1280x720 | 15 | 1.5 Mbps | ~0.7 GB | ~1.35 GB |
| 1920x1080 | 15 | 3 Mbps | ~1.35 GB | ~2.7 GB |
| 1920x1080 | 25 | 5 Mbps | ~2.25 GB | ~4.5 GB |

> 因为只在事件期间录制（每天通常累计 0.5~2 小时），32GB 卡可存 2~4 周，配合上传与清理完全够用。

## 4. 方案 B：MIPI CSI 摄像头（IMX219/IMX415，进阶）

### 4.1 为什么值得做

- 展示 BSP 能力：**写 DTS overlay、配媒体管线、调 ISP**，这是简历上"Linux 驱动层"最有分量的部分。
- 功耗/延迟/画质优于 USB 摄像头，适合长期 7×24 部署。

### 4.2 需要完成的三件事

1. **sensor I2C 节点**：把 IMX219/IMX415 注册到 I2C 总线（ROCK 5C 的 CAM I2C：`SCL_CAM/SDA_CAM`）。
2. **CSI 管线连接**：sensor → `csi2_dcphy0` → `rkcif`（+ `rkisp` 可选）→ `/dev/video*`。
3. **内核配置**：sensor 驱动（IMX219 已 =y）与 CIF/ISP（已 =y），一般无需再改 config。

### 4.3 参考素材（本机已备）

```text
├── media_headers/                   # v4l2-subdev 等头文件

├── dts_rock5c/rk3588s-evb1-lp4x-v10-camera.dtsi   # ★ EVB 摄像头参考（csi2_dcphy0 完整写法）
```

### 4.4 编写 ROCK 5C 摄像头 overlay（步骤）

以 IMX219 为例，新建 `/home/wbh808/bsp/.src/radxa-overlays/arch/arm64/boot/dts/rockchip/overlays/rock-5c-radxa-camera-8m-219.dts`：

```dts
/dts-v1/;
/plugin/;

#include <dt-bindings/clock/rk3588-cru.h>
#include <dt-bindings/gpio/gpio.h>
#include <dt-bindings/pinctrl/rockchip.h>

&{/} {
    vcc_cam_3v3: vcc-cam-3v3 {
        compatible = "regulator-fixed";
        regulator-name = "vcc_cam_3v3";
        regulator-min-microvolt = <3300000>;
        regulator-max-microvolt = <3300000>;
        gpio = <&gpio1 RK_PB6 GPIO_ACTIVE_HIGH>;   // CAM_RST/PDN 按原理图调整
        enable-active-high;
    };
};

&i2c8 {                                            // ROCK 5C CAM I2C（按原理图确定总线号）
    status = "okay";
    pinctrl-names = "default";
    pinctrl-0 = <&i2c8m2_xfer>;

    imx219: imx219@10 {
        compatible = "sony,imx219";
        reg = <0x10>;
        clocks = <&cru CLK_MIPI_CAMARAOUT_M4>;
        clock-names = "xvclk";
        clock-frequency = <24000000>;
        pinctrl-names = "default";
        pinctrl-0 = <&mipim0_camera1_clk>;         // CAMERA1_CLK
        reset-gpios = <&gpio1 RK_PB7 GPIO_ACTIVE_LOW>; // CAM_RST
        pwdn-gpios = <&gpio1 RK_PB6 GPIO_ACTIVE_HIGH>; // CAM0_PDN
        rockchip,camera-module-index = <0>;
        rockchip,camera-module-facing = "back";
        rockchip,camera-module-name = "rpi-camera-v2";
        rockchip,camera-module-lens-name = "default";
        port {
            imx219_out: endpoint {
                remote-endpoint = <&dcphy0_in_imx219>;
                data-lanes = <1 2>;
            };
        };
    };
};

&csi2_dcphy0 {
    status = "okay";
    ports {
        #address-cells = <1>;
        #size-cells = <0>;
        port@0 {
            reg = <0>;
            dcphy0_in_imx219: endpoint {
                remote-endpoint = <&imx219_out>;
                data-lanes = <1 2>;
            };
        };
        port@1 {
            reg = <1>;
            csidcphy0_out: endpoint {
                remote-endpoint = <&mipi0_csi2_input>;
            };
        };
    };
};

&mipi0_csi2 {
    status = "okay";
    ports {
        #address-cells = <1>;
        #size-cells = <0>;
        port@0 {
            reg = <0>;
            mipi0_csi2_input: endpoint {
                remote-endpoint = <&csidcphy0_out>;
            };
        };
        port@1 {
            reg = <1>;
            mipi0_csi2_output: endpoint {
                remote-endpoint = <&cif_mipi_in0>;
            };
        };
    };
};

&rkcif {
    status = "okay";
};

&rkcif_mipi_lvds {
    status = "okay";
    port {
        cif_mipi_in0: endpoint {
            remote-endpoint = <&mipi0_csi2_output>;
        };
    };
};

&rkcif_mmu {
    status = "okay";
};
```

> 注意：具体 GPIO（reset/pwdn/clk）与 I2C 总线号必须以 **ROCK 5C 原理图/官方 CAM 排针定义**为准（见文档 08 第 4 节接口表：CAM_RST、CAM1_PDN、CAMERA1_CLK、SCL_CAM/SDA_CAM）。上面为模板，GPIO 编号需按实际硬件核对。


### 4.6 板端媒体管线配置与验证

```bash
sudo apt install -y v4l-utils      # 已包含 media-ctl（Debian 不单独提供该包）

# 4) 出图测试
v4l2-ctl -d /dev/video0 --set-fmt-video=width=1920,height=1080,pixelformat=NV12 \

```

### 4.7 ISP 与图像质量（IMX219/IMX415 示例）

RK3588 的 ISP 提供 3A（自动曝光/白平衡/对焦）。板端建议：

```bash
# 用 rkaiq 提供的 3A 服务（RadxaOS 自带 rkaiq_3A_server 或 rkisp 3A）
sudo systemctl status rkaiq_3A_server   # 若存在
# 或使用官方 rkisp_demo / imx219 的 libcam 示例
```

如果只跑固定场景（室内、固定光照），也可以**固定曝光/白平衡**，减少 3A 抖动导致的画面闪烁：

```bash
v4l2-ctl -d /dev/video0 --set-ctrl exposure=300,analogue_gain=100,white_balance_automatic=0
```

## 5. 音频（可选加分项）

项目不强制要求声音，但"猫咪进食咀嚼声"可作为**行为判定的辅助信号**（降低误判）。

### 5.1 Linux 音频栈

```text
ALSA（内核：snd-usb-audio / Rockchip I2S + ES8388/ES8316 编解码）→ /dev/snd/*
   → PulseAudio/PipeWire（可选）→ 应用（arecord / GStreamer）
```

### 5.2 启用与验证

```bash
# 内核确认（bsp kconfig.conf 或 defconfig）
CONFIG_SND_USB_AUDIO=y        # USB 麦克风
CONFIG_SND_SOC_ROCKCHIP=y     # 板载音频（默认已开，见 bsp kconfig.conf 注释）

# 板端
arecord -l                     # 列出录音设备
arecord -D plughw:0,0 -f cd -d 5 /tmp/test.wav
gst-launch-1.0 alsasrc device=hw:0 ! audioconvert ! audio/x-raw,rate=16000 ! \
    filesink location=/tmp/test.raw
```

音频融合方案（后续迭代）：

- 用 WebRTC VAD 检测"是否有声音片段"；
- 与视觉状态机做 AND/OR 融合：视觉候选 + 声音持续 >1s → 提高事件置信度；
- 或训练一个小型音频分类器（进食声 vs 环境声），输出与视觉结果加权。

## 7. 常见问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `v4l2-ctl --list-devices` 无输出 | UVC 驱动未开/供电不足 | 检查 `lsusb`、换 USB 口、内核开启 `CONFIG_USB_VIDEO_CLASS` |
| MIPI 无画面 | DTS 节点缺失或媒体管线未配置 | 核对 overlay 中 GPIO/I2C/时钟；用 `media-ctl -p` 查拓扑 |
| 编码时 CPU 100% | 没走 MPP 硬件编码 | 确认 `mpph264enc` 插件存在且被使用（`gst-inspect`） |
| 夜间画面噪点大/全黑 | 无补光、ISP 参数不当 | 红外补光灯；固定曝光增益；提高码率 |
| 录制丢帧 | SD 卡太慢/码率过高 | 换 A2/U3 卡；降帧率码率；用 eMMC/NVMe |
| 长时间运行采集卡死 | USB 电源管理或驱动 bug | `echo on > /sys/bus/usb/devices/*/power/control`；加 watchdog 重启应用 |

链路跑通后，进入文档 10：在采集帧上做 AI 行为识别与事件录制。
