### 1.4 rsdk（RadxaOS 构建系统）

| 属性 | 内容 |
|---|---|
| **路径** | `/home/wbh808/rsdk` |
| **性质** | Debian OS 镜像构建工具链，**不包含内核源码** |
| **构建工具** | `bdebstrap` + Jsonnet + `guestfish` |
| **功能** | 生成可刷写的 RadxaOS 系统镜像 |

**摄像头相关内容:**
- 内核配置补丁 `debian/patches/linux/0001-feat-Radxa-common-kernel-config.patch` 中启用了:
  - `CONFIG_VIDEO_IMX214=m`, `CONFIG_VIDEO_IMX219=m`, `CONFIG_VIDEO_IMX415=m`, `CONFIG_VIDEO_IMX708=m`
  - `CONFIG_VIDEO_OV5647=m`, `CONFIG_VIDEO_DW9807_VCM=m`, `CONFIG_USB_VIDEO_CLASS=m`
  - `CONFIG_VIDEO_V4L2=y`, `CONFIG_VIDEO_V4L2_I2C=y`, `CONFIG_VIDEO_V4L2_SUBDEV_API=y`
- **不包含**: 内核源码、设备树、摄像头驱动代码
- 仅为构建系统工具链，实际内核源码来自 `github.com/radxa/kernel`

## 4. RK3588S ISP/CIF 摄像头数据流通路解析

### 4.1 硬件数据流

```
  摄像头传感器 (I2C 控制, XVCLK 时钟)
       │
       │ MIPI CSI-2 差分信号 (1/2/4 data lanes)
       ▼
  ┌──────────────┐
  │  MIPI D-PHY  │  mipi_dcphy0/1, csi2_dphy0~5_hw (物理层)
  │  (物理层)     │  最大支持 2.5 Gbps/lane
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │ CSI2 D-PHY    │  csi2_dcphy0/1, csi2_dphy0~5 (软件组合节点)
  │  (组合节点)   │  将 D-PHY 硬件与 CSI 控制器绑定
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │  MIPI CSI-2  │  mipi0~3_csi2 (CSI-2 协议控制器)
  │  控制器       │  CSI-2 协议解析、虚拟通道管理
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │   RKCIF      │  rkcif + rkcif_mipi_lvds (Rockchip Camera Interface)
  │  (摄像头接口) │  数据捕获、格式转换、裁剪
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │     ISP       │  rkisp0/rkisp1 + rkisp0_vir0 (Image Signal Processor)
  │  (图像信号处理)│  3A(AF/AWB/AE)、去噪、坏点校正、色彩校正、Gamma...
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │    ISPP       │  ispp (ISP 后处理)
  │  (后处理)     │  FEC(镜头畸变校正)、缩放、裁剪
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │  V4L2 输出   │  /dev/videoX (用户空间访问)
  │  (用户空间)   │  GStreamer, v4l2-ctl, rkaiq, libcamera...
  └──────────────┘
```

### 4.2 设备树节点映射关系（完整链路）

```
传感器 I2C 节点 (例如 imx415@1a)
    │  compatible = "sony,imx415";
    │  reg = <0x1a>;
    │  port → endpoint → remote-endpoint = <&mipi_in_ucam0>;
    │  data-lanes = <1 2 3 4>;
    ▼
csi2_dcphy0 (或 csi2_dphyX)
    │  port@0 输入: remote-endpoint = <&sensor_out>
    │  port@1 输出: remote-endpoint = <&mipi0_csi2_input>
    ▼
mipi0_csi2 (CSI-2 控制器)
    │  port@0 输入: remote-endpoint = <&csidcphy0_out>
    │  port@1 输出: remote-endpoint = <&cif_mipi_in0>
    ▼
rkcif_mipi_lvds (CIF MIPI 通道)
    │  port: remote-endpoint = <&mipi0_csi2_output>
    ▼
rkcif_mipi_lvds_sditf (CIF → ISP 桥接)
    │  port: remote-endpoint = <&isp0_vir0>
    ▼
rkisp0_vir0 (ISP 虚拟输出)
    │  port: remote-endpoint = <&mipi_lvds_sditf>
    ▼
rkisp0 (ISP 核心处理单元)
    │
    ▼
  /dev/videoX (最终输出设备节点)
```

### 4.3 RK3588S SoC 可用的 CSI/ISP 硬件资源

根据 `rk3588s.dtsi` 定义，RK3588S 提供:

| 资源类型 | 节点名 | 数量 | 说明 |
|----------|--------|------|------|
| **D-PHY 硬件** | `csi2_dphy0_hw` ~ `csi2_dphy1_hw` | 2个 | 物理 MIPI D-PHY |
| **DC-PHY (自带D-PHY)** | `mipi_dcphy0`, `mipi_dcphy1` | 2个 | 集成 D-PHY 的 MIPI 接口 |
| **CSI2 D-PHY 软件节点** | `csi2_dcphy0/1` + `csi2_dphy0~5` | 8个 | 虚拟组合节点 |
| **MIPI CSI-2 控制器** | `mipi0_csi2` ~ `mipi3_csi2` (实际可用取决于pinmux) | 4个 | 独立 CSI-2 控制器 |
| **RKCIF MIPI 通道** | `rkcif_mipi_lvds` ~ `rkcif_mipi_lvds3` | 4个 | CIF 抓取通道 |
| **ISP 核心** | `rkisp0`, `rkisp1` | 2个 | 独立 ISP 处理单元 |
| **ISP 虚拟输出** | `rkisp0_vir0`~`vir2`, `rkisp1_vir0`~`vir2` | 6个 | 多路虚拟输出 |
| **ISP 联合模式** | `rkisp_unite` | 1个 | 双 ISP 联合处理 (高像素) |
| **ISPP 后处理** | `ispp` | 1个 | FEC/缩放/裁剪 |
| **CIF MMU** | `rkcif_mmu` | 1个 | IOMMU |
| **ISP MMU** | `isp0_mmu`, `isp1_mmu` | 2个 | ISP IOMMU |

### 4.4 RK3588S vs RK3588 (完整版) CSI 资源差异

**RK3588S** (ROCK-5C 使用的芯片) 是 RK3588 的精简版:
- D-PHY 硬件: 2个 (vs RK3588的多个)
- 部分 CSI 通道不可用或被缩减
- 但 ISP 核心 (rkisp0/rkisp1) 完整保留
- **ROCK-5C 通常只有 1 个 4-lane MIPI CSI 接口可对外使用**

## 5. ROCK-5C 摄像头配置现状与关键发现

### 5.1 当前状态 ⚠️

**ROCK-5C 的主设备树 (`rk3588s-rock-5c.dts`) 中完全没有摄像头相关配置！**

| 检查项 | 状态 |
|--------|------|
| I2C 总线配置 | I2C0 (PMIC), I2C2 (NPU供电), I2C7 (音频Codec) — **无摄像头I2C** |
| CSI D-PHY 节点 | **未启用** |
| MIPI CSI-2 控制器 | **未启用** |
| RKCIF | **未启用** |
| ISP | **未启用** |
| 摄像头 overlay | **没有 rock-5c 专属的overlay** |

### 5.2 重要发现 ★

**现有的 ROCK-5A 摄像头 overlay 中已包含 `"radxa,rock-5c"` 兼容性标记！**

在 `bsp/.src/linux/arch/arm64/boot/dts/rockchip/overlays/` 下:

| Overlay 文件 | 使用的传感器 | 兼容性 |
|-------------|-------------|--------|
| `rock-5a-radxa-camera-4k.dts` | **IMX415** (Radxa Camera 4K) | 含 `radxa,rock-5a`, **`radxa,rock-5c`** |
| `rock-5a-radxa-camera-8m-219.dts` | **IMX219** (Radxa Camera 8M) | 含 `radxa,rock-5a`, **`radxa,rock-5c`** |
| `rock-5a-okdo-5mp-camera.dts` | OKDO 5MP | 含 `radxa,rock-5a`, **`radxa,rock-5c`** |
| `rock-5a-rpi-camera-v1_3.dts` | **OV5647** (RPi v1.3) | 含 `radxa,rock-5a`, **`radxa,rock-5c`** |
| `rock-5a-rpi-camera-v2.dts` | **IMX219** (RPi v2) | 含 `radxa,rock-5a`, **`radxa,rock-5c`** |
| `rock-5d-radxa-camera-4k.dts` | IMX415 | 含 `radxa,rock-5d` |
| `rock-5b-radxa-camera-4k.dts` | IMX415 | 含 `radxa,rock-5b` |

**这意味着**: ROCK-5A 的摄像头 overlay **理论上可以直接在 ROCK-5C 上使用**！因为:
1. ROCK-5A 和 ROCK-5C 都使用 **RK3588S** SoC
2. overlay 文件中已经声明了 `radxa,rock-5c` 兼容性
3. overlay 引用的 I2C/GPIO/CSI 通路在两块板上相同

### 5.3 开发摄像头驱动的推荐策略

有两种方式:

**方式A (推荐新手)**: 使用现有的 ROCK-5A 摄像头 overlay
- 直接使用 `rock-5a-radxa-camera-4k.dts` (IMX415) 或 `rock-5a-rpi-camera-v2.dts` (IMX219)
- 这些 overlay 已经配置好了完整的 CSI → CIF → ISP 数据通路
- 只需确保内核 defconfig 中启用了对应的传感器驱动

**方式B (新传感器开发)**:
1. 确定目标传感器的硬件连接（I2C 总线、GPIO、MIPI lane 数）
2. 仿照 `rock-5a-radxa-camera-4k.dts` 创建新的 overlay
3. 编写或移植传感器驱动到 `drivers/media/i2c/`
4. 更新 Kconfig/Makefile/defconfig

    ret = v4l2_async_register_subdev(&sensor->subdev);

    // ... rk_camera_module_register(...) ...

### 9.2 常见问题排查

| 问题 | 可能原因 | 排查方法 |
|------|---------|---------|
| **I2C 通信失败** | GPIO/供电/时钟配置错误 | 用示波器量 CLK/DATA; 检查 RESET 和 PWDN GPIO 电平; 检查 XVCLK |
| **Chip ID 不匹配** | 寄存器地址错误/时序不对 | 确认数据手册的 CHIP_ID 寄存器和期望值; 加延时等传感器稳定 |
| **probe 函数未调用** | compatible 不匹配/设备树问题 | 检查 `/proc/device-tree/` 下是否有对应节点; 检查 compatible 字符串 |
| **无图像输出** | MIPI 配置错误 | 检查 data-lanes 数; 检查 link-frequencies; 检查 MIPI clock |
| **花屏/条纹** | 时序不匹配 | 调整 HTS/VTS/Exposure/Vblank; 用示波器量 MIPI 信号 |
| **ISP 报错** | IQ 文件不匹配 | 确认 sensor 名称与 RKAIQ IQ 文件名一致 |
| **帧率不对** | VTS/HTS 配置问题 | `v4l2-ctl -d /dev/v4l-subdevX --get-frame-interval` |
