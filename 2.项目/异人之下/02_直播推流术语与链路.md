# 直播推流：术语表与链路方案

> [!info] 一句话核心
> 直播全链路只有四环：**采集 → 编码 → 上传 → 平台分发**。所有术语都在回答"这一环的数值是多少"。
> 排查故障先分三件事：**卡 = 带宽不够，糊 = 码率不够，灰 = 色彩范围不对**——三套完全不同的修法，混着查最浪费时间。

> 设备前提：拯救者 R7000P 2021（RTX 3050Ti Laptop / 4G）作游戏机 + 第二台电脑作推流机，B 站与抖音双平台。
> 设置侧的口径与 [[01_设置项探勘表]] 对照使用，冲突处以本文 §2 的说明为准。

---

## 0. 链路总览

```
游戏机 --HDMI--> 采集卡 --USB 3.0--> 推流机 --网络--> 平台
                    |
                    +--环出--> 显示器（自己看，零延迟）
```

双机的全部价值在这一句：**游戏机只跑游戏不编码，所以能开独占全屏、榨出全部性能**；推流机只做编码，两个平台各推一路互不干扰。

---

## 1. 信号链路

| 术语 | 含义 | 判据 / 影响 |
| --- | --- | --- |
| 采集卡 | 把 HDMI 信号采进电脑的硬件 | 双机方案里游戏机与推流机唯一的通路 |
| 环出（Loop-out / Passthrough） | 采集卡上的 HDMI OUT，原样复制一份输入信号 | **硬件直通不压缩，延迟近零**；你玩看这路，观众看 USB 那路 |
| USB 3.0 | 5Gbps 接口标准 | 1080p60 未压缩约 **250 MB/s**，USB 2.0 仅 60 MB/s，物理上传不动 |
| YUY2 / NV12 | 未压缩视频像素格式（16 bit / 12 bit 每像素） | 标注这两个 = 真采集、延迟低，选卡认这两个词 |
| MJPG | 逐帧 JPEG 压缩传输 | 廉价卡唯一方案：画质降档、需解码、延迟 100ms+ |
| 1080p60 | 1920×1080 @ 60fps | 格斗游戏底线，30fps 看不清出招 |

> [!warning] 选卡三条硬线
> ① 1080p60 YUY2/NV12 ② 带 HDMI 环出 ③ 带 3.5mm 耳机口。
> 缺第三条只能走显示器耳机口（音质差且有延迟）；缺第二条要另买 HDMI 分线器。

## 2. 显卡与游戏设置

| 术语 | 含义 | 判据 / 影响 |
| --- | --- | --- |
| 移动版显卡（Laptop GPU） | 笔记本专用 GPU，同型号弱 20–40%，受功耗墙限制 | RTX 3050Ti 移动版 ≈ 台式 GTX 1660，**低于本作最低配（台式 RTX 2060）** |
| 显存 / VRAM | 显卡高速内存，存纹理与帧缓冲 | 4G 是硬伤：纹理开高会"爆显存"，帧数断崖式下跌 |
| 独占全屏 | 游戏直接接管输出，绕过桌面合成器 | 延迟最低、帧数最高；**双机下可放心用**，采集卡抓的是 HDMI，与窗口模式无关 |
| 帧率上限 / FPS Cap | 限制每秒最多渲染多少帧 | **作用从"压性能"变成"压波动"**，详见下方专项 |
| 渲染比例（Resolution Scale） | 按百分之几的分辨率渲染再拉伸 | 100% 为原生；降到 85% 肉眼难辨却能白捡帧数 |
| 纹理质量 | 贴图精细度，直接吃显存 | 4G 显存必调低，唯一没有妥协空间 |
| 动态模糊 | 快速移动时的拖影 | 格斗游戏必关：拖影影响判断对方出招 |
| 垂直同步（V-Sync） | 帧率与刷新率对齐，消撕裂 | 代价是输入延迟，必关 |
| 温度墙 / 降频 | 芯片达临界温度（GPU ≈ 87°C）自动降频 | 笔记本最大的隐形杀手：帧数掉一档但不报错 |
| 硅脂 | CPU/GPU 与散热器间导热膏，逐年干涸 | 五年未换散热效率可掉 20–30%，**软件调不回来** |
| 野兽模式 | 拯救者性能模式（Fn+Q） | 提高功耗上限；不插电时任何模式都降频 |

### 专项：帧率上限，直播时该不该锁

[[01_设置项探勘表]] 的判据是"帧率拉满、不锁 60"，这条**在纯竞技场景下是对的**——帧率越高，输入延迟越低。但直播时目标变了：

| 场景 | 优化目标 | 帧率上限怎么设 |
| --- | --- | --- |
| 不直播、纯竞技 | **最低输入延迟** | 拉满。机器跑多少算多少 |
| 直播（编码器介入） | **最低帧时间波动** | **锁在"能稳定维持"的那一档**，不是锁死 60 |

原因：编码器按固定帧率取帧（60fps 就是每 16.7ms 取一张）。如果游戏帧数在 40–55 之间跳，编码器会取到重复帧和缺帧，观众看到的是**间歇性卡顿**，比稳定 45 帧难看得多。

所以正确的做法不是"锁 60"，而是**先测出这台机器在这款游戏里能稳定维持的帧数**：
- 能稳 60 以上 → 锁 60（或拉满，两者差别已很小）
- 只能稳 45–55 → 锁 45，同时降画质往上够
- 稳不到 40 → 降分辨率到 900p 或把渲染比例压到 85%，再锁 60

**一句话：非直播看延迟，直播看稳定。** 两份笔记不冲突，是同一个开关在不同场景下的两个位置。

## 3. 编码与推流参数

| 术语 | 含义 | 判据 / 影响 |
| --- | --- | --- |
| 编码 | 把原始画面压成 H.264 流 | 直播全部算力成本所在 |
| 软编 / 硬编 | CPU 算（x264） / 显卡专用电路算 | 硬编不占 CPU；<6000kbps 画质逊于软编，之上差距不可见 |
| NVENC | NVIDIA 硬件编码器（Ampere 为第 7 代） | 有 N 卡首选，几乎零代价 |
| QSV | Intel 核显硬件编码器（Quick Sync） | 推流机无独显时的退路 |
| H.264 | 最通用压缩标准 | 直播唯一可用，H.265 平台不接 |
| 码率 / bitrate | 每秒传输数据量（kbps） | 8000kbps = 8Mbps = 1MB/s；不足则糊，过则超平台上限或撑爆上行 |
| 关键帧间隔 / GOP | 隔固定秒数插完整 I 帧，其余存差值 | 标准 2 秒；太稀观众刚进来要等画面，太密白烧码率 |
| 色彩空间 BT.709 | 高清视频色彩定义 | 设错偏色 |
| 部分范围 / Limited（16–235） | 视频只用 0–255 中的 16–235 | **推流端与平台不一致 = 灰蒙蒙**，最说不清的画质问题 |

### 参数速查

| 项 | B 站（OBS） | 抖音（直播伴侣） |
| --- | --- | --- |
| 编码器 | NVENC H.264 / QSV | 预设"高性能" |
| 分辨率 · 帧率 | 1920×1080 · 60fps | 1920×1080 · 60fps |
| 码率 | 6000–8000 kbps | 10000 kbps 拉满 |
| 关键帧间隔 | 2 秒 | 默认 |
| 色彩空间 | BT.709 / 部分（Limited） | 默认 |
| 音频 | 48kHz · 192kbps | 48kHz · 192kbps |

## 4. 平台、账号与网络

| 术语 | 含义 | 判据 / 影响 |
| --- | --- | --- |
| 推流 | 把编码流实时上传到平台 | "开播"的技术本质 |
| 推流码 / 串流密钥 | 平台发放的密钥 = 开播权限 | 泄露等于他人可用你的号开播 |
| 上行带宽 | 家宽上传速度，通常远小于下行 | 下行 300M 的宽带上行可能仅 30M；双平台同推需 **18Mbps 稳定上行** |
| 电脑直播权限 | 抖音对 PC 端开播的独立授权 | B 站实名即可；抖音需申请，粉丝不足常需公会通道 |
| 公会 | 抖音直播经纪体系 | 代申请权限、流量扶持；权限卡住时的现实解法 |
| 账号权重 | 平台对账号的流量分配评估 | 断续开播会掉；固定时段是养权重唯一有效手段 |
| 删档测试 | 测试期数据结束后清空 | 价值在练手与养号，数据不带入公测 |
| 监听 / Monitoring | 推流软件把某路音频输出到本地耳机 | OBS 监听有几十 ms 延迟，**格斗游戏不能靠它听声**，须走硬件环出 |
| 虚拟声卡（VoiceMeeter / VB-Cable） | 软件模拟音频设备，可多路输出 | 需"自己插耳机 + 同时送采集卡"时才用；能不用就不用 |

### 平台门槛

| 平台 | 门槛 | 耗时 |
| --- | --- | --- |
| B 站 | 实名认证 | 基本即时，当晚可播 |
| 抖音 | 实名 + 申请电脑直播权限（粉丝门槛浮动） | 有审核周期，**必须提前做** |

## 5. 故障定位口诀

| 症状 | 真正原因 | 修法 |
| --- | --- | --- |
| 卡 / 掉线 / 花屏 | 上行带宽不足 | 降码率 → 降帧率 → 降分辨率，依次让 |
| 画面糊 / 马赛克块 | 码率不足或编码器预设太差 | 提码率至平台上限，编码器换 NVENC quality |
| 灰蒙蒙像蒙雾 | 色彩范围 Full/Limited 不匹配 | 推流端与平台统一为 Limited + BT.709 |
| 弹幕和画面对不上 | 采集延迟高（MJPG 卡） | 换 YUY2/NV12 的卡，或确认走 USB 3.0 |
