# 06 实战：打造"只含所需驱动 + 端侧 AI"的定制发行版

> 前置：已读完 01（BSP）、04（rsdk）、05（AI 部署），并理解 02/03 的取舍。
> 本方案采用**推荐路线**：BSP 定制内核 → rsdk 组装 Debian rootfs → `--debs` 集成自定义内核 → customize-hooks 部署 AI 运行时与模型 → 产出可烧录镜像。

---

## 1. 方案设计：为什么这样选

### 1.1 三条 rootfs 路线的取舍

| 需求 | rsdk（推荐） | Buildroot | Yocto |
| --- | --- | --- | --- |
| AI 运行时（rknn/rkllm 以 deb/wheel 发布） | 直接 apt/pip | 需手工移植 | 需写 recipe |
| "只含所需驱动"（裁剪） | 中等（Debian 包粒度） | **最强**（包粒度最细） | 强（包粒度细） |
| 开发速度 | **最快** | 中等 | 慢 |
| 可复现性 | 好 | 好 | **最好** |
| 体积 | 数百 MB 起 | 最小（几十 MB 起） | 可小可大 |

**结论**：

- 首推 rsdk：AI 集成省力，产出标准 Debian 系系统，`--debs` 天然对接 BSP 产物。
- 若未来要做"超小体积专用固件"（如只跑一个固定推理任务），可把 Buildroot 作为量产备选（文档 03 的方法同样适用）。
- Yocto 适合团队化、可复现的长期产品线，学习成本高，本方案不强制。

### 1.2 总体架构

```text
┌─────────────────── PC 端构建流程 ───────────────────┐
│                                                      │
│ ① 需求分析 → 硬件驱动清单                            │
│ ② BSP 定制内核（裁剪驱动 + 开启 NPU）→ deb 包       │
│ ③ rsdk 定制 rootfs（packages + customize-hooks）    │
│ ④ 准备本地 deb 目录（内核 + AI 用户态 + 自研应用）   │
│ ⑤ rsdk build --debs ... → output.img                 │
└──────────────────────────────────────────────────────┘
                        │ 烧录
                        ▼
┌─────────────────── ROCK 5C 运行态 ──────────────────┐
│ 自定义 u-boot + 精简内核（含 rknpu 驱动）             │
│ Debian rootfs：仅含所需驱动包 + AI 运行时             │
│ 推理服务（systemd 自启动）+ 模型文件                  │
└──────────────────────────────────────────────────────┘
```

## 2. 步骤 0：需求分析——确定"所需驱动"

先在**一块已装好官方 RadxaOS 的 ROCK 5C** 上摸底，把最终要保留的驱动清单列出来：

```bash
# 板子上执行
lsmod                                 # 当前加载的内核模块（驱动清单）
uname -a                              # 内核版本
lspci && lsusb                        # PCIe/USB 外设（NVMe、WiFi、USB 设备）
cat /proc/cpuinfo | grep -i model     # SoC 信息
df -h && lsblk                        # 存储设备（eMMC/SD/NVMe）
```

示例需求清单（ROCK 5C 常见配置）：

| 类别 | 需要的驱动/模块 | 说明 |
| --- | --- | --- |
| 存储 | `dw_mmc`（eMMC/SD）、`sdhci`、`nvme`（PCIe NVMe） | 启动与数据盘 |
| 网络 | 以太网 PHY、`brcmfmac` 或 AIC8800 WiFi、`bluetooth` | 联网/远程 |
| NPU | `rknpu` | 端侧 AI 必需 |
| 显示 | `drm/rockchip`、`mali`（GPU） | 如无显示需求可裁剪 |
| USB | `dwc3`、`xhci` | 外设接入 |
| 串口 | `8250_dw` | 调试 |
| 摄像头（按需） | `rkcif`、`rkisp`、`video4linux` | 视觉应用 |
| 音频（按需） | `rockchip_sound`、`es8388` | 语音应用 |

> 裁剪原则：**从内核 .config 里去掉清单之外的模块**（改为不编译或编为模块但不安装），而不是从零配置内核——从零配置极易漏掉启动必需项。

## 3. 步骤 1：用 BSP 定制内核

### 3.1 准备源码并开启 NPU

```bash
cd /home/wbh808/bsp
./bsp linux rk2410 rock-5c --no-build
```

确认/开启 NPU 驱动（RK3588 内核默认通常已开启，务必核实）：

```bash
cd /home/wbh808/bsp/.src/linux
grep -E 'ROCKCHIP_RKNPU' .config
# 若没有，在 kconfig.conf 固化：

# CONFIG_ROCKCHIP_RKNPU=y

# CONFIG_ROCKCHIP_RKNPU_DRM_GEM=y
```

### 3.2 裁剪驱动（固化到 kconfig.conf）

编辑 `/home/wbh808/bsp/linux/rk2410/kconfig.conf`，追加裁剪条目。示例：

```text
# ===== 定制发行版驱动清单 =====

# --- 保留 ---
CONFIG_ROCKCHIP_RKNPU=y
CONFIG_DRM_ROCKCHIP=y
CONFIG_DRM_PANEL_SIMPLE=y
CONFIG_NVME_CORE=y
CONFIG_BLK_DEV_NVME=y
CONFIG_MMC=y
CONFIG_MMC_DW=y
CONFIG_MMC_DW_ROCKCHIP=y
CONFIG_USB_XHCI_HCD=y
CONFIG_USB_DWC3=y
CONFIG_SERIAL_8250_DW=y
CONFIG_WLAN=y

# --- 裁剪示例（按你的清单决定是否删除）---

# CONFIG_SND_SOC_ROCKCHIP is not set          # 不用音频

# CONFIG_VIDEO_ROCKCHIP_ISP is not set        # 不用摄像头 ISP

# CONFIG_DRM_ANALOGIX_DP is not set           # 不用 DP
```

> 注意：裁剪要小心，很多驱动存在依赖关系。改完后至少先做一次"裁剪前构建 + 烧录验证"，再逐步减少，不要一次删太多。

### 3.3 构建并收集 deb

```bash
cd /home/wbh808/bsp
./bsp linux rk2410 rock-5c -r 999

# 同时构建 u-boot（可选，通常保留官方即可）
./bsp u-boot rk2410 rock-5c -r 999

ls -lh *.deb
```

把产物收集到一个固定目录（后续给 rsdk 用）：

```bash
mkdir -p /home/wbh808/custom-debs
cp /home/wbh808/bsp/linux-image-*_arm64.deb /home/wbh808/custom-debs/
cp /home/wbh808/bsp/linux-headers-*_arm64.deb /home/wbh808/custom-debs/
cp /home/wbh808/bsp/linux-dtb-*_arm64.deb /home/wbh808/custom-debs/
cp /home/wbh808/bsp/u-boot-rk2410_*_arm64.deb /home/wbh808/custom-debs/
```

## 4. 步骤 2：准备 AI 运行时 deb/目录

把板端 AI 组件做成"可被打包"的形式。最省事的方式：**先把组件装到一台 ROCK 5C（官方系统）上，再把库文件复制进 rsdk 的 overlay/自定义 hook**。

### 4.1 用户态库

```bash
mkdir -p /home/wbh808/custom-ai/usr/lib /home/wbh808/custom-ai/usr/local/bin

# RKNN C API 库（rknpu2 包安装后也会提供）
cp /home/wbh808/rknn-toolkit2-2.3.2/rknpu2/runtime/Linux/librknn_api/aarch64/librknnrt.so \
   /home/wbh808/custom-ai/usr/lib/

# RKLLM C API 库
cp /home/wbh808/rknn-llm-release-v1.2.3/rkllm-runtime/Linux/librkllm_api/aarch64/librkllmrt.so \
   /home/wbh808/custom-ai/usr/lib/
```

（路径中的 aarch64 子目录以实际解压结构为准，用 `find ... -name 'librknnrt.so'` 定位。）

### 4.2 推理程序与模型

```bash
# 编译好的推理程序（RKNN demo / RKLLM llm_demo / 自研应用）
cp <你的推理程序> /home/wbh808/custom-ai/usr/local/bin/

# 模型文件（按需，模型较大时建议放数据分区而不是镜像内）
mkdir -p /home/wbh808/custom-ai/opt/models
cp /mnt/hgfs/Qwen2.5-1.5B-Instruct.rkllm /home/wbh808/custom-ai/opt/models/ 2>/dev/null || true
```

### 4.3 打成一个本地 deb（可选，最规范）

如果希望包可复用、可升级，写一个最小 Debian 包：

```bash
mkdir -p /home/wbh808/ai-runtime-pkg/DEBIAN
cat > /home/wbh808/ai-runtime-pkg/DEBIAN/control <<'EOF'
Package: my-ai-runtime
Version: 1.0.0
Section: misc
Priority: optional
Architecture: arm64
Maintainer: You <you@example.com>
Description: Edge AI runtime for ROCK 5C (RKNN + RKLLM)
EOF

cp -r /home/wbh808/custom-ai/* /home/wbh808/ai-runtime-pkg/
dpkg-deb --build --root-owner-group /home/wbh808/ai-runtime-pkg \
    /home/wbh808/custom-debs/my-ai-runtime_1.0.0_arm64.deb
```

这样 `my-ai-runtime` 就能和自定义内核一起被 rsdk 安装。

## 5. 步骤 3：定制 rsdk rootfs

### 5.1 追加软件包

编辑 `/home/wbh808/rsdk/src/share/rsdk/build/rootfs.jsonnet`，在 `packages+` 里追加：

```jsonnet
packages+:
[
    // ===== 定制发行版附加包 =====
    "rknpu2-rk3588",        // NPU 用户态 + udev 规则（Radxa 源）
    "python3",              // 按需
    "python3-pip",
    "python3-venv",
    "git",
    "curl",
    "i2c-tools",
    "ethtool",
    "systemd",              // 默认已有，确保自启动服务可用
    "my-ai-runtime",        // 我们打的 AI 运行时包（配合 --debs）
],
```

### 5.2 追加定制 hook

同一文件 `customize-hooks+` 追加（注意保持原有条目不动，只往末尾加）：

```jsonnet
"customize-hooks"+:
[
    // 创建 NPU 设备节点规则（部分镜像需要）
    |||
        set -e
        mkdir -p "$1/etc/udev/rules.d"
        cat > "$1/etc/udev/rules.d/99-rknpu.rules" <<'EOF'
KERNEL=="rknpu", MODE="0666"
EOF
    |||,
    // 部署自启动 AI 服务
    |||
        set -e
        cat > "$1/etc/systemd/system/my-ai.service" <<'EOF'
[Unit]
Description=My Edge AI Service
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/my-ai-app --model /opt/models/model.rkllm
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF
        chroot "$1" systemctl enable my-ai.service
    |||,
    // 清理本地 apt 仓库（若不想保留）
    // 'rm -rf "$1/srv/local-apt-repository"',
],
```

### 5.3 检查产品配置

确认 `products.json` 中 rock-5c 配置无误（已在文档 04 列出）。如需默认 CLI 而非桌面，构建时指定 `cli` 即可。

## 6. 步骤 4：构建镜像

```bash
cd /home/wbh808/rsdk

# 确保本地 deb 目录包含：自定义内核 + AI 运行时
ls /home/wbh808/custom-debs/

# 正式构建（国内网络建议加镜像参数）
rsdk build --debs /home/wbh808/custom-debs \
    -M https://mirrors.ustc.edu.cn/radxa-deb \
    -m https://mirrors.ustc.edu.cn \
    rock-5c bookworm cli

# 产物
ls -lh out/rock-5c_bookworm_cli/output.img
```

构建要点：

- 首次构建会下载大量包，耐心等待；日志里可确认本地 deb 是否被采用（pin 1999）。
- 自定义内核包名要与官方一致（`linux-image-6.1.x-1-rk2410`），否则本地包不会自动替换官方包，需在 `packages` 里显式声明。
- 如需桌面版，把 `cli` 换成 `kde`，但体积会大很多。

## 9. 常见问题

**Q1：镜像里没有我的内核？**

检查 `--debs` 目录与 `rootfs.jsonnet` 的 packages 是否包含 `linux-image-*`；查看构建日志中本地仓库是否命中（本地仓库会显示为最高优先级来源）。

**Q2：NPU 设备节点不存在？**

内核必须有 `CONFIG_ROCKCHIP_RKNPU=y`；设备树保留 `rknpu@fdab0000` 节点；必要时加 udev 规则（见 5.2）。

**Q3：裁剪后系统起不来？**

保留所有与启动相关驱动（MMC/SD、USB、串口、PWM、GPIO、PMIC、时钟）。建议分阶段裁剪：先禁用"明显无关"（如蓝牙音频、HDMI 音频编解码），每次裁剪后都烧录验证。

**Q4：模型文件太大放不进镜像？**

1.5B 量化后约 1GB，7B 约 4GB。建议镜像内不放模型，首次启动从数据分区/网络拉取，或单独制作"数据卡"。

**Q5：构建时 apt 源 404？**

确认 `-M` 指向支持 bookworm 的 radxa-deb 镜像；第三方镜像可能缺 `pkgs.json`，加 `-P` 禁用。
