# 16 猫咪监控项目：本地常显屏与情趣面板

> 前置：文档 08~12（采集、AI、录制、上传、systemd）已跑通；可选对照 [Radxa QT 交叉编译](https://docs.radxa.com/rock5/rock5c/app-development/qt_cross_compile)。
>
> 本文档回答三件事：
> 1. **为什么值得加一块屏**（不是为了调 ROI / 运维）；
> 2. **用哪些技术**；
> 3. **从开机到日常运行的详细执行逻辑**。

---

## 0. 产品定位（先定原则）

### 0.1 加屏的正当性

| 不成立的理由 | 成立的理由 |
| --- | --- |
| 为了给工程师调 ROI / 置信度 | 家人路过一眼知道「今天吃喝几次」「正在吃饭」 |
| 为了塞调试预览 / 画框图 | 常亮「宠物相框」，把监控感做成装饰感 |
| 为了证明会交叉编译 Qt | 异常（断网、满盘、摄像头掉线）在物理空间可见 |
| 用户自己标定碗区 | 标定出厂/安装一次完成，屏上**永不暴露**标定控件 |

**一句话**：屏是「猫区旁的常亮生活物件」，主服务仍是无头 7×24；GUI 是可选前台，挂了也不影响录像与上传。

### 0.2 硬件形态建议

| 方案 | 硬件 | 适合 |
| --- | --- | --- |
| A（推荐入门） | HDMI 小显示器 7~10 寸 + 无触摸 | 开发验证、客厅演示 |
| B（产品向） | MIPI DSI 小彩屏 5~7 寸（可选触摸） | 一体机外壳、猫碗旁常亮 |
| C（极简实用） | 小彩屏仅显示文字/插画，不播实时流 | 低功耗、少隐私顾虑 |

默认假设：**方案 A，Qt 走 `linuxfb` 或 `eglfs`，无完整桌面环境**（与官方交叉编译 `-no-opengl` / `QT_QPA_DEFAULT_PLATFORM=linuxfb` 路线兼容；有 GPU 的 RadxaOS 桌面版可用 `xcb`/`wayland` 作为备选）。

### 0.3 功能分层（必须分清）

```text
┌─────────────────────────────────────────────────────────┐
│  L2 情趣层（屏存在的主理由）                              │
│     宠物相框 / 事件氛围动画 / 猫日记 / 庆祝瞬间            │
├─────────────────────────────────────────────────────────┤
│  L1 实用常显（不掏手机也能用）                            │
│     今日看板 / 正在发生 / 异常告警 / 访客模式              │
├─────────────────────────────────────────────────────────┤
│  L0 无头核心（永远可独立运行）                            │
│     cat-camera / 录制 / 上传 / watchdog（文档 10/12）     │
└─────────────────────────────────────────────────────────┘
```

ROI、阈值、预录秒数等仍只存在于 `roi_config.yaml` 与安装脚本中，**不进 GUI**。

## 1. 功能规格

### 1.1 L1 实用常显

| ID | 功能 | 验收标准 |
| --- | --- | --- |
| D1 | 今日看板 | 显示：进食次数、饮水次数、上次进食/饮水时间、本地未上传数 |
| D2 | 正在发生 | 状态机进入 `ACTIVE(eat/drink)` 后 ≤1s 切换全屏提示；结束后回到相框/看板 |
| D3 | 异常告警 | 摄像头掉线、WiFi 断、磁盘 &lt;5GB、上传连续失败 → 全屏或顶栏告警，可静音但不自动消失直到恢复 |
| D4 | 访客模式 | 一键（GPIO 短按或触摸手势）关闭实时相关内容，仅保留统计与插画；再次短按恢复 |

### 1.2 L2 情趣层

| ID | 功能 | 验收标准 |
| --- | --- | --- |
| E1 | 宠物相框 | 空闲时轮播「今日精彩帧」；无图时显示默认插画/猫剪影呼吸动画 |
| E2 | 事件氛围 | 进食/饮水确认瞬间播放 3~8s 插画动画（非监控画面），带短文案 |
| E3 | 猫日记 | 每天固定时刻（如 21:00）生成一句摘要，屏上展示至次日刷新 |
| E4 | 仪式感 | 首次检测到新事件类型、或连续 N 天有规律喝水 → 庆祝卡（可关） |
| E5 | 夜间模式 | 22:00~07:00（可配置）亮度降至最低、刷新降至 1fps、禁用庆祝动画 |

### 1.3 明确不做

- 用户可编辑 ROI / 模型阈值 / 预录参数；
- 默认常开实时监控流（可选「长按看一眼」，默认关）；
- 复杂设置页、账号体系、Web 管理后台（那是手机/PC 的事）。

## 2. 技术栈清单

### 2.1 总览

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| GUI 框架 | **Qt 5.12+ Widgets**（交叉编译 aarch64） | 常显 UI、动画、夜间模式；与 [官方 QT 交叉编译](https://docs.radxa.com/rock5/rock5c/app-development/qt_cross_compile) 对齐 |
| 显示后端 | `linuxfb` / `eglfs`（无桌面）；或 `xcb`（有桌面） | 直接上屏，不依赖完整 DE |
| 可选 GPU | Mali / Qt eglfs + OpenGL ES（若启用） | 平滑动画；极简镜像可纯 CPU + QPixmap |
| 进程间通信 | **Unix Domain Socket + JSON Lines** | 主服务 → 面板：状态/事件；面板不反向改算法参数 |
| 状态持久化 | SQLite（或复用 `events.csv` + 当日汇总 JSON） | 今日统计、日记、精彩帧索引 |
| 精彩帧 | JPEG 落盘（事件 ACTIVE 中抽 1~3 帧） | 相框素材；由主服务写入，面板只读 |
| 文案 | 本地模板库（中文）+ 简单规则填空 | 猫日记 / 氛围文案；**不依赖云端 LLM**（可选后期接 RKLLM） |
| 系统集成 | systemd user/system unit、`After=cat-camera.service` | 面板可单独启停；主服务挂了面板进「离线插画」 |
| 输入（可选） | GPIO 按键 / 触摸屏 `evdev` | 访客模式切换、亮度临时调高 |
| 亮度 | sysfs 背光 或 HDMI 不调光仅软件变暗 | 夜间模式 |
| 构建 | x86 交叉编译 Qt → 板端 scp / 打进 rsdk deb | 文档 13 镜像集成 |
| 镜像裁剪 | Buildroot 可选不装面板；rsdk 用 package 开关 | 无屏量产镜像体积不受影响 |

### 2.2 为什么选 Qt Widgets 而不是 Web/QML

| 方案 | 结论 |
| --- | --- |
| Qt Widgets | ✅ 与官方交叉编译示例一致；`-skip qtdeclarative` 也能做；资源占用可控 |
| Qt Quick/QML | 动画更炫，但依赖 declarative，交叉编译体积与依赖更大 |
| Electron/浏览器 | 过重，不适合常亮小屏 |
| Python PyQt | 开发快，但与无头 Python 主服务抢资源；推荐 **C++ Qt 面板 + Python 主服务** 分进程 |

### 2.3 与现有组件的边界

```text
┌──────────────── cat-camera.service（文档 10/12）──────────────┐
│  V4L2 → 运动门控 → RKNN → 状态机 → GStreamer 录制 → 落盘     │
│  写：/data/videos/…  /data/events/events.csv                 │
│  写：/data/display/highlights/*.jpg                          │
│  写：Unix socket → 面板（状态推送）                            │
└──────────────────────────────────────────────────────────────┘
                              │ JSON Lines
                              ▼
┌──────────────── cat-panel.service（本文档）───────────────────┐
│  Qt：相框 / 看板 / 氛围 / 日记 / 告警                          │
│  只读 highlights + events 汇总；不写 ROI；不控 NPU            │
│  可选：GPIO → 访客模式（写 /run/cat-panel/mode）               │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
                         HDMI / DSI 屏
```

### 3.2 主服务 → 面板：JSON Lines 协议

路径：`/run/cat-monitor/status.sock`（systemd `RuntimeDirectory=cat-monitor`）

每行一个 JSON 对象，UTF-8：

```json
{"ts":1710000000,"type":"heartbeat","state":"IDLE","cam_ok":true,"wifi_ok":true,"disk_free_gb":12.4,"upload_pending":3}
{"ts":1710000001,"type":"state","state":"CANDIDATE","behavior":null}
{"ts":1710000002,"type":"state","state":"ACTIVE","behavior":"eat"}
{"ts":1710000003,"type":"highlight","path":"/data/display/highlights/2026-08-14/eat_103022_01.jpg","behavior":"eat"}
{"ts":1710000010,"type":"state","state":"COOLDOWN","behavior":"eat","event_id":"eat_20260814_103022"}
{"ts":1710000015,"type":"stats","date":"2026-08-14","eat_count":3,"drink_count":5,"last_eat":"10:30","last_drink":"09:12"}
{"ts":1710000020,"type":"alert","code":"DISK_LOW","level":"warn","msg":"剩余空间不足 5GB"}
{"ts":1710000021,"type":"alert_clear","code":"DISK_LOW"}
```

约定：

- `heartbeat`：主服务每 2s 发一次；面板 **6s 无心跳** → 视为主服务异常，切告警场景；
- 面板**不向** socket 写控制指令改 ROI；访客模式只改本地 `/data/display/mode`；
- 若需「暂停录制」等高级控制，另开受控管理 socket（默认不做）。

### 3.3 `daily_stats.json` 示例

```json
{
  "date": "2026-08-14",
  "eat_count": 3,
  "drink_count": 5,
  "last_eat": "10:30",
  "last_drink": "09:12",
  "total_eat_s": 420,
  "total_drink_s": 180,
  "streak_drink_days": 4
}
```

跨日 00:00：归档旧日统计，清零当日计数；精彩帧目录按日期新建。

## 4. 界面场景与状态机（面板侧）

### 4.1 场景定义

| 场景 ID | 名称 | 显示内容 | 进入条件 |
| --- | --- | --- | --- |
| `S_FRAME` | 相框 | 轮播 highlights + 底部小字今日统计 | 默认空闲 |
| `S_ACTIVE` | 正在发生 | 插画动画 +「正在吃饭/喝水」 | 收到 `ACTIVE` |
| `S_CELEBRATE` | 仪式 | 庆祝卡 5s | 规则触发且非夜间 |
| `S_DIARY` | 日记 | 大字一句日记 | 21:00 或用户点按（可选） |
| `S_ALERT` | 告警 | 告警插画 + 文案 | 有未清除 alert 或心跳超时 |
| `S_VISITOR` | 访客 | 仅插画 + 模糊统计，无任何「监控感」素材 | mode=visitor |
| `S_NIGHT` | 夜间 | 极暗相框或纯时钟剪影 | 夜间窗内且无 ACTIVE/ALERT |

优先级（高 → 低）：

```text
ALERT > ACTIVE > VISITOR > CELEBRATE > DIARY > NIGHT > FRAME
```

### 4.2 面板场景状态机（伪代码）

```yaml
on_message(msg):
  update_local_cache(msg)
  if msg.type == alert or heartbeat_timeout:
       goto ALERT
  elif mode == visitor:
       goto VISITOR
  elif msg.state == ACTIVE:
       goto ACTIVE   # 启动氛围动画计时器 T_amb=5s
  elif celebrate_pending and not night:
       goto CELEBRATE
  elif diary_show_pending:
       goto DIARY
  elif in_night_window and msg.state in {IDLE, COOLDOWN}:
       goto NIGHT
  else:
       goto FRAME

on_ACTIVE_finished:   # 收到 COOLDOWN/IDLE 或动画播完
  maybe_queue_celebrate()
  maybe_save_highlight_already_done_by_camera()
  transition_by_priority()
```

### 4.3 相框轮播逻辑

```text
highlights = list /data/display/highlights/今日/*.jpg
if empty:
  highlights = list 近 3 日；仍空则用 assets/default_cat.png

每 8s（夜间 30s）切换下一张，淡入淡出 400ms
底部 HUD（非访客）：吃×N  喝×N  ·  上次吃饭 HH:MM
```

### 4.4 「正在发生」逻辑（情趣优先，不是监控预览）

1. 收到 `state=ACTIVE, behavior=eat|drink`；
2. 立即切 `S_ACTIVE`：全屏插画（碗/水滴），文案随机自模板，例如「小馋猫开工了」；
3. **默认不贴摄像头实时帧**（避免监控感）；若配置 `allow_live_peek=true`，长按 GPIO 才叠加半透明小窗 10s；
4. 收到 `COOLDOWN` 或 ACTIVE 结束：淡出 → 回相框；主服务同时已抽精彩帧，相框池自动变新。

### 4.5 猫日记生成逻辑

触发：systemd timer `cat-diary.timer` 每天 21:00，或主服务日切时。

```text
输入：daily_stats.json
规则示例：
  if eat_count==0 and drink_count==0 → 「今天像个小懒猫，吃喝都没被拍到。」
  elif drink_count>=5 → 「今天喝水很积极，共 {drink_count} 次。」
  elif eat_count>=4 → 「饭点很准时，一共吃了 {eat_count} 顿。」
  else → 「今天吃饭 {eat_count} 次，喝水 {drink_count} 次，上次吃饭 {last_eat}。」

写 /data/display/diary.txt
发 socket: {"type":"diary","text":"..."}
面板：可短时切 S_DIARY，或仅在相框角标「今日一句」
```

后期可选：用 RKLLM 把同一统计润色成更俏皮的句子；失败则回退模板。

### 4.6 仪式感触发

| 条件 | 行为 |
| --- | --- |
| 当日第一次 `ACTIVE(eat)` | 轻量庆祝（可关） |
| `streak_drink_days >= 3` 且今日首次饮水结束 | 「连续喝水第 N 天」 |
| 从严重告警恢复（如 WiFi 重连） | 不庆祝，仅清除告警 |

夜间窗口内：只记 flag，次日白天首次进入 `S_FRAME` 再播，或直接取消。

### 4.7 异常告警逻辑

| code | 来源 | 面板表现 |
| --- | --- | --- |
| `CAM_FAIL` | 主服务打开 `/dev/video*` 失败或读帧超时 | 红/橙告警，「摄像头走丢了」 |
| `WIFI_DOWN` | 主服务或 `wifi-check` 探测失败 | 「家里网断了，视频先存在本地」 |
| `DISK_LOW` | `disk_free_gb < 5` | 「空间不够了，请清理或扩容」 |
| `UPLOAD_FAIL` | 上传连续失败 ≥3 次 | 「上传卡住了，本地仍安全」 |
| `CAMERA_SVC_DOWN` | 面板心跳超时 | 「监控服务休息了」 |

恢复：对应 `alert_clear` 或心跳恢复后，按优先级退回下层场景。

### 4.8 访客模式

```text
短按 GPIO KEY → toggle /data/display/mode  normal↔visitor
visitor：
  - 不显示 highlights 实拍（改默认插画）
  - 统计可保留为「今天状态不错」类模糊文案，或只显示吃/喝次数
  - 忽略 CELEBRATE / DIARY 弹层
长按 2s → 临时提高亮度 30s（方便看清）
```

## 5. 主服务侧执行逻辑（`display_bridge`）

在现有 `cat_camera` 主循环中增加旁路，**不得拖慢 NPU 路径**：

```text
主循环每帧:
  … 原有：门控 → 检测 → 状态机 → 录制 …

  每 2s:
    emit heartbeat(JSON)

  on 状态机迁移:
    emit state(JSON)
    if 进入 ACTIVE:
         标记 highlight_slots = 3
    if ACTIVE 中且 highlight_slots>0 且距上次抽帧>1.5s:
         选当前帧（可轻度裁剪猫框）→ JPEG 写 highlights/
         emit highlight(JSON)
         highlight_slots -= 1
    if 进入 COOLDOWN 且事件有效:
         更新 daily_stats.json / events.csv
         emit stats(JSON)
         检查仪式感条件 → emit celebrate（或只写 flag 给面板）

  on 健康检查失败/恢复:
    emit alert / alert_clear
```

精彩帧要求：

- 质量：JPEG q=85，最长边 ≤1280；
- 配额：每日最多保留 40 张，超出删最旧；
- 隐私：访客模式不读这些文件即可，文件仍可存在盘上供主人回家看。

## 6. Qt 面板内部模块与运行时序

### 6.1 模块职责

| 模块 | 职责 |
| --- | --- |
| `StatusSocketClient` | 连接 `/run/cat-monitor/status.sock`，断线重连（指数退避 1s→8s） |
| `SceneController` | 实现 §4 优先级状态机，驱动 `QStackedWidget` 或场景 Widget 显隐 |
| `HighlightModel` | 监视 `highlights/` 目录（`QFileSystemWatcher`），维护播放列表 |
| `DiaryGenerator` | 面板侧也可只读 `diary.txt`；生成建议放 timer 脚本以免 GUI 逻辑膨胀 |
| `NightGuard` | 读配置时段 + 系统时钟，输出 `is_night` |
| `GpioWatcher`（可选） | `QSocketNotifier` 监听 gpio 或调用 `libgpiod` |
| `MainWindow` | 全屏、无边框、鼠标可选隐藏；`showFullScreen()` |

### 6.2 开机到稳态时序

```text
1. systemd 启动 cat-camera.service
     → 创建 RuntimeDirectory、打开摄像头、加载 RKNN
     → listen status.sock
2. systemd 启动 cat-panel.service（After=cat-camera.service；但 Restart 不互相捆绑失败）
     → 设置 QT_QPA_PLATFORM=linuxfb（或 eglfs）
     → cat-panel 全屏启动 → 先显示默认插画（S_FRAME）
     → 连接 socket；连上前可显示「正在醒来…」
3. 收到首包 heartbeat + stats → 刷新看板数字
4. 进入日常：FRAME 轮播；事件来时 ACTIVE；异常 ALERT
5. 21:00 diary.timer → 写 diary.txt → 面板短时展示
6. 夜间：亮度与刷新下降；ACTIVE 仍可打断夜间（真实吃饭优先于美学）
```

### 6.3 进程崩溃与降级

| 故障 | 行为 |
| --- | --- |
| 面板崩溃 | systemd `Restart=on-failure`；主服务不受影响，继续录 |
| 主服务崩溃 | 面板心跳超时 → `S_ALERT`；录制中断由 watchdog 拉起主服务 |
| 屏线脱落 | 面板可能报错退出；主服务照常；无屏镜像可不装 panel 包 |
| socket 权限 | `socket` 属组 `catmonitor`，面板用户同组 |

### 6.4 systemd 单元示意

```ini
# /etc/systemd/system/cat-panel.service
[Unit]
Description=Cat Monitor Ambient Panel (Qt)
After=cat-camera.service
Wants=cat-camera.service

[Service]

Environment=QT_QPA_FB_DRM=1
# 若使用 eglfs：

# Environment=QT_QPA_PLATFORM=eglfs

RestartSec=3

[Install]

```

### 7.1 推荐裁剪与本项目的对应关系

| 官方配置项 | 本项目建议 |
| --- | --- |
| `-xplatform linux-aarch64-gnu-g++` | 保持 |
| `QT_QPA_DEFAULT_PLATFORM=linuxfb` | 无桌面常亮屏 ✅ |
| `-no-opengl` / 跳过 webengine、declarative | Widgets 相框足够；要做复杂动画再开 GLES |
| `-nomake examples/tests/tools` | 保持，缩短编译 |
| 板端 `libqt5gui5` 等 | RadxaOS：`apt`；自制镜像：rsdk packages 写入 |

### 7.2 应用侧 `.pro` 要点

```qmake
QT += core gui widgets network

RESOURCES += assets/assets.qrc
```

设备套件：Qt Creator 指向交叉 qmake + 板端 SSH 部署路径 `/opt/cat-monitor/bin/`。

## 8. 美学与文案规范（避免「监视器脸」）

1. **默认无实时画面、无检测框、无 ROI 叠层**；
2. 配色：暖纸色 / 低饱和插画，避免 CCTV 绿黑；
3. 字体：圆润标题 + 清晰数字；夜间仅保留必要对比度；
4. 文案语气：养宠、轻松，不出现「目标锁定」「入侵检测」等词；
5. 动画：缓入缓出，避免闪烁；告警可用缓慢呼吸而非刺眼闪红；
6. 声音：默认静音（猫区安静）；庆祝可选极轻提示音且可关。

`copy_templates.json` 示例：

```json
{

  "active_drink": ["补水中…", "咕咚咕咚", "今天也要好好喝水"],
  "alert_wifi": ["家里网断了，视频先住在本地"],

    "balanced": "今天吃饭 {eat} 次，喝水 {drink} 次，上次吃饭 {last_eat}。",
```

## 9. 与镜像构建的关系

| 路线 | 面板如何集成 |
| --- | --- |
| rsdk（主推） | `packages` 增加 Qt5 运行时 + 自打 `cat-panel` deb；`customize-hooks` 安装 unit、资源到 `/opt/cat-monitor`；无屏 SKU 用 jsonnet 开关去掉 |
| Buildroot | 可选 `BR2_PACKAGE_QT5` + 自有 package；极简固件默认 **不选**，证明无头核心独立 |
| Yocto | `cat-panel` recipe + `IMAGE_INSTALL` 条件打开 |
| BSP | 若用 DSI 屏：设备树/overlay 在 bsp 维护（与摄像头 overlay 同类工作） |

验收：同一套主服务，**插屏镜像**与**无屏镜像**都能完成录像上传；仅前者多 `cat-panel.service`。
