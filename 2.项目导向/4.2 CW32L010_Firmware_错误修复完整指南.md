## 3. 错误清单与修复流程

### 错误 3.1: clangd 路径错误 → main.c 全屏报未声明

**现象**:
```
error: Call to undeclared function 'tim_100us_irq_cfg'
error: Call to undeclared function 'led_init'
error: Use of undeclared identifier 'GPIO_PIN_0'
error: Use of undeclared identifier 'HAL_TIMER_INDEX_100US'
... (main.c 中几乎全部符号报错)
```

**根因**:
`.vscode/settings.json` 中 clangd 配置指向了 `out/CW32L010_APP/CW32L010F8/Debug`，但该目录下**没有** `compile_commands.json`。实际的编译数据库在 `tmp/2/` 下。

**修复** (`.vscode/settings.json`):
```json
"clangd.arguments": [
    "--compile-commands-dir=d:\\Github_Code\\3.MCU\\MCU_Solution\\CW32L010_Firmware",
    "--query-driver=c:\\Users\\wangb\\.vcpkg\\artifacts\\2139c4c6\\compilers.arm.armclang\\6.24.0\\bin\\armclang.exe"
]
```

> 指向 workspace 根目录，使用合并版 `compile_commands.json`

### 错误 3.2: 单项目 clangd 配置无法覆盖两个项目

**现象**: 修改 clangd 指向某一个项目的 compile_commands.json 后，另一个项目的文件报错。

**根因**: clangd 的 `--compile-commands-dir` 只能指向一个目录。

**修复**: 
创建合并版 `compile_commands.json` 到 workspace 根目录：

```powershell
python -c "
import json, os

root = r'd:\Github_Code\3.MCU\MCU_Solution\CW32L010_Firmware'
all_entries = []

for proj_dir in ['tmp/1', 'tmp/2']:
    cc_path = os.path.join(root, proj_dir, 'compile_commands.json')
    if os.path.exists(cc_path):
        with open(cc_path, 'r') as f:
            data = json.load(f)
        all_entries.extend(data)

merged_path = os.path.join(root, 'compile_commands.json')
with open(merged_path, 'w') as f:
    json.dump(all_entries, f, indent=2)
print(f'Merged {len(all_entries)} entries')
"
```

> 合并后共 60 个条目 (BootLoader 11 + APP 49)

**现象**:
```
error: 'cw32l010_adc.h' file not found

error: Call to undeclared function 'ac_frequency_calculate'

/* Includes ------------------------------------------------------------------*/

#include "cw32l010_adc.h"          // ← 新增
#include "func_dust_collect.h"     // ← 新增
```

### 错误 3.4: ATIM_IRQHandler 重复定义（链接错误）

**现象**:
```
Error: L6200E: Symbol ATIM_IRQHandler multiply defined
  (by tim_cfg.o and interrupts_cw32l010.o)
```

**根因**: `ATIM_IRQHandler` 在两个文件中都有定义：
- `CW32L010_APP/BSP/tim_cfg.c` — 真实实现（处理定时器中断、调用 hal_timer_run）
- `CW32L010_APP/App/interrupts_cw32l010.c` — 空壳占位符

**修复**: 从 `interrupts_cw32l010.c` 中删除空的 `ATIM_IRQHandler` 定义，只保留 `tim_cfg.c` 中的真实实现。

```c
// 删除以下代码块:
/**
 * @brief This funcation handles ATIM
 */
void ATIM_IRQHandler(void)
{
    /* USER CODE BEGIN */
    /* USER CODE END */
}
```

### 错误 3.5: compile_commands.json 重复 --target 标志

**现象**: CMSIS Pack 文件报 IntelliSense 错误（见 [已知残留](#8-已知残留问题)）。

**根因**: CMake 生成的 `compile_commands.json` 中包含 **4 个重复的** `--target=arm-arm-none-eabi` 标志，最后一个不带 `-mcpu=cortex-m0plus`，导致 clangd 以错误的 CPU 架构解析 CMSIS 头文件。

**修复**: 清理所有 compile_commands.json 中的重复 --target 标志，并添加 `-D__ARM_FEATURE_LDREX=0`：

```powershell
# 方法1: 运行修复脚本
.\.vscode\scripts\fix_compile_commands.ps1

# 方法2: 手动 Python 脚本（见 .vscode/scripts/fix_compile_commands.ps1 内容）
```

## 7. 复现指南（构建后恢复）

每次运行 `cbuild` 重新生成构建文件后，需要执行以下恢复步骤：

### 步骤 1: 修复各项目 compile_commands.json
```powershell
# 运行修复脚本（清理 --target 重复标志 + 添加 M0+ 宏）
.\.vscode\scripts\fix_compile_commands.ps1
```

### 步骤 2: 重新合并 compile_commands.json 到 workspace 根目录
```powershell
python -c "
import json, os
root = r'd:\Github_Code\3.MCU\MCU_Solution\CW32L010_Firmware'
all_entries = []
for proj_dir in ['tmp/1', 'tmp/2']:
    cc_path = os.path.join(root, proj_dir, 'compile_commands.json')
    if os.path.exists(cc_path):
        with open(cc_path, 'r') as f:
            all_entries.extend(json.load(f))
with open(os.path.join(root, 'compile_commands.json'), 'w') as f:
    json.dump(all_entries, f, indent=2)
print(f'Merged {len(all_entries)} entries')
"
```

### 步骤 3: 重启 clangd
- VS Code 命令面板 → `clangd: Restart language server`
- 或重新加载 VS Code 窗口

### 步骤 4: 验证
- 打开 `CW32L010_APP/App/main.c` → 应无 IntelliSense 错误
- 运行 `cmake --build .` → 应编译成功

## 8. 已知残留问题

### CMSIS Pack IntelliSense 报错

**文件**: `core_cm0plus.h` (CMSIS 6.3.0 Pack)

**错误信息**:
```
error: load and store exclusive builtins are not available on this architecture
error: Unknown type name 'IRQn_Type'; did you mean 'IPSR_Type'?
```

**根因**: clangd 使用自己的内置 clang 引擎（而非 armclang）解析头文件。CMSIS 6.x 的 `cmsis_armclang.h` 通过 `#if (__ARM_FEATURE_LDREX >= 1)` 保护 LDREX/STREX 内置函数，但 clangd 即使在 `-mcpu=cortex-m0plus` 下仍将 `__ARM_FEATURE_LDREX` 设为 >=1，导致这些不兼容的宏被展开。

**影响评估**: 
- ✅ **不影响实际编译** — armclang 6.24 正确处理
- ✅ **不影响用户代码 IntelliSense** — 仅 CMSIS Pack 头文件报错
- ⚠️ **IDE 问题面板有干扰** — 可忽略或折叠 CMSIS 文件报错

**可能的彻底解决**:
1. 降级 CMSIS Pack 到 5.x (`csolution.yml` 中指定 `ARM::CMSIS@5.9.0`)
2. 等待 clangd 修复 Cortex-M0+ 架构的 `__ARM_FEATURE_LDREX` 处理
3. 使用 VS Code 问题面板过滤器忽略 CMSIS Pack 路径的报错
