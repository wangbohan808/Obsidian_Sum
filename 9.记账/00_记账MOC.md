## 账期制度（核心）

| 项 | 值 |
|---|---|
| 起点 | 每月 20 号发工资 |
| 终点 | 次月 19 号 |
| 命名 | 用起点日，`2026-10-20` |
| 长度 | 28–31 天 |

**纯日历周期，不跟着实际结清日浮动。** 早一天晚一天结清，都归同一个账期，否则账期长度不定，月度之间没法横向比较。

## 四条规则

1. **一个数据源**。所有支出只写进 `流水/YYYY-MM-20.csv`。
2. **只记发生的事**。计划值（固定 2,825、饮食 49/天）由 [[预算参数]] 提供，不进流水。
3. **还款不进支出**。还花呗/白条只减少现金和负债，净资产不变。记 `类型=还款`，看板自动排除。消费当天已经记过，再记一次就是双计。
4. **净资产 = 期初 + 收入 − 支出**。这个式子只有在上面第 3 条成立时才准。

## 每月 20 号要做的三件事

1. 新建 `流水/YYYY-MM-20.csv`，把上期固定支出复制过来改日期
2. 结清白条/花呗（记 `类型=还款`，不进支出）
3. 核对余额宝 + 银行卡实际总额 vs 看板「当前净资产」，差额超 200 元说明有漏记

## 账期边界：发薪日当天的三件事

**顺序固定：结清欠款 → 付下月房租 → 领工资 → 开新账期。**

| 顺序 | 动作 | 记什么 |
|---|---|---|
| ① | 结清白条 / 花呗 | `类型=还款`，永不进支出 |
| ② | 付**下个月**房租 1,680 | `固定 / 房租` |
| ③ | 工资 9,990 到账 | `收入` |
| → | 余额 = 新账期的起点 | — |

**房租是预付下一个月的，所以它永远不在账期内发生。** 由此：

| | 金额 |
|---|---|
| 全口径月固定 | 2,825 |
| 落在账期外（发薪日） | 房租 1,680 |
| **落在账期内** | **1,145**（水电 250 + 猫咪 500 + 话费 76 + 健身 199 + AI 120） |
| 账期预算（31 天） | 1,145 + 57×31 = **2,912** |

**首期（2026-10-20）是唯一例外**：那天的还款、房租、工资都已含在期初 33,000 里，一笔不记。从 2026-11-20 起按上表记。看板靠「账期起点 == 期初日期」自动识别首期，不用手动改参数。

> 为什么次期起要把工资和房租「倒记」进账期第一天：如果两笔都不记，净资产公式从第二期起会失真 8,310 元（工资 9,990 − 房租 1,680）。记上之后链条才连续。


## 关键结论沉淀

> 记账本身不产生价值，从记账里得出的判断才会。

- **2026-10-20 基线**：实际可支配 11,430（税前 12,500 / 迟到扣 150 / 到手 9,990 / 公积金 1,440）。期初净资产 **33,000**（已含 10/20 工资、已结清白条花呗、**已付房租**——三笔都不入流水）。
- **月最低支出 4,535**（30 天口径）/ **4,592**（31 天）；但**账期内只会花 2,912**，差额 1,680 是发薪日提前付掉的房租。真实底线约 5,185，含未列项 650。
- **外卖不是财务风险**。自炊 **57/天**已全额计入预算，25 元外卖替代当日做饭反而更省。真正的漏洞是「做了饭又点外卖」的叠加型，只盯这一项。
- **预算大头不在可变支出**。房租 1,680 占月支出 39%，硬性固定占固定项 89%。可压缩空间只有 319 元（健身 199 + AI 120），结构靠省吃俭用改不动，只能靠收入。
- **猫咪 500 到 2027-05 结束**，之后每月释放 500，年化 6,000。
- **迟到早退是唯一可完全消除的支出**。月 150 / 年 1,800，按点到岗即归零。连续 3 个月零扣款，日额度 287 → 292。
